§2 — The measured amendment: the pin is semantic identity, not a file digest

The locked artifact-resolution decision said "packaged pinned digest". The node measured that a manifest digest cannot be pinned: the artifact's IDS containers carry library write metadata, so authoring identical semantics twice publishes different manifest digests (two runs: b41c076e… vs 889cbc2a… — every file the same size, every file hash different). What both runs reproduce exactly is MachineArtifactManifest.semantic_identity() — sha256:18c75c19493714108fc71f88a55cc775836218e489e073f43942fd007d937bdc — covering the DD pin, physical + registry identity, shot extent and per-field provenance, excluding the file table. That is what the package pins; a local materialization's digest is an address on one filesystem, never an identity. The decision's intent (in-repo pin, resolvable location, env-overridable, no hand-set env vars in tests) is honoured on the only address that can carry it. Recorded as an amendment to the decision rationale. One deliberate policy reversal rode along, explicitly owner-visible: the seam test test_an_unnamed_artifact_refuses_to_build_a_source became …_still_names_a_machine — "refusing beats defaulting" was correct while the only default was a filesystem path; the semantic pin removes the unstated default that rule guarded against.
