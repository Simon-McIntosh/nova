A profile is a variable, not an identity (2026-09-08 11:36Z)

Lead ruling, 2026-09-08: every slice has a different plasma profile; the profile is a variable, much like a coil current. It is therefore member data and must never reach the operator's static identity.

What the trace shows, and it indicts the acceptance criterion rather than only the code. This plan's own boundary already classified profile tables as member data, stacked along a leading member axis and passed as traced arguments. The implementation nonetheless routed a profile callable into the static auxiliary, so a closure-carried profile became part of operator identity, contradicting the section's own words. The done-when could not see it: it required a width-twelve MAST batch to trace with no member-specific constant and to match width one bit for bit, and that passed, because the driver deduplicates twelve members onto six profile objects, the two variants of each row sharing a callable. A fixture whose members share profiles cannot observe whether profiles are static.

The defect surfaced only when an allocation-free processor run stacked two frames that genuinely differ, and the batch declined them at four compiles per pass instead of one. The semantic identity landed the same morning is not the cause and stays correct for what it does; it made a pre-existing staticness visible rather than introducing it.

Consequence. The width-twelve result stands as a measurement of twelve members over six distinct profiles, not of twelve slices, and a production batch over genuinely different slices would fall back to the sequential route today. The repair carries a profile as array leaves through the array-owned flux function, whose tables are leaves so its identity contribution is the tree structure rather than the values, and the fixture must vary every quantity the contract calls member data, or it proves nothing about them.

Lesson. The same shape as the day's other findings, one layer down: the check existed and ran where the failure could not be. Here the fixture's members were too alike to fail.

Strict-exit rows persist before the identity assertion (2026-09-15 08:14Z)

Node bob-strict-exit-rows-persist-before-assert (implement; commit b0878d5e at worktree head on base 0f872fd6). Resolves the DIII-D strict-exit identity followup: in the H200 width-5 batch, frame 179's terminal state differed with the exit on, and the extraction asserted cross-arm identity before serialising, so no DIII-D rows survived.

Result. benchmarks/strict_exit_incidence.py now persists every member's rows for both strict-exit passes before any cross-arm identity assertion. Each row carries a per-member terminal_state_difference (maximum absolute flux difference plus the without_exit_converged and with_exit_converged flags), a terminal_state_bit_identical_where_both_arms_converged field, and both arm records. Identity is asserted once after extraction and only over members converged in both passes, because a fired exit (settlement) is by construction not converged; a strict exit that moves a non-converged member's state is recorded as data instead of discarding that member's rows. The determinism guard still refuses a both-converged member whose passes differ. Both the batched and sequential extraction paths share the same row builder and the same post-extraction assertion.

Measure. On all_debug CPU x64 in one fresh process, tests/test_strict_exit_incidence.py passes 8 of 8 (six pre-existing tests plus two new). The batch-row test drives the extraction on a synthetic two-member batch whose second member differs between the exit-on and exit-off arms and is not converged with the exit on: rows for both members are written for both passes with a per-member terminal_state_difference, no exception is raised, and identity is asserted only over the both-converged member. The positive-control test manufactures a both-converged member with differing terminal states and asserts the guard still raises RuntimeError. No GPU job was submitted.

Lesson. The defect was an in-loop raise ahead of serialisation in the row extraction of both measurement paths; persisting first turns a scientific negative into a receipt, and scoping the determinism guard to both-converged members keeps it honest where it is decidable.
