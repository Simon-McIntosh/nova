§2 — production carriers: overflow judged on critical nodes

Run r-20261002T124430828085-ctta-tree-capacity-on-critical-nodes (codex-terra), merged at 76e935345 from 18c543541 to 233200a35, removes the resolution limit recorded above. The sweep now uses the carrier's own vertex and edge capacities. Only critical nodes and tree arcs are compacted into the 256-node, 255-edge receipt, and edge endpoints are remapped to the compacted node rows. A refusal is a named receipt flag and never raises under jit.

The gate covers all four persisted Solov'ev certificates at the 340, 550 and 1074-cell rungs, twelve cases, and both MAST rows on the full 464-cell carrier (644 vertices, 1737 edges). Every case agrees with the brute force at every sampled level, with one more node than edges and no overflow. The MAST trees have 66/65 and 69/68 nodes/edges, and the contour-tree suite passes, 31 tests. Restoring the vertex-count overflow refuses the MAST and 340-cell carriers, which is the negative control. No 2616-cell persisted state exists.

The first review (79 of 100) blocked the head because the compacted node rows and the uncompacted edge endpoints used different index spaces. A 13-node tree on the 340-cell rung carried an edge endpoint of 353. The component-count comparison cannot see this. A committed invariant test now asserts that every valid edge endpoint is a valid node row and names the carrier vertex the uncompacted edge named. The re-review scored 96 of 100.

Cost. CPU execute grows from 3.3 s at 353 live vertices to 75.8 s at 1089, against compile near 1.4 s. Each sweep visit forms a repeated-neighbour matrix over the fixed edge buffer, so the work grows with vertices times the square of the edge capacity. That is an implementation choice of the vectorised union-find sweep, not a property of contour trees. Figures and logs: /nova/figures/contour-tree-topology-authority/capacity-on-critical-nodes/.
