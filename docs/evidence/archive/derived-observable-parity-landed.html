The single most consequential finding: both routes already share the label spine. ForwardProfile.solve and ForwardProfile.solve_batch terminate in the same _solve_accelerated → _receipt path, so there are no route-specific derived-label definitions to reconcile. A repair that authored a second batched volume, radius or divergence function would create exactly the duplicate authority the plan forbids. What differs between the routes is layout, accumulation order and kernel selection — not the definition.

The discriminator therefore has a clean shared-state arm. ForwardProfile.observe is the reusable no-iteration entry: evaluate one selected shared terminal flux per case through scalar observe, then through jax.jit(jax.vmap(...)) of the same observe, and compare. Stable observable paths come from _named_tree/_leaves; the committed exact/dual-envelope rules from _score_observable. Intermediate receipts are taken only after a terminal leaf differs.

Seven no-candidate findings, two of which change the plan's scope. There is no package-level terminal-observable registry — only the benchmark generator, the tests and the committed JSON own the 69 registrations. There is no observe_batch, so the batch arm must be a vmap of observe. Neither jitted-eager-parity-gate.json nor conditioned-convergence-and-observables.json retains the two raw route values for a case, and neither retains terminal flux arrays — so the discriminator must run; it cannot be reconstructed from the banked aggregates. Nor do the receipts retain clipped-support moments, radial-volume numerators, eroded support masks, intermediate current or divergence fields, or reduction indices, so localising a first differing operation needs a focused trace around the shared spine. Finally, a heterogeneous six-profile solve_batch does not exist: solve_batch batches dynamic arrays for one profile, and the shot-wide MAST vmap belongs to another solver and emits no ForwardEquilibrium labels. The existing solve_batch parity regression checks flux agreement and aggregate finiteness, not these three labels.

Per-observable fitness verdicts. moments.volume — STRONG TARGET, BOUND QUALIFICATION REQUIRED: its exact equality is an empirical zero-width float64 calibration envelope, not a discrete-type guarantee, which is the fact the exact-equality-bounds decision turns on. moments.major_radius — STRONGEST SHARED-SUPPORT COMPANION: it shares the clipped volume support and differs by up to 2.220446049250313e-16 at 2.7365469397805193 bound utilisation, so it should be evaluated alongside volume rather than separately. conservation.divergence_j — DIRECTLY REUSABLE, BUT NOT THE MOMENT SUPPORT: it uses a distinct eroded finite-difference support and fails mainly through relative difference 0.6 against a relative bound of 0.15286615188530017.

§4 — Label parity as a re-runnable acceptance, and the instability it exposed

One entry point — nova.equilibrium.observable_acceptance.evaluate_observable_bound_acceptance — validates registered shapes and dtypes, applies the registered exact or dual absolute-relative envelope to every case and every batch member, and fails a bound if any member fails. Batch-size dependence is real and it is stated per row. Three of 69 bounds carry batch-size-dependent case or aggregate pass status — conservation.divergence_b, conservation.divergence_j and moments.major_radius — and every one of the 69 receipt rows explicitly carries pass_status_depends_on_batch_size, so a reader cannot mistake silence for independence. divergence_b is a fourth failing observable that appears only at width 1, which no earlier measurement had surfaced.

The bigger finding, and the reason this receipt is worth more than a pass would have been: the labels are not reproducible against themselves. Two retained repetitions on identical inputs and one device moved the aggregate counts — 66 → 65 at width 1 and 68 → 66 at width 4. The worker retained the repetition rather than collapsing it into a pass, recording it as scientific evidence. That instability is a strictly stronger constraint on the label store than batch-size dependence is: batch-size dependence can be characterised and bounded, but a route that disagrees with itself across identical reruns cannot certify anything. Whether the reduction repair removes it is the next measurement, not an assumption.

The measured constraint the section carried is now demonstrated rather than argued. The plan warned that a semantically zero representation change had moved a reference root by 10.744 orders, and concluded that label parity at one batch size says nothing about another. That is now measured directly: the pass count itself moves with width, and moves again on a bare rerun. The acceptance is therefore correctly shaped as a per-rung re-run.
