The plan's throughput goal had been carrying an estimated denominator — “300–600 equilibrium timesteps per shot, roughly 3.5–7 M slices” — and every rung target below it inherited that estimate. The catalog actually holds 1,341,435 equilibrium slices.

Coverage is complete, which is what makes the number usable. The FAIR-MAST metadata index rows, the unique shots, the shot count this plan asserts, and the reachable mirrored stores all agree at 11,573, so the catalog-versus-mirror shortfall is exactly zero. Of those stores 11,378 carry equilibrium/time metadata and 195 contain no equilibrium group at all and contribute exactly zero slices — a real property of the catalog rather than a read failure, and stated as such so a later reader does not treat it as missing data.

The derived requirement. A 3,600 s wall clock over 8 devices demands 372.620833333 slices/s aggregate and 46.577604167 slices/s per device — not the 1,000–2,000 /s aggregate and 125–250 /s per device the plan carried. The requirement is 2.7–5.4× gentler than every rung gate written against the estimate, so those gates are over-specified and are restated before the first throughput rung is dispatched rather than after.

But the hour is marginal, not comfortable, and the larger estimate was hiding that. 46.6 slices/s per device is a per-slice budget of 21.5 ms. The banked warm-start economy from dual-basin-solve §4 is 19.070 ms per portfolio state — the same order. An over-estimated denominator had been concealing an under-measured per-slice cost; corrected, the two nearly meet. This also sharpens the plan's open convergence-policy decision: at 21.5 ms per slice, a bounded-tail two-pass scheme and a single global budget are separated by a much smaller margin than the plan's framing implies.

Method and its constraint. Counting read remote shot/campaign metadata plus local Zarr v3 shape JSON only. Zero equilibrium solves were run and no bulk signal arrays were downloaded, honouring the plan's counting constraint. The enumerator is committed reproducible at scripts/mast_slice_census/census.py and the receipt carries per-campaign rates and content hashes; an independent direct-filesystem JSON invariant check was run against it. Entry-gate state — the ladder stays shut

The census is the only throughput-plan node that has landed, and deliberately so. The plan is held at its entry gate under an owner directive that forward-solve stability and the multi-basin question be settled first, on the reasoning that a fast catalog of incorrect equilibria has no value. Recorded here so the gate's state is legible beside the census rather than only inside the plan's comment history.

Discharged: the multi-basin question. Closed by dual-basin-solve through attribution rather than by lifting the stalls. Branch selection is closed by construction — amplitude elimination leaves one admissible plasma branch at max closure error 2.495e-16 across all eleven frozen references. A DIII-D pinning control reached 1.59e-09 diverted in four accepted iterations where its paired unpinned control ended at 0.514 limited after twenty-four, from the same seed and the same 24-conductor input. Basin reachability was then attributed rather than solved: 5/5 stall floors scale with mesh (ratios 0.096–0.512, observed orders 0.97–3.39), so the stalls are discretisation-limited and no basin-entry driver can close them.

Not discharged: three live forward-solve defects. None is a basin problem and none is resolution alone.

  • The exact autodiff residual-Jacobian action is non-finite on the first Arnoldi vector, returning a finite zero step. Now screened — commit 6143221d, see the DIII-D landed record — but screening makes the failure visible rather than making the solve converge.
  • Topology-preserving trial admission is absent. The only route that converges (7.75e-11 in 89 accepted iterations) crossed topology at iterations 31, 50 and 88 and terminated on the wrong branch. Open.
  • A mesh-independent closure-path defect: the passive-closure reproduction move holds at 0.6098 / 0.6392 / 0.6378 points across realised 566 / 1587 / 2214 cells against a 0.15 ceiling, all six solves converged at or below 2.5e-10. Refinement does not buy it back. Owned by the operator-refinement lane and under trace.

Two consequences already recorded against the plan's own architecture. The batched Picard loop §2 specifies is not available: the map is non-contractive with spectral radius 1.1456 after current pinning and 1.2577 without, so the loop is Newton-only and the iteration distribution the first rung profiles is a Newton-step distribution. And the default residual action changes under the locked solver-default-route ruling to a finite-difference action, which costs one extra map evaluation per Krylov vector where an exact tangent reuses a single linearisation — so the 21.5 ms per-slice budget above must be re-derived on the differenced arm rather than inherited from an economy measured on the exact one.
