One DIII-D frame is built without its siblings (2026-09-17 21:41Z)

Node mulw-diiid-identity-single-member-build (s19-local worker, spec guided; commit 7c88c6a8).

Result. The DIII-D gate bank holds five frames and each is a different shot, so a frame's build reaches no sibling: it reads its own parquet, its own cached machine description and its own cold diverted seed portfolio. benchmarks/strict_exit_incidence.py now exposes that construction as a single-member build beside the whole-set builder, both formed from one row builder, with the whole-set builder's result unchanged. Separately, the identity frame driver measures one frame per child, started by re-executing the driver with a frame index rather than forking: a fork taken after a CUDA context is up deadlocks silently, so the previous shape could not isolate a frame by forking. A child that outlives a per-frame timeout is killed and recorded as a hang naming the timeout that expired, and each frame's receipt is written by its own child as it lands, so an expiry loses at most one frame.

Measure. The CPU equality gate asserts member 1 of the single-member build equals member 1 of the whole-set build on one DIII-D frame in a fresh all_debug process: identical identity, target current, tolerance, state authority and limits, a 1173-element float64 terminal seed state, 24 float64 coil currents and 2275 profile-operator leaves, all bit-equal, 9 passed in 187.52 s.
