§3 — The adapters got thinner, and the gate did not move

The point of the migration is that the MAST modules stop owning physics. They now re-export the package kernels: mast_acquisition_scale.py shed 757 lines and mast_sensor_noise.py 402, against 1,343 lines of new kernel. Behaviour is unchanged where it matters — the adapter lane ran 316 passed / 2 skipped in 6.03 s with the vacuum-cohort and block-scale read-path tests untouched, so the vacuum-floor gate is exactly where it was.

Full default suite: 4893 passed / 2 failed / 121 skipped / 4 xfailed in 1427 s, against the 4148-passed baseline the first slice recorded — +745 passes as the collection expanded.

§4 — The two failures, and why they are not ours

Both failures are store-backed probe-axis sign assertions in tests/test_mast_solve_inputs.py: for shots 15000 and 13500 the reconstructed probe axis comes back at +π/2 where the target is −π/2. They are pre-existing, they traverse no changed calibration path, and they sit in the module whose direct sensor doors mast-corrected-read-layer is closing — so that plan owns the fix. They are recorded here because this suite run is where the evidence was produced, not because this plan caused them.

§5 — Integration note

The block-scale import block conflicted on merge with concurrently landed promoted-chain work. Both intents were preserved: the chain imports stayed, and the ladder symbols (LADDER_TOLERANCE, ChannelScaleHistory, nearest_rung) moved to their new canonical home in nova.calibrate.scale_step, which mast_acquisition_scale re-exports so either import path resolves.

The adapter-boundary decision is locked arrays-only, ratifying what the first slice had already built. Keeping the geometry registry out of the kernels is precisely what makes the unit lane store-free: a registry-aware kernel would have to reach for geometry to build its own responses, putting a store path back inside a numerics module.
