Execution record for spine-boundary-accelerator. The earlier rung — the behaviour pins re-banked against synthetic truth, the exact-tangent Newton–Krylov and safeguarded Anderson promoted into the package, and the budget ladder that locked nk-jvp and implicit-fit — is recorded separately in the promotion record. This document carries the read-wall removals of §2 item 3 and the stencil generalisation of §2 item 4.

The governing discipline is read-equivalence first, speed second. Each removal had to reproduce the current read before its speedup counted, so every row below states an equivalence verdict beside its measured number. A removal that were merely faster would not have landed.

§2 item 3 — the read wall

The topology read is about 99.7% of every map evaluation, so it — not the accelerator — sets what a batched corpus solve costs. Three independent removals were scoped; two have landed.

Dilate-by-doubling flood fill

Commit 232cf5fa, merged to main. The forced one-cell dilation loop in nova/equilibrium/flux_surface_connectivity.py ran a fixed nr+nz iterations regardless of how far the fill actually had to travel. It is replaced by an associative fixed-point segment scan whose propagation depth doubles each step.

Equivalence: exact. The scan reaches the identical fixed point as the nr+nz reference — bit-for-bit array equality, not a tolerance — on both committed connectivity fixtures and both benchmark grids. The behaviour pins that guard the boundary push stayed green through the change: marginal-transition continuity, Lipschitz response, topology no-flip, and wall/X-point termination — 27 tests across tests/test_flux_surface_connectivity.py, test_connectivity_boundary.py and test_topology_boundary.py.

The steps beat the bound, and that is the result worth reading twice. The plan predicted about log₂(nr+nz) steps — 7.3 and 8.3 on these grids. The measurement is 2 on both. The doubling bound is worst-case over an adversarial fill geometry; a real connectivity region is compact enough that the front closes almost immediately. The speedup therefore grows with grid size (2.26× → 5.19×) while the step count does not, which is the signature of a cost that has stopped scaling with nr+nz altogether.

Measurements ran on JAX CPU under warm JIT: the installed jaxlib in the worker environment is not CUDA-enabled, so these are CPU per-evaluation ratios and a device run would have to be re-measured before being quoted as throughput. Harness: benchmarks/flux_surface_flood.py.

Warm-started binding search

Commit f5feee0a, merged to main. The binding level was rediscovered from cold on every map evaluation by a full 48-level sweep. The preceding flood level is now threaded through the device read and its exact cold-grid bracket reused while it stays local, with the cold sweep retained as the fallback for the first evaluation and for a bracket miss.

Equivalence: exact, including on the fallback. The limited and diverted behaviour fixtures reproduce the cold s_flood to exact array equality; a forced bracket miss was exercised as its own test and also reproduced s_flood exactly, which is the case that matters — a warm start is only safe if missing costs correctness nothing. All 20 existing connectivity and topology behaviour pins passed.

The wall-clock gain is well short of the operation-count gain, and that gap is the finding. A warm hit does 6 search evaluations instead of 48 — an 8× reduction in work — yet returns only 1.72× in time. The fixed per-evaluation overhead that survives the removal now dominates what the search itself costs, so further shrinking the level sweep has little left to win; the remaining read cost has moved elsewhere. This is also why the node was worth measuring rather than reasoning about: the operation count alone would have overstated the result by roughly a factor of five.

Timing selected JAX cpu:0 because the environment carried no CUDA-enabled jaxlib, so 1.72× is a CPU-specific figure and not a GPU throughput claim. Harness: measure_binding_search() in benchmarks/fixed_point_ladder.py.

Coarse-resolution iteration read

Commit ed5ed052, merged to main. The boundary push now iterates on an edge-preserving stride-2 read that restores the smooth core weight to the solve grid, while traced_emit_boundary_read remains the calibrated full-resolution read taken only at emit.

Equivalence holds where it is contractual, and the iterate is where it does not. The emitted psi_axis, psi_bnd, s_soft, radii and core_weight reproduce the full-resolution reference to exact array equality. The coarse iterate itself does not, and the difference is large rather than marginal: a maximum boundary-flux difference of 3.39×10⁻³ of the field span and a maximum cellwise core-weight difference of 0.985. Both are reported here at magnitude rather than absorbed into a tolerance, because the second number deserves to be read directly.

What that pairing means. A near-unity cellwise core-weight difference during iteration alongside a bit-exact emitted result says the fixed point is insensitive to the read resolution used to reach it — the coarse read moves the path, not the destination. That is the property the removal relies on, and it is a stronger claim than a small iterate difference would have been, because it is demonstrated at a difference large enough that agreement could not be coincidental. It also marks the limit of the evidence: the guarantee is on the emitted quantities under the pins exercised here, not a proof that no configuration can converge elsewhere.

§2 item 4 — stationary points on the hex rings

Commit 254ed6fb, merged to main. ring_sign_changes counted sign transitions by rolling a hardcoded 8-neighbour raster ring, which tied the stationary-point search to a rectangular grid even though nova's production plasma mesh is hexagonal and already writes its own angle-sorted neighbour rings. It now accepts an optional centre-plus-neighbour index array and counts cyclic transitions from it directly.

The default did not move. The rectangular raster roll remains the path taken when no stencil is supplied, and the full scoped suite stayed green — 14 passed, 1 skipped for an unavailable GPU.

The conditioning is the decision-relevant number, and it is benign. The plan required this be checked before any default switched, because a 6-coefficient quadratic fit on a 7-point cluster is exactly determined and therefore has no least-squares slack to absorb a poorly shaped neighbourhood. At 5.47 the normalised design matrix loses well under one decimal digit — the hex cluster is a well-posed geometry for the sub-null fit, not a marginal one. Nothing blocks a future default switch on conditioning grounds; the raster path stays default because no consumer has been rewired yet, which is scope this node did not carry.
