§7 — four bytes made the shared artifact unverifiable in parallel

Commit faac79e8. Gate passed — 4/4 concurrency tests in 90.10 s, 61/61 artifact regression tests. Scope was extended mid-node to nova/imas/mast_artifact.py.

The cause was deterministic, not a race anyone was unlucky with: the pre-fix failure rate was 20/20. HDF5's version-zero superblock begins at byte 1024, and bytes 1044–1047 hold the file-consistency flags. HDF5 sets them while any handle is open — the observed mutation is exactly byte 1044 going 0 → 1 and reverting on close. A raw whole-file digest of an HDF5 container is therefore never a stable identity while concurrent readers exist, which is why partitioned scoring cancelled SLURM 1245311 after three checksum races and had to recompute 105 of 180 partitions in private per-task caches.

MeasurementPre-fixPost-fix
verification under 4 concurrent opens, 20 trials0/20 succeed20/20 succeed
raw master digest during concurrent openmismatchesstill mismatches 20/20
4-partition run on one shared artifactrequired a private cache per taskcompletes, no private copy, no retry

That second row is the point: the mutation was not suppressed, and the fix does not pretend it stopped happening. Only the four consistency-flag bytes are canonicalized when deriving file identity, and manifest creation and reader verification both call the same _file_identity, so the two can no longer disagree. Verification stays mandatory for the manifest, the file inventory, sizes and canonical per-file digests.

The narrowness is proven exhaustively rather than asserted. A synthetic-image test rejects a change to every one of the 2,044 bytes outside the four-byte field — so widening the exemption would fail the suite, which is the property that keeps this from trading a deterministic failure for an undetectable one.

No re-publication is required, and this was checked rather than hoped for. Closed consistency flags are already zero, so the manifest master.h5 sha256, the new canonical identity, and the closed raw sha256 all remain 488c3db17800f4667b118efd54f3f33230b58c778202ab7581e8e2d87eeb84b0. Existing published artifact digests stay valid and no cache-key migration follows — unlike the dd_version identity change, which did force every cache key to move.
