§6 — Closing the guard's blind spots

Node acnwp-guard-follow-ons closes the four gaps the §3/§4 review found. A binary artifact that still embedded a worktree path is repaired and its two producers now repair their own dumps; two benchmark defaults that resolved into a removed worktree become required arguments; one evidence sentence that called its now-relative path absolute is reworded; and the guard's full-tree scan is replaced by one candidate search shared with the commit hook. Every gate below is logged with its exit status and wall time under logs/ in the run directory.

Binary artifacts: the cProfile dump and its producers

docs/figures/millisecond-converged-solve/trip-quantum/host-profile/production-solve.pstats is a cProfile dump that stored each frame's file path verbatim, so a run from a worktree embedded that worktree's path and the text scans skipped it as binary. relativize_cprofile_dump in benchmarks/production_solve_host_profile.py's producer loads the dump with marshal, rewrites every recorded file path -- both the top-level stat keys and the nested caller keys -- through relativize_worktree_paths, and writes it back in the format dump_stats produced. The producer calls it right after dump_stats, as does the second producer, benchmarks/program_scope_census.py (which writes cached-entry.prof; no copy is tracked). The committed dump was repaired with the same helper.

Gate (c) reads the repaired dump: pstats.Stats loads it, the 237 entries and 393 caller keys hold 630 distinct recorded paths, and none of the 630 contains the worktree root directory name (gate_c.log, EXIT=0). git grep over the file returns no match (rc=1).

Benchmark defaults

DEFAULT_SHADOW_ROOT in benchmarks/backend_divergence_forensics.py and DEFAULT_PINNED_ROOT in benchmarks/pure_arm_comparison_figure.py no longer hold a literal path, but they still resolved into a removed worktree. Both are removed; each root is now a required argument, and each option's help text says what kind of tree to pass (a checkout at the pinned revision that resolves the solver, and the .npz inside a pinned checkout respectively). One candidate search, shared

worktree_path_candidates in nova/database/filepath.py runs git grep --no-color -l -a -F <WORKTREE_ROOT> over the working tree (the repository test) or over the index with --cached (the commit check). -a treats binary files as searchable, so a committed binary that carries the root name is a candidate. Only the candidates are passed to worktree_path_offenders, the single scanning decision. The content is read by the reader that matches where the candidates came from: worktree_path_text reads the working-tree file for the repository test, and worktree_path_index_text reads the staged blob (git show :path) for the commit check, because the staged blob -- not the working copy -- is what a commit records. Both decode with errors="replace" instead of returning "" for binary content. This retires _staged_files and _staged_text in nova/database/scripts.py and _tracked_files in the guard test, all deleted, leaving one enumeration for the hook and the test.

The guard test asserts first that the candidate search returns nova/database/filepath.py -- the exempt module that always holds the root name -- before it accepts an empty offender list, so a search run from the wrong directory, without git, or after pattern drift fails loudly rather than reading as a clean tree. The predicate's offending branch is already covered at tests/test_filepath.py:263; the node adds tests for the binary readers, for both forms of the candidate search, and for the index reader's divergence from the working-tree reader.

The commit check reads the index

A review found the first form of the check still decided from the wrong content: the candidates came from the index (--cached) but _worktree_path_text read the working-tree file, so a file staged while it named a worktree path and then edited in the working tree without restaging passed the hook while the index blob still named the root. worktree_path_index_text reads the staged blob and relativize --check passes it into worktree_path_offenders; the working-tree reader stays for the repository test. Both readers are public, because nova/database/scripts.py and the guard test import them across modules. A test stages a file naming a worktree path, rewrites the working copy without restaging, and asserts the index reader reports it while the working-tree reader does not.
