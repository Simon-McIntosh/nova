§6 — Closing the guard's blind spots

Node acnwp-guard-follow-ons closes the four gaps the §3/§4 review found. A binary artifact that still embedded a worktree path is repaired and its two producers now repair their own dumps; two benchmark defaults that resolved into a removed worktree become required arguments; one evidence sentence that called its now-relative path absolute is reworded; and the guard's full-tree scan is replaced by one candidate search shared with the commit hook. Every gate below is logged with its exit status and wall time under logs/ in the run directory.

Binary artifacts: the cProfile dump and its producers

docs/figures/millisecond-converged-solve/trip-quantum/host-profile/production-solve.pstats is a cProfile dump that stored each frame's file path verbatim, so a run from a worktree embedded that worktree's path and the text scans skipped it as binary. relativize_cprofile_dump in benchmarks/production_solve_host_profile.py's producer loads the dump with marshal, rewrites every recorded file path -- both the top-level stat keys and the nested caller keys -- through relativize_worktree_paths, and writes it back in the format dump_stats produced. The producer calls it right after dump_stats, as does the second producer, benchmarks/program_scope_census.py (which writes cached-entry.prof; no copy is tracked). The committed dump was repaired with the same helper.

Gate (c) reads the repaired dump: pstats.Stats loads it, the 237 entries and 393 caller keys hold 630 distinct recorded paths, and none of the 630 contains the worktree root directory name (gate_c.log, EXIT=0). git grep over the file returns no match (rc=1).

Benchmark defaults

DEFAULT_SHADOW_ROOT in benchmarks/backend_divergence_forensics.py and DEFAULT_PINNED_ROOT in benchmarks/pure_arm_comparison_figure.py no longer hold a literal path, but they still resolved into a removed worktree. Both are removed; each root is now a required argument, and each option's help text says what kind of tree to pass (a checkout at the pinned revision that resolves the solver, and the .npz inside a pinned checkout respectively). Nothing else in either driver changed.

A record that contradicts itself

In docs/evidence/archive/figure-and-solver-audit-landed.html the hand-repaired coil-edit receipt sentence still described its repository-relative path as absolute. The clause now reads that the receipt recorded the path as absolute into a since-removed worktree and now carries the published repo-relative path, so a reader resolving the receipt's own figure field reaches the figure. Nothing else in the record changed.

One candidate search, shared

worktree_path_candidates in nova/database/filepath.py runs git grep --no-color -l -a -F <WORKTREE_ROOT> over the working tree (the repository test) or over the index with --cached (the commit check). -a treats binary files as searchable, so a committed binary that carries the root name is a candidate. Only the candidates are passed to worktree_path_offenders, the single scanning decision, with a reader that decodes each candidate's bytes with errors="replace" instead of returning "" for binary content. This retires _staged_files and _staged_text in nova/database/scripts.py and _tracked_files in the guard test, all deleted, leaving one enumeration for the hook and the test.

The guard test asserts first that the candidate search returns nova/database/filepath.py -- the exempt module that always holds the root name -- before it accepts an empty offender list, so a search run from the wrong directory, without git, or after pattern drift fails loudly rather than reading as a clean tree. The predicate's offending branch is already covered at tests/test_filepath.py:263; the node adds tests only for the binary reader and for both forms of the candidate search.

  • Gate (a). From the worktree with PYTHONPATH set to it, pytest tests/test_artifacts_carry_no_worktree_paths.py tests/test_filepath.py passes: 44 passed, 3 skipped, EXIT=0 (gate_a.log). The guard file alone reports 1 passed in 4.63 s of pytest time (8.58 s including the uv run wrapper), under the ten-second bar (guard_alone.log).
  • Negative control b1. A scratch git tree carrying a binary file that names a worktree path makes the guard test fail naming artifact.bin: FAILED, EXIT=1 (negctl_b1.log).
  • Negative control b2. In a scratch git repository carrying a copy of scripts/git-hooks/pre-commit (installed the way the repository installs it, through core.hooksPath), staging that binary file is refused: the hook prints artifact.bin: names a worktree path; run \`filepath relativize artifact.bin\` to rewrite it, exits 1, and commits nothing (negctl_b2.log).
  • Negative control b3. With the candidate search forced to return nothing, the guard test fails on its positive control (the candidate search returned nothing it is known to hold ...: candidates=[]), EXIT=1 (negctl_b3.log).
