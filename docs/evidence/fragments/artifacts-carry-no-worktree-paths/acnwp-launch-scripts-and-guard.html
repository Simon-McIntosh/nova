§3 — run-time roots, the residual data files, and the guard

Node acnwp-launch-scripts-and-guard makes the launch scripts resolve their repository root at run time, repairs the residual data files the §2 rule could not map, and adds a repository test and a read-only pre-commit hook that together reject any new worktree path.

Run-time roots in the launch scripts

Each launch script that used the worktree path as a cd target or output root now resolves it from its own location. Shell and sbatch scripts use the realpath-first idiom script_path="$(realpath -e -- "${BASH_SOURCE[0]}")" then repository_root="$(git -C "$(dirname "${script_path}")" rev-parse --show-toplevel)"; the four Python launch scripts resolve the root with git rev-parse --show-toplevel from Path(__file__).resolve().parent. Files where the path was only a comment or an echoed banner went through filepath relativize. benchmarks/backend_divergence_forensics.py and benchmarks/pure_arm_comparison_figure.py import WORKTREE_ROOT from nova.database.filepath instead of spelling the root. 58 shell and sbatch scripts plus 4 Python scripts carry a run-time root; a probe evaluated each root line from this worktree and every one (62/62) printed this worktree's toplevel.

The five residual data files

The two figure-and-solver-audit fragments and replan-2026-09-24/thin-interfaces.md were reworded to describe worktree paths without spelling the root. The truncated path in cpu-compile-abort-landed.html and the space-broken path in figure-and-solver-audit-landed.html were hand-repaired to repository-relative form, changing nothing else.

The repository test and the commit hook

  • tests/test_artifacts_carry_no_worktree_paths.py enumerates every tracked file with git ls-files, reads the working tree, and asserts worktree_path_offenders returns nothing, naming each offender. Its reader mirrors git grep -I (a NUL byte in the opening block reads as binary), so the test and the census share one reach. A positive control asserts the scan reaches a file in every top-level directory.
  • scripts/git-hooks/pre-commit is an executable two-line shell shim that runs the project interpreter on nova.database.scripts with relativize --check, PYTHONPATH set to the hook's own checkout root resolved with the same realpath-first idiom. The --check mode reads the staged files from the index and exits nonzero naming each offender; no file is modified. core.hooksPath is not set.

Census at head now lists only nova/database/filepath.py (which defines the pattern and is exempt). The new guard test fails at the dispatch base, listing the launch scripts as offenders. In a checkout carrying the hook, staging a file that names a worktree path makes the hook exit nonzero; after filepath relativize it exits 0.
