§2 — the rewrite rule and the data-file rewrite

Node acnwp-rewrite-data-artifacts implements the §2 rewrite rule in nova/database/filepath.py and applies it to every committed data file the census names. The rule is lexical, because the worktrees a committed path names no longer exist on disk. It matches a path under a nova-<hash> worktree by layout and rewrites it to its repository-relative trailing name; a bare worktree root becomes .; a path under another repository's worktree, or a layout the matcher cannot complete, is reported and left unchanged, never guessed.

The surface added

  • relativize_worktree_paths(text) -> (rewritten_text, unmapped_spans) owns the rule. repository_relative delegates its worktree case to the same matcher, so a path under a removed worktree maps identically through either entry point.
  • worktree_path_offenders(paths, read) is the one scanning decision the commit check and the repository test share.
  • Two module constants — WORKTREE_ROOT and WORKTREE_PATH_EXEMPTIONS — are imported by every other file that would otherwise spell the pattern, including the tests.
  • The relativize subcommand of the existing filepath click group applies the rule over files in place and prints each file changed and each span left unmapped.
