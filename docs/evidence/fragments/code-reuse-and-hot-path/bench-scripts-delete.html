The verdicts split on a kept-code reference

The census models Python imports only. Applying its 715 delete and 3 merge unconditionally would orphan files the census did not model as consumers: shell and sbatch drivers invoke a prototype’s entry module by name, kept Python modules import a sibling the census marked delete, and product docstrings name a benchmark. Those references break the census’s own keep rule (“imported by kept code”) because the keeping happens after the citation pass and does not cascade into the newly kept file’s imports.

So each delete path is checked against the whole tracked tree before it is removed. A path named by any kept .py, .sh, .bash or .sbatch file outside docs/ is withheld from this node and reported to the census defect. The initial scan exempted docs/ references; the final check below verifies that each exempted evidence reference carries a revision at which its named driver exists.

Withheld paths

The 102 withheld paths are named by 112 kept files across 138 references: 76 shell or sbatch drivers, 28 other kept Python modules, four test modules and four product modules under nova/. By area, 82 sit under scripts/prototypes, 14 under benchmarks, and the remaining six in six other script directories. They are reported on the node’s manifest rather than edited here, because repairing a shell driver or a product docstring is a separate decision from applying the census.

The same non-cascade defect reaches one step further. Two withheld files are reached only through another kept file’s bare sibling import: measure_branches.py imports terminal_class.py by its bare name after putting its own directory on sys.path, and test_terminal_panel_geometry.py imports render_terminal_panels.py the same way. Both siblings were deleted in the batches and both are restored here, because deleting them broke test collection with ModuleNotFoundError. The reference scan that keeps a path is a path-string scan, so it sees neither a bare module name nor the directory that resolves it.

Repairs after review

A review of the first round found kept content still naming deleted paths. Every one is now restored from the batch base rather than edited: editing a caller to hide a reference leaves its behaviour broken, while a restored file is byte-identical to the revision it came from.

  • benchmarks/nearfar_error.py: the kept module benchmarks/near_field_elliptic.py runs it through subprocess.run(check=True). That caller cannot import at the base either, because it names _R_FLOOR from nova.biot.greens and the name is gone, so the deletion added no new failure; the reference itself is what the clause forbids, and it now resolves.
  • scripts/prototypes/diiid_xpoint_held_nodes/: the five modules the kept prototype loads by path, restored with measure.py, batch.py, preflight.py, provenance.py and render.py. Loading the kept prototype then failed further down its chain, so the restore follows imports rather than one directory: it reaches diiid_core_hold/measure.py, then diiid_diverted_branch/measure.py, whose import measure resolves through scripts/prototypes/diiid_warmup_admission, the directory that file puts on sys.path. That directory’s eight modules are restored too, as is diiid_core_hold/batch.py, and the prototype now loads.
  • benchmarks/BASELINE.md: a kept document naming deleted drivers. The eight drivers it names are restored, so the document reads true at the head without a revision stamp.
  • The six scripts/<topic>/report.md receipts named twenty more deleted drivers. Each restored driver named four others in turn, and the restore ran to a fixed point: 47 files, 18107 lines.
  • Re-running the same scan at that head found twelve more references, all of them in scripts/<topic>/run*.log receipts naming five deleted drivers. Those drivers are restored in a second commit: five files, 3550 lines. The repair round therefore restores 52 files and 21657 lines in total.

The scan that keeps these honest is re-run to a fixed point over the whole tracked tree: every deleted path is searched for as a path string in every kept file outside docs/, and every kept module is parsed for a bare import whose module file is deleted and whose directory the importer puts on sys.path. At the head it reports no path string and no bare import. The first round’s scan reported neither defect because it matched only a whole path in a code file and knew nothing of a directory put on sys.path.

The batch table above is corrected here: batches four, five and six removed 29931, 29959 and 29691 lines against the 29926, 29946 and 29685 first recorded, taken from each commit’s own --shortstat.
