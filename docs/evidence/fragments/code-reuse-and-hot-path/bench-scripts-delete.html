The verdicts split on a kept-code reference

The census models Python imports only. Applying its 715 delete and 3 merge unconditionally would orphan files the census did not model as consumers: shell and sbatch drivers invoke a prototype’s entry module by name, kept Python modules import a sibling the census marked delete, and product docstrings name a benchmark. Those references break the census’s own keep rule (“imported by kept code”) because the keeping happens after the citation pass and does not cascade into the newly kept file’s imports.

So each delete path is checked against the whole tracked tree before it is removed. A path named by any kept .py, .sh, .bash or .sbatch file outside docs/ is withheld from this node and reported to the census defect. Every docs/ reference is a historical evidence record carrying the revision it ran at, which the plan permits.

Withheld paths

The 102 withheld paths are named by 112 kept files across 138 references: 76 shell or sbatch drivers, 28 other kept Python modules, four test modules and four product modules under nova/. By area, 82 sit under scripts/prototypes, 14 under benchmarks, and the remaining six in six other script directories. They are reported on the node’s manifest rather than edited here, because repairing a shell driver or a product docstring is a separate decision from applying the census.

The same non-cascade defect reaches one step further. Two withheld files are reached only through another kept file’s bare sibling import: measure_branches.py imports terminal_class.py by its bare name after putting its own directory on sys.path, and test_terminal_panel_geometry.py imports render_terminal_panels.py the same way. Both siblings were deleted in the batches and both are restored here, because deleting them broke test collection with ModuleNotFoundError. The reference scan that keeps a path is a path-string scan, so it sees neither a bare module name nor the directory that resolves it.
