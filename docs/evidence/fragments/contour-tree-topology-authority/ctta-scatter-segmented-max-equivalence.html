Carrier neighbour combine: a duplicate-index scatter equals a segmented maximum

The carrier sweep folds one contribution per edge endpoint into a per-vertex key. A vertex named by several edges supplies that key more than once, so the combine sees duplicate indices. A last-write-wins combine would make the reduction depend on the order the carrier happens to store its edges, and a receipt could change without the graph changing. Combining duplicates with a maximum removes that dependence. This node names the equivalence the sweep relies on, which the near-linear sweep's review argued but no test pinned.

tests/test_contour_tree_scatter_equivalence.py builds carrier graphs whose edge endpoints repeat and asserts the scatter's result equals jax.ops.segment_max and a NumPy np.maximum.at reference, bit for bit, at fixed seeds. The named cases are a vertex at the carrier's full neighbour width (sixteen edges on one vertex, its neighbour row full), a vertex no edge names (an empty segment that must keep the reduction's identity), and an edge stored three times.

The negative control replaces the scatter's maximum combine with last-write-wins; the saturated-vertex case and all five random-carrier seeds then disagree with segment_max, while the empty-segment and single-endpoint cases are unchanged. The hazard is therefore measured, not restated: the equivalence holds because the combine is a maximum.
