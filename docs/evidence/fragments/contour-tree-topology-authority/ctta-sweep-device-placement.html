Contour-tree sweep placement

The benchmark holds the carrier arrays fixed across placements: 12 persisted certificate rungs (340, 550 and 1074 cells) and the two MAST carriers. It compares serial host calls, a device vmap of the existing sweep, and a benchmark-only device union-find prototype that pointer-jumps the full parent table at each visit. CPU-built carrier arrays are persisted before the H200 arms so the placement comparison does not include a backend-specific mesh-construction roundoff.

Placement: keep a single solve on the host CPU (0.225 s mean versus 0.370 s for the H200 prototype); use the H200 parallel union-find formulation for a labeller batch (0.407 s at eight fields versus 1.793 s serial) and for a census (0.461 s at 64 fields versus 14.484 s serial). Do not use device vmap alone: it is slower than the host for one field and slower than the parallel prototype at every measured batch.

The committed comparator reports zero mismatches for every receipt field (node_vertex, node_psi, node_valid, critical_type, edges, edge_valid and overflow) for CPU versus both H200 placements. Compile walls are reported per arm; CPU arms were intentionally bounded per carrier, so their cold setup is not a process-amortised deployment estimate.
