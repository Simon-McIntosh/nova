Certificate booking on fixtures rebuilt in the run's own root

The booking helper read the certified carrier and exterior records by the semantic key recorded in their receipts, and refused them: the stored groups were keyed on a superseded identity schema and carry a wall hash the current sources no longer produce. Every one of the six analytic certificate parametrizations therefore failed before booking, so the closed-form booking identity was unverified on the certificate carriers. Both fixtures are now built on the identity the current sources define, under a writable root the run owns, and the certified directory is read and never written. In the same node the scanned-operand guard against a sequential cell axis is tightened from a length comparison against one cell count to the traced program's own leading axis, with a negative control that lowers a sequential scan of a different length.

Fixture rebuild on the current identity

A published carrier record is keyed on the identity schema in force when it was written, so it cannot be reused once those sources move. Reading it by the recorded key raised before booking: the base arm of H200 job 1287207 fails all six rows with AssertionError raised at scripts/prototypes/support/book.py:55, inside the cache-key assertion, with no receipt written. The repair does not attempt to reuse the stored groups. Both helpers build instead on the current identity. The carrier build is redirected by pointing NOVA_ANALYTIC_ORACLE_CACHE at the run's root for the duration of the call; the exterior build places its store beside its caller, so its store factory is substituted for the same span. Each helper asserts the resulting store path lies under that root, so a build that landed anywhere else fails loudly rather than quietly publishing over a certified record. The root is NOVA_BOOK_FIXTURE_ROOT when the caller sets one, and otherwise a directory the process creates under its own temporary root. Nothing is written back into the certified caches.

The fixture helpers hold a lock file beside their store, so a read that fell back to the certified directory would open a lock file for writing there. Rebuilding is therefore not only the simpler path but the one that keeps the read-only promise: the certified caches are opened for reading only, and every lock, group and machine this node builds lands under the job's own temporary root.

Rebuilding costs the machine build, which dominates the gate. The six rows were cold on this job: the head arm ran 3521 s wall for the six rows, of which the 2,000- and 5,000-cell carrier builds are the larger part, against 10.2 s for the base arm, which fails before any build. A run that needs the same rows twice pays that cost twice, because the fixtures live under a temporary root that is removed when the job ends.

The scanned-operand guard

The guard against a sequential scan over the cell dimension compared every scan length in the lowered program against one number, the cell count of a single 17-cell fixture. A scan that iterated the cells at any other bound passed: only a scan of exactly 17 was refused, and 17 was also the length of scans that are legitimate ring reductions, so the check was keyed on an incidental collision rather than on the axis. The guard now traces the booking program at two cell counts and identifies the cell axis from the program's own input — the leading axis of the traced flux samples, which every per-cell operand carries — and refuses the program in two cases: a scan length equal to that axis, and a scan-axis set that changes with the cell count. The second case is what makes the guard a statement about the dimension rather than about a length, because a scan over the cells moves with the count whether it runs to the count, short of it, or past it.

The negative control replaces nova.equilibrium.current.book with a program whose body does a lax.scan over jnp.arange(cells - 2), a bound two short of the cell count, loaded as a pytest plugin so the guard test's own import binds the mutated callable. The tightened guard refuses it in one test: the traced scan axes are {15} and {17} at 17 and 19 cells, reported as follows-cell-count, and the run ends EXIT=1 with test_booking_does_not_scan_over_cells failing. The committed head passes that same test. The bound is not 17, so the length comparison the guard replaces would have accepted this program; the control is a measurement of the tightening and not of the guard's continued presence.

The guard test is not new — it existed at the orientation base and passed there, which is the finding: it passed because its single 17-cell fixture could not distinguish a cell scan at another bound from a ring reduction. Naming more cell counts is not enough on its own; what closes it is asking the program which axis it scanned.
