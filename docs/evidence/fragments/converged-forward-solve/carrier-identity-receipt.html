Carrier vertex identity: the device receipt and the importing-test arm rebuilt at main

A measurement at main revision 0f50140bb, which carries both the vertex grouping rule and the pinned reference solve. No product code, test or data file changed: the only committed source is the driver scripts/prototypes/carrier_identity_receipt/measure_carrier.py, which builds each certificate carrier through the same route the identity test uses and publishes the identity that build reads. The receipt is a build's own output rather than a test's, so the arm can be re-measured without importing a test module, and a carrier that will not build records the stage that refused it instead of aborting the run.

The limited 550-cell carrier still does not build at main, and the refusal is the same one and at the same stage on both devices: ValueError: cell edges must have non-zero length, raised in AtomicCellMesh.from_cells at nova/equilibrium/separatrix_clip.py:1950, reached from MomentGeometry.from_cells at nova/equilibrium/stencil_mesh.py:545. The limiter-contour wall at this cell count yields a polygon carrying a zero-length edge, so the arm publishes no identity on either device and no partition can differ. This is a pre-existing build limitation of the carrier, not a change in the partition, and it is recorded rather than worked around.
