The carrier is the same carrier on every device

Two changes make the diverted 300-cell certificate carrier device independent. The reference solve now runs through one ordered routine, so its coefficients are bit-identical wherever it runs, and the moment geometry identifies a lattice vertex by the cell slots that share it rather than by a quantised coordinate.

The constraint system the reference solves has condition number 1.58e5, so a last-bit difference in the library solve becomes 4e-14 in the coefficients and moves every wall and cell position downstream.

A vertex is the slot set that shares it

MomentGeometry.from_cells merged sampling and atomic vertices by rint(vertex / tolerance). A shared corner is reconstructed once per cell that carries it, so the copies differ in their last bits; two copies merge only while they fall inside one bin, and a bin boundary between them is decided by the phase the reference solve happens to produce. The merge now reads the mesh's own neighbour rings, which the geometry already receives: two slots of adjacent cells join when their coordinates agree within 1e-9 of the mesh scale, which is a millionth of the distance between neighbouring corners and a thousand times the observed drift. A merge is accepted only when the match is mutual and unique, so a wall-clipped sliver cannot be collapsed into a degenerate polygon. Merged polygon vertices carry one stored coordinate, so the atomic mesh that atomises them keys on equal values instead of on a bin edge.

The vertex identity is compared as a partition, not as the numeric id array: the two devices list the same cells in a different order, so a slot's id is not comparable between them. Each slot is named by the micron cell of its own centre and the comparison asks which slots share a vertex, which a cell reordering does not disturb.

The reference solve is solved twice in fresh processes at OMP_NUM_THREADS, OPENBLAS_NUM_THREADS and MKL_NUM_THREADS of 1 and 4, and the coefficients, magnetic axis and separatrix are required to be bit-identical. The solve publishes coefficient_digest, the sha256 of its coefficient vector as stored binary64, so a carrier records the reference it was built from.

One delta: test_preclip_samples_come_from_the_verified_authored_generator. It builds a mesh carrying a single ring — one centre and its six nearest cells — and requires PlasmaGrid._index_sampling_vertices to reproduce MomentGeometry.sample_node_coordinates. The two agree only while the identity is mesh-independent. It is not any more: a vertex is now the set of slots that share it through the adjacency the mesh declares, so a one-ring mesh merges nothing that lies outside that ring, and the test's restricted lattice keeps 318 sample nodes where the grid's full lattice keeps 242. The binned identity it was written against merged coincident coordinates globally, so adjacency played no part.

Reconciling the two means either the sample bank adopts the lattice identity as well — which changes this pinned equality rather than preserving it, and so needs the test file itself, outside this round's write scope — or the identity grows a global tolerance pass, which changes all three device arms and the negative control and must be measured again. The delta is recorded rather than argued away.

Two files did not produce a result. tests/equilibrium/test_topology_read.py and tests/test_equilibrium_forward_reference.py exceeded the 420 s per-file bound on both arms, so neither carries a measurement in either direction. They are the heaviest of the eleven and were not run to completion here.

One residual device difference is outside this node's write scope: the atomic vertex count reads 923 on the CPU and 922 on the H200 at the head, because AtomicCellMesh.from_cells in nova/equilibrium/separatrix_clip.py still atomises by a quantised coordinate key. It does not enter node_number, which counts the grid, wall and sample vertices, and those agree exactly.
