Tangent compile rows measured by child CPU seconds

The compile rows timed each fresh process by wall, which moves with unrelated load and pushed rows past the 3.0 bound without the program having changed. The shared harness tests/biot/tangent_identity.py now measures each fresh compile process by the CPU seconds it spends inside lowered.compile(), taken with time.process_time() around exactly that call and reported by the child. compile_ratio asserts the 3.0 bound on the median of seven CPU medians, with no absolute floor. The wall and the whole child's CPU (from getrusage(RUSAGE_CHILDREN) deltas around the spawn) are printed beside every arm. The whole-child CPU is recorded but deliberately not the asserted measure: a fresh child spends about five CPU seconds importing the interpreter and the module before compiling anything, a constant that would collapse the ratio toward one and let the row measure the interpreter rather than the program.

The negative control NOVA_TANGENT_COMPILE_HEAVY=1 compiles the tangent program twice and sums it. On graded_residual the tangent program grows from 953 to 1910 expanded equations and its median compile CPU rises to 2.478 s against a 0.615 s primal, a ratio of 4.03, so the compile row fails on the CPU measure. pytest reports it as test_tangent_compiles_within_three_primals[graded_residual] in negative-control.log (EXIT=1).

The gate did not complete in the 60-minute fence and cannot as written on this allocation. Each compile row spawns 21 fresh processes, and each fresh process imports the test module (its base modules and fixtures) before compiling, so a row costs 3.5 to 7 minutes. On two of the three rows the sequential pass reached, the row itself exceeded the repository's 300 s per-test pytest-timeout before its assertion ran: test_tangent_compiles_within_three_primals[complete_pole] and ...\[product\] both failed with Failed: Timeout (>300.0s), not a ratio. Reaching all 29 rows twice sequentially and twice under eight CPU-bound processes is a gate of many hours here, and any row whose wall approaches 300 s cannot complete under added load at all. The rows measured: factorise passes at 2.37 by CPU; graded_residual fails only when the deliberately heavy mutation is applied. Not run: the loaded passes, the complete_pole and product diagnosis at the bound, graded_residual without the mutation, and the tests/biot delta.
