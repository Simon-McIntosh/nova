Unfinished, with reason

  • separatrix_clip.padded_polynomial_current_moments: the clause asks that it be deleted and its consumers rerouted to the owner. The code contradicts the premise. The function is not a duplicate reduction: it localises to centroid and scale, calls the owner, and contracts a complete polynomial basis of degree two through nine. Its consumers (ring_attribution, own_node_interior_score, density_moment_projection, in_cell_order_study, density_forcing_ladder, and two test modules) all live inside the granted write scope, so scope is not the obstacle. Deleting it would either remove the only route for degrees above two, which density_moment_projection and density_forcing_ladder use at degree nine, or inline the same localise-and-contract body into eight call sites, which is duplication rather than hygiene. It is left in place and reported.
  • polygon_density_moments and its module: the clause asks that both be deleted and the module removed "if nothing live remains". Something live does remain — benchmarks/exact_clip_closed_form_floor.py measures the closed-form route through it against the fan reference and the locked per-row budget, which is a live measurement of the surviving owner route and not a dependent of the deleted name. The duplicate name is gone; the contraction the live measurement needs is kept.
  • The certificate-row reconciliation was not attempted. It is a two-stage heavy pipeline: scripts/prototypes/support/measure.py builds the {kind}-{cells}-fixture.json identity files, then book.py books against them, and the comparison against merge 06cc5abe1 needs the same six rows on a second tree. None of the fixture files exist in the tree, the GPU lane is required, and the adjacent read gate was the subject of a dedicated node that ran nine attempts across three days. It is not reachable inside a one-hour fence.
