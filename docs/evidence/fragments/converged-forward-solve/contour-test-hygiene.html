Contour-tree test hygiene

The capacity-overflow check called build_contour_tree directly, so it no longer exercised compilation though its name and docstring claim it; a jit-incompatibility in the build would have left it green. tests/test_contour_tree_merge.py::test_critical_node_capacity_overflow_is_jittable_and_visible now calls the build through jax.jit(build_contour_tree, static_argnames=("neighbour_capacity","node_capacity","edge_capacity")) and asserts the overflow flag, the 256 valid nodes and the 255 valid edges through that compiled call. The declared negative control was applied in a scratch extraction: a Python branch on a traced value was inserted at the head of the build body, and the test then fails with a tracer truth-value conversion, EXIT=1, in fresh process. The mutation lives only in the scratch tree; no product source changed.

The sparse-build receipt check pinned a sha256 digest of the receipt's integer arrays for every (kind, cells). At 2,000 cells those digests are host-dependent: the same code passes on a sirius node (job 1292526, c84c432e9) and fails on this Broadwell fleet node class (98dci4-clu-2068), two failed and two passed, with the receipt reordered. test_sparse_build_matches_base_receipt now checks host-independent structure instead: the receipt's valid arcs form a tree spanning its valid node rows, so the valid node count exceeds the valid arc count by one, every arc endpoint is a valid node row, no more than one valid node is the typed-outside slot, and every other valid node maps to a valid carrier vertex. The pinned digest is kept only for the 550-cell rows. A component-count reference was tried and rejected: a superlevel component can join several above-level tree nodes through a below-level saddle, so the component count does not follow the receipt's node and arc tallies. An env-selected arc-drop mutation (CONTOUR_TREE_ARC_PERTURB=rewire) makes the check fail on this fleet node class.
