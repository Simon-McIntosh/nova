The MAST-U s1-4-5-B read is refused by the carrier adjacency table's fixed width of 16, not by the 256-node or 255-edge DD capacities. On the main checkout snapshot db4375c2fb8a90d5f1fbfcf890bc95c1e36d9550, the native ContourTreeArrays.overflow is true at lattice resolutions 16, 24 and 32. This diagnostic has a positive control for its degree counter: it reports the 3, 2 and 2 overfull MAST-U vertices while reporting zero for the limited carrier. Each process also checked the native receipt against the individually reported adjacency, join-append, split-append, split-insertion and DD-row overflow sources. Only adjacency is true in the three MAST-U rows; all five are false for limited 550.

The refusal is set in nova/equilibrium/contour_tree.py: _carrier_adjacency selects neighbour_capacity = 16 when edge_count > 2 * vertex_count at line 223; it sets overflow = jnp.any(keep & (position >= neighbour_capacity)) at line 256. build_contour_tree incorporates that bit at lines 509–513 (specifically line 511), alongside separate node and edge count checks. Each MAST-U carrier satisfies the sparse-graph branch condition and has valid endpoint positions 17–22, so the 16-slot table omits real neighbours and correctly refuses the resulting partial tree. The reported node and edge rows are the partial receipt's counts, not evidence that its topology can be accepted.

The carrier-side checks found no duplicate edge pairs, self edges, duplicate vertex coordinates, or equal-flux edge endpoints at any MAST-U resolution. Every live vertex has a distinct flux value (291/291, 533/533, 825/825), ruling out an exact flat-flux plateau as this count's cause. The overfull vertices have distinct incident edge endpoints and are not marked as wall vertices. These checks establish a genuine degree beyond the table's declared width, rather than an inflated count from those tested degeneracies. They do not claim that all possible geometric defects have been excluded.

Repair owner: nova/equilibrium/contour_tree.py, _carrier_adjacency and build_contour_tree. Replace the fixed 16-neighbour assumption with a shape bound at least the carrier's actual maximum valid degree, computed from the carrier at geometry construction and supplied as static mesh metadata to the JIT build. Preserve a visible refusal if an explicitly declared width is smaller than the measured degree; keep the DD node and edge capacity checks independent. A generic direct-graph call needs a safe edge-count bound when no carrier degree metadata is supplied. The repair must retain the sparse build's scaling rather than allocate an edge-width row for every vertex on large meshes. scripts/prototypes/contour_tree_overflow/test_overflow.py::test_machine_carrier_fits_tree_capacity is the regression contract: it fails on this main snapshot because the 16-resolution MAST-U receipt overflows, while the small-field test proves an ordinary graph still stays within capacity. After repair, the production topology-read test should assert that the MAST-U receipt is accepted, without weakening refusal for a deliberately undersized declared width.
