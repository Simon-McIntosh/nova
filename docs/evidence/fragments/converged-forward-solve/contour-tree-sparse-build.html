Sparse contour-tree build

The build no longer scans the whole edge table per vertex, iterates the growing carrier arrays, or forms a dense node-by-vertex equality matrix. Carrier adjacency is assembled by a stable lexsort over edge endpoints, the split-node pass visits only split-only vertices, the per-visit arc append is vectorised against a free-slot index, and the node-to-vertex inverse map is a scatter.

Receipts at 550 and 2,000 realised cells on the limited and diverted analytic cases are byte-identical to the base revision efd1d9553 across node_vertex, node_psi, node_valid, critical_type, edges, edge_valid and overflow. The committed test pins the six arrays whose bytes are host-independent — node_vertex, node_valid, critical_type, edges, edge_valid and overflow — by digest against the base build's own receipts, so carrier slot order, wall-contact semantics, tree arcs and critical-type assignment are shown unchanged rather than assumed. node_psi is float64 carried through from the caller's flux field, so its bytes encode the host's XLA codegen rather than the build; it is asserted as the contract the build owes instead, that every valid node row carries the value the build was given, gathered at that row's carrier vertex. The same file passes on both hosts measured (see below).

H200 job 1290126 on 98dci4-gpu-0003 (device cuda:0) measured both builds over the same four rungs. The repair buys 5–8% of warm wall and does not move the exponent: the four-rung fit is 1.467 base against 1.501 sparse for the limited whole read, and 1.473 against 1.495 for the diverted case. The 10,000-cell whole read is 81.557 s base and 75.948 s sparse on the limited case, and 78.438 s against 72.033 s diverted — the 10 s whole-read target is not met; the nearest figure is 72.0 s. The contour-tree stage carries the read on every row, and its compilation grows no faster than linearly (8.9 s at 10,000 cells).

Because the removed structures were real but the exponent did not move, they were not the dominant cost, and the O(N log N) argument that motivated them does not describe this kernel. The now-dominant operation is the contour-tree sweep, unchanged here: _sweep_tree runs a lax.fori_loop over vertex_count whose every sequential step carries nine state arrays and calls the pointer-doubling while_loop in _neighbour_roots plus an arc append, so two sweeps issue on the order of 2·N dependent dispatches. That is named as the leading candidate, not as a measured attribution; instrumenting it is the next node's work.

The two suite arms ran as one sirius batch job. A first attempt (job 1290127) was lost: the base arm segfaulted inside JAX compilation after 58 tests and the job then exhausted its four-hour limit before writing either arm's record. The resubmission (job 1290366) runs each arm as its own process so a crash is recorded as that arm's exit status rather than ending the job. The negative control — restoring the base build's dense equality matrix verbatim and clearing SPARSE_INDEXED_BUILD — turns the sparse-build test file red with a non-zero exit, failing the marker test while the four receipt digests stay green.

The suite found a defect this node had introduced, which is the outcome the brute-force and order-invariance files exist to produce. _carrier_adjacency selected its valid endpoints with jnp.nonzero(keep, size=sources.size, fill_value=0); because only a few hundred of the fixed 4,096 concatenated endpoints are valid, every excluded endpoint was replaced by an index of 0 rather than dropped. Vertex 0 therefore counted thousands of phantom neighbours: its degree was inflated past the declared capacity and the adjacency table carried the wrong neighbours for every mesh. That one cause produced all three head-only failure groups — five capacity refusals in the brute-force file, six order-invariance failures, and four digest mismatches — while the base arm passed all three. The mask is now applied as a sort key rather than a filter, so an invalid endpoint takes the padding row and inflates nothing.

Both arms ran as one sirius batch job (1290820) that gives every file its own fresh pytest process, because one process across all of them segfaulted inside JAX compilation and then hung in the faulthandler dump, which is how two earlier allocations were lost. The base arm is revision efd1d9553, extracted with git archive; the head arm was re-run at the fixed build b65fd38fa. No per-file log contains a SKIPPED line, so the census tie tests ran rather than skipped under the analytic oracle cache. Judged by delta, the head adds no failure anywhere: the six failures the base arm reports in the topology-read file are the head arm's six, and the seven setup errors the base arm reports come from git rev-parse HEAD failing in a tree that is not a git checkout rather than from the build.

The four added failures were the pinning test's own fragility, not the build, and the test now pins only what travels. test_sparse_build_matches_base_receipt hashed the exact bytes of every receipt array, node_psi among them, against constants recorded on 98dci4-clu-2002. node_psi is float64 carried through from the caller's flux field, so the hash was sensitive to the host's XLA codegen rather than to the build's semantics. Sirius job 1291014 ran the base build and the head build through the same fixture path on 98dci4-clu-5050, the host the after arm ran on, and printed head == base for all four configurations while both differed from the pinned values; the same comparison under a single pinned CPU on 98dci4-clu-2002 reproduced the pinned values exactly, so the variable is the host and not the CPU count. The pin is therefore split by portability. The six integer and boolean arrays are digested against the base build's own digests, computed by sparse-build/suite/pin_integer_digests.py with the base module loaded beside the head, which reports head == base for every configuration. node_psi is asserted as the contract the build owes: every valid node row carries the value the build was given, gathered at that row's carrier vertex, and every invalid row carries zero.
