The support arm now agrees with its own name

The default is now the exact arm: EXTERIOR_SUPPORT_ARM = _EXACT_SUPPORT_ARM, read by the function signature, the fixture exterior and its cache identity, so a single constant governs the exterior, its identity and its moments. Callers that depended on the old default now receive the exact arm; that is the intended change and their rows are the ones measured below.

The two rules are the same rule

The reroute is identity-preserving only if the deleted tensor-Duffy rule and the owner's signed-jacobian fan rule agree. Measured on the login node in binary64 over convex, non-convex, holed and overlapping rings, relative agreement in every moment component:

The declared negative control

The declared mutation sets EXTERIOR_SUPPORT_ARM to the legacy arm, restoring the default that exact_current_moments selected before this node. It must turn test_exterior_closure_falls_below_booking[2000] red while the head arm passes it.

Three attempts, and the first two are recorded because a control that fails for the wrong reason is not a control. Job 1283914's control passed, but so did its head arm — the mutation was inert, because the overlay that carried it was shadowed: python -m pytest puts the working directory at sys.path[0], ahead of PYTHONPATH, and with tests/__init__.py present the repository root is also pytest's rootdir, so a fixture module reached through PYTHONPATH alone never won the import. Job 1283963 made the overlay the rootdir and the mutation did take effect (EFFECTIVE_ARM legacy), but its variant tree held only scripts and tests, so the run died at FileNotFoundError: nova/biot/polygonanalytic.py — red for a missing-file reason, which is not evidence about the mutation. Job 1283965 fixes both: the variant is the worktree with every top-level entry symlinked and scripts a real mutated copy, so the overlay wins the import and the rest of the package still resolves. Its header confirms both (EFFECTIVE_ARM legacy /tmp/variant_legacy2_1283965/scripts/…, POLYGON_MODULE /tmp/variant_legacy2_1283965/nova/biot/polygonanalytic.py). The certified booking rows cannot be re-read

Done-when (3) also asks that the current.book rows equal those recorded at 06cc5abe1, read from the certified cache of r-20261009T181553786165-proto-support. That read is refused by an identity guard, for a reason independent of this node's change.

scripts/prototypes/support/book.py rehydrates a recorded carrier through fixture._from_dataset, which requires the store's recorded semantic_identity attribute to equal a freshly recomputed identity (measure.py:716-722). The certified stores record a superseded schema. Read directly from analytic_oracle_clipped_exterior.zarr, group ac098ff84d3cab83:

{"schema": "analytic-oracle-clipped-exterior",
 "machine_semantic_key": "4c818bdbed936090",
 "clip": "production-spline-geometry-from-analytic-zero-level", ...}

There is no builder_revision key and no closed_form_constants block, so fixture.cache_identity emits a different shape today and the equality cannot hold at any revision at or after the schema change. All six booking rows failed this way in job 1283901's book.log, at book.py:55, before any measurement ran. A repaired read path — trust the receipt's recorded group, and corroborate it by requiring the exterior's recorded machine_semantic_key to equal the receipt's machine key — was written, measured to still be refused downstream at fixture._from_dataset, and reverted rather than landed as a half-repair that weakens a guard without enabling the read.

The carrier identity digest is over-broad

The same digest explains the carrier rebuild, and shows the certified cache was already unreachable before this node changed anything. fixture.builder_revision() hashes Path(__file__) — the fixture module itself — together with coupling_build, and folds the result into every carrier and exterior identity. Its docstring says it digests "the coupling-assembly sources that define a carrier". Measured per revision, by hashing the two files as that function does:

Two consequences. The certified carriers already carried a different identity at this node's base than at the revision that wrote them, so the booking comparison was not executable against the store before this node's change either. And because the fixture module is inside the digest, deleting an integrator from measure.py renames the carrier group for every rung — the fixture's own edits invalidate the carrier cache. The digest should cover the assembly source it is documented to cover, not every byte of the module that calls it.
