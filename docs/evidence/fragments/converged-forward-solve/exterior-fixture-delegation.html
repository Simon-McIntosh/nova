What the overlay does and does not isolate. The comparison is clean in one direction and it contradicts the ruling's premise. Because the variant symlinks every top-level entry and copies only scripts, overwriting one file, the base arm differs from the head arm in measure.py and nothing else: same nova/, same scripts/prototypes/support/, same tests/, same benchmarks/. The part-in-103 movement is therefore produced by this node's own edit, not by base-tree work, and no commit sitting between the record and this base moved these rows. The coordinator's reading was that a near-edge kernel repair now in the base had shifted the record's reference; the measurement says otherwise, and it says why. The repair landed in nova/biot/polygonanalytic.py, which the deleted fixture-local integrator never called, so it could not have reached these rows — while the head's routed path does call it. What moved is the fixture crossing from its own quadrature onto the shared kernel.

Both arms build the machine and the exterior through the same support module and the same identity machinery, so carrier provenance is not a second variable here: the machine identity carries builder_revision e1987f9d1833a86f in the base arm, the value the fixture computes at f68870f99, and 12d9a73b56af0fb7 at head — which is the fixture's own digest moving because this node edited the fixture, not the store being read differently.

The movement is confined to the exact arm's moment path, and one row says so independently. The 550 legacy control, which does not traverse that path, reproduces between base and head to 1.8e-14 on the map and 3.1e-14 on booking; and the head tree with the arm forced to legacy reads booking 0.008968389255064343 and closure 0.017694131251761665 at 2000, equal to the record's own control values at the precision the record carries.

The direction of the closure term is worth recording, though this measurement does not settle which rule is right. The head's closure is roundoff, 2.43e-15, where the base's is 1.09e-05 at 2000 and 4.35e-06 at 5000; the closure asks how well the booked image reproduces the exterior's own image, and the booking side runs through the shipped kernel. A base fixture resolving 1e-5 against that kernel is the fixture disagreeing with the shipped code, so the head's numbers are the self-consistent ones. The local CPU equivalence experiment in the section above does not contradict this, but it does not cover it either: those rings were convex, non-convex, holed and overlapping, with no near-edge cells, and the two rules agree there to 7.5e-16. The fixture's own cells are where they part, by a part in 103 — so the equivalence claim holds off the near-edge regime and stops at its boundary. Establishing which quadrature is correct on near-edge cells is a separate question, and it is not this node's.

Two limits on what this run establishes. It compares the two arms at 550, 2000 and 5000 only, and it does not separate the fixture's own near-edge cells from its interior ones, so the mechanism above is inferred from where the difference sits rather than measured per cell. And the booking rows the ruling also asked for are only partly in — but what landed strengthens the account rather than merely truncating it. The shard built head limited 550 (booking 16314773.310234185 against analytic 16314773.310234187, net relative error 1.1e-16, read image error 1.78e-05) and head limited 2000 (booking 16314773.310234271, net relative error 0.0, read image error 2.67e-06), both EXIT=0, and then head diverted 550 failed the module's own reference check.

The certified booking rows cannot be re-read

Done-when (3) also asks that the current.book rows equal those recorded at 06cc5abe1, read from the certified cache of r-20261009T181553786165-proto-support. That read is refused by an identity guard, for a reason independent of this node's change; the coordinator then ruled that rehydrating the certified store is not required, and that the book rows are to be built fresh at base and at head and compared with each other. Job 1283976 does that through a driver that builds machine and exterior through the fixture's writable miss path, writes the receipt book.measure expects beside them, and calls it; no certified store is read. The reason the read is refused is kept here because it explains why the certified rows cannot serve as a reference at all.

scripts/prototypes/support/book.py rehydrates a recorded carrier through fixture._from_dataset, which requires the store's recorded semantic_identity attribute to equal a freshly recomputed identity (measure.py:716-722). The certified stores record a superseded schema. Read directly from analytic_oracle_clipped_exterior.zarr, group ac098ff84d3cab83:

{"schema": "analytic-oracle-clipped-exterior",

There is no builder_revision key and no closed_form_constants block, so fixture.cache_identity emits a different shape today and the equality cannot hold at any revision at or after the schema change. All six booking rows failed this way in job 1283901's book.log, at book.py:55, before any measurement ran. A repaired read path — trust the receipt's recorded group, and corroborate it by requiring the exterior's recorded machine_semantic_key to equal the receipt's machine key — was written, measured to still be refused downstream at fixture._from_dataset, and reverted rather than landed as a half-repair that weakens a guard without enabling the read.

The same digest explains the carrier rebuild, and shows the certified cache was already unreachable before this node changed anything. fixture.builder_revision() hashes Path(__file__) — the fixture module itself — together with coupling_build, and folds the result into every carrier and exterior identity. Its docstring says it digests "the coupling-assembly sources that define a carrier". Measured per revision, by hashing the two files as that function does:

Two consequences. And because the fixture module is inside the digest, deleting an integrator from measure.py renames the carrier group for every rung — the fixture's own edits invalidate the carrier cache. What remains

  • The near-edge cells the two quadratures disagree on. The rule-equivalence measurement behind the deletion used synthetic convex, non-convex and holed rings, and the two rules agree there to 7.5e-16. They do not agree on the fixture's own cells: no difference at 550, a part in 103 at 2000 and 5000, which is the signature of near-edge cells rather than of a global rule change. Naming those cells — which of the fixture's clipped or sliver polygons, and how many — is the measurement that would turn the mechanism above from inferred into established. Which rule is right on them is a separate question and not this node's.
  • What the identity clause should compare against. The recorded f68870f99 rows are reproduced exactly by the fixture code this node deleted, so they cannot be the reference for a fixture that no longer contains it, and head against base is a comparison the change is definitionally outside of. Either the clause is rewritten to compare head against the shipped kernel's own moments — the natural reference once the fixture shares that kernel — or it is dropped in favour of the closure's own value, which is now roundoff.
  • The book comparison is incomplete, and its first diverted rung failed a pinned reference. The rows are in book_fresh.log, attributed by the driver's # book label kind cells markers, because book.measure prints an unlabelled BOOKING_ROW. Two rows landed (head limited 550 and head limited 2000); head diverted 550 then tripped the module's own guard at book.py legacy_map against the pinned 0.197327, and no base-side row exists, so nothing was compared. Resubmit the ladder from the side that is missing — and treat the pinned constant as the open question, not the tolerance: it is a recorded reference value, and it must not be repinned to agree with the code under test.
  • Plan-owned, per the coordinator ruling: how the certified proto-support carriers are to be re-read, and scoping builder_revision to the coupling-assembly source it documents, since it currently hashes measure.py's own bytes and so invalidates every carrier on any fixture edit.
