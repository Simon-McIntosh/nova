machine-artifact-gpfs — machine bundles publish on GPFS

Machine-artifact publication now uses the content store's probing default. nova/imas/machine_artifact.py:materialize_machine_artifact no longer passes rename_factory=_linux_rename_no_replace. It passes the factory the store's probe selects for the cache root (_publication_rename_factory): renameat2 RENAME_NOREPLACE where the filesystem admits it, plain renameat where it does not. The re-export of the no-clobber primitive at the old line 35 is removed. A machine bundle now publishes into a directory on GPFS and resolves there.

Change

The publication path inside the store is unchanged and was not edited: publish_files still writes the pending directory, fsyncs it, renames it into place and verifies the destination. Only the caller changed, and it changed to the store's own selection, so no second probe or rename strategy exists outside nova/database/content_store.py. The factory is computed at the call site rather than left to the store's internal default, and that ordering is load bearing: the store probes the cache root after the pending directory exists, so a root swapped during publication would be refused by the probe's own pin rather than by the pinned-root guard that swap must trip. Selecting up front probes the real root and leaves test_object_root_path_swap_cannot_redirect_materialization exercising the guard it names.

test_gpfs_machine_artifact_publishes_and_resolves materializes a manifest into a fresh cache directory on the GPFS home and resolves it back: the stored and resolved digests both match the manifest digest, the manifest marker is present, and the object root holds exactly one entry, the digest. The test asserts the root does not admit no-clobber rename and skips otherwise, so it cannot pass by exercising the supported branch; on this host it ran (9 passed in the module against 8 at base, so it was collected and green, not skipped).

Negative control

The declared mutation is the pre-change behaviour restored: forcing the explicit no-clobber rename (rename_factory=_linux_rename_no_replace) in materialize_machine_artifact. Applied in a scratch tree and run against the GPFS test, it reproduces the publish failure at the probe-free path — ContentStoreError: the cache filesystem does not support atomic no-clobber directory rename, re-raised as MachineArtifactError — giving 1 failed in 9.32s, EXIT=1, with the failing id test_gpfs_machine_artifact_publishes_and_resolves, which the after arm does not fail. The mutation was reverted and the delivered tree carries the probing selection.
