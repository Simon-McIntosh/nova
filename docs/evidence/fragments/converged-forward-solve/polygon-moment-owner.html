Consolidated polygon-moment reduction

Each candidate reduction was measured against the exact rational signed-fan monomial integral of the same doubled coordinates (fractions.Fraction), cross-checked against mpmath at 50 digits (agreement 0.0). The corpus is 600 polygons: 120 convex, 120 concave, 80 sliver triangles below 1e-8 m², 80 near-collinear quads, 80 hex cells and 60 hole-fragment rings. Errors are reported per candidate and per monomial degree. max_rel is over the whole corpus, max_rel_trim drops the single worst cell of each degree so one pathological sliver cannot decide the ranking, and max_abs is the true error magnitude.

Every surviving reduction routes through the owner

The names above survive because their callers live outside this node's write fence, but the reductions they named do not. In commit 32d463cf7 polygon_moments.polygon_monomial_moments returns the owner table directly and its Green-theorem edge-weight machinery (_edge_weights, _residual_exponents, the binomial and exponent tables, 129 source lines) is deleted; polygon_density_moments contracts the density against that same table. padded_polynomial_current_moments reads the owner table at the degree its complete basis requires. Commit 90bb6f21e holds the claim: each surviving reduction on the traced path is required to reach the owner in its own source, and the numpy area view is required to reproduce the exact rational area, first and second moments.

Two reductions are deliberately kept, each for a measured reason. stencil_mesh._polygon_monomial_integral is the independent signed-fan oracle that scripts/clip_independent_representation/score_candidates.py compares the production reductions against, so making it call the owner would make that comparison the owner agreeing with itself. separatrix_clip._area_moments was delegated and then reverted in 4523dc2f3: AtomicCellMesh.clip calls it once per mesh cell inside a Python loop, and an eager traced call per cell turned that loop into a compile-and-dispatch per cell. Its absolute error, 6.661e-16, is the smallest of any candidate, and it returns the same total-degree-two block of the same monomial integrals.

The wall of test_moving_separatrix_padded_contraction_traces_once, the single test that exercises that loop, measured one process at a time on a dedicated all_debug node: 152.72 s with the delegated view and 5.97 s with the numpy closed form — a factor of 26. The delegation was first seen as a pytest Timeout at the 300 s default, because that gate ran three heavy pytest processes against eight cores; the same 152 s of per-cell dispatch crosses 300 s under that contention. So the reverted commit removes a 26-fold wall inflation, and the control that measures it is the pair of walls above. The control specified for this repair — reverting 4523dc2f3 in an exported copy and requiring the test to fail or time out by id — was run and did not reproduce: on a dedicated node the reverted tree passes that test in 152.72 s, well inside the timeout, so the delegation degrades the wall rather than breaking the test. Logs: negative_control_revert.log (reverted tree, armed and verified delegated: 1 passed in 152.72 s), cert_head2.log (head tree, same test: 1 passed in 5.97 s).

Booked-current certificate rows

The read-driven certificate rows named in clause (4) are tests/test_read_ten_thousand_cells.py, parametrised over 550, 2000 and 5000 cells for both the limited and the diverted topology. Each carries a committed CPU golden whose comparison is exactly atol=1e-13 on membership, axis, X-point validity, X-point position and boundary flux.

The rows must be read from the tree under test, and until this pass they were not. python -m pytest puts the working directory at the head of sys.path ahead of PYTHONPATH, and the shared environment at ~/Code/nova/.venv carries an editable install pointing at the main checkout, so a run launched from the worktree without PYTHONPATH imports the main checkout's nova. The two arms recorded earlier (8 passed, 576 s and 578 s) did exactly that: they measured the main checkout, which is why they agreed with the committed goldens. Each arm is now run with its own tree as its working directory, and the -m free python of the shared environment as the interpreter.

The six golden comparisons fail on both arms, by a maximum absolute difference of 6.15e-12, and that is a property of the base tree rather than of this node's change: the committed CPU snapshots pin the arithmetic of the main checkout at its current revision, and the node's base c054a721f differs from it at the twelfth digit. The earlier arms passed because they were the main checkout; the base arm fails identically, which is what shows the reroute is not the cause.

Why the reroute cannot move the booked current at all: topology.read books each cell's area from the atomised mesh's own shoelace sum (nova/equilibrium/topology.py:2414), not from the polygon-moment reductions. The rows are a guard that the reroute leaves the read path untouched, not a measurement of the reduction — the reduction's own accuracy is the census table above, anchored at tests/test_exact_clip_moments.py. The golden check does bite when the booked quantity itself moves: perturbing limited-550-cpu.npz's membership by 1e-9 turns test_closed_form_read_is_accurate_and_compatible[550-limited] red at the 1e-13 assertion.
