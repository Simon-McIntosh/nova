Refuse a reference flux span the guard cannot decide

The reference sign guard in scripts/prototypes/efit_field_swap/orientation.py treated a span whose magnitude lay within its tolerance of zero as agreement, so a slice whose grid fixed no flux extremum was neither refused nor flagged and a caller could not distinguish "checked and agreed" from "could not tell". The check now separates three outcomes: agrees, contradicts and undecidable. An undecidable span raises UndecidableSignError (a subclass of ReferenceSignError, so existing catches still refuse) naming the slice, the declaration, the span and the tolerance it failed to clear. A contradiction is reported first when both hold. Every caller refuses on undecidable: the TCV comparison measure.measure_slice and the two trace read sites crosscheck._decision and probe_read.probe_record propagate the error before constructing a field or reaching the topology read.

The tolerance is stated in the code with its basis. _SIGN_TOLERANCE = 1024 * eps is a thousand-fold margin over the double-precision unit roundoff, applied to the flux magnitude the compared spline samples carry (the tolerance is relative, never an absolute psi value, so the gauge cannot move it). The curvature fallback names its own floor, _CURVATURE_TOLERANCE = 1e-9 on the axis Hessian eigenvalues, the same way.

The TCV driver now reads every distinct psi-grid block of the 1703-slice LIUQE store, not a hand-chosen twelve. A block scan finds seventeen distinct grids, so five slices that had never been guarded now are. Outcome: LIUQE_ROWS 17 REFUSED 17 AGREES 0 CONTRADICTS 17 UNDECIDABLE 0 - all seventeen contradict (declared DD 3.41.0 COCOS 11 with negative Ip requires a psi maximum; scalars agree, grid does not), each reported with its scalar and grid spans. No slice is undecidable.
