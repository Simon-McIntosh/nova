The default lane collects a heavy forward test

Base revision 6cce876e3. The two slow forward test files were re-run to satisfy the plan's caller-test clauses. The first finding is not a timeout but a lane-hygiene defect, and it is reproducible in seconds.

The default lane is path-free pytest, whose configuration in pyproject.toml is -m 'not slow' with timeout = 300. A collection-only run of the two files under that marker filter reports 1 collected, 3 deselected: the single test of tests/test_forward_receipt_raster.py is collected (it carries no marker), while all three tests of tests/test_forward_compile_identity.py are deselected because each carries @pytest.mark.slow.

command: pytest tests/test_forward_receipt_raster.py \
    tests/test_forward_compile_identity.py -m 'not slow' --collect-only -q
result:  1/4 tests collected (3 deselected)

So the raster test runs inside the fast lane, where it cannot finish: it builds an oracle machine and runs a full production request-seam solve. The compile-identity file is already excluded from the fast lane and needs no marker change.

The per-test timeout does not bound the native solve

A default-lane run of the base raster file on the host CPU with the repository's own bound (--timeout 300, signal method) was still executing past 420 s wall with no failing mark and no summary. The bound does not cut this test: pytest-timeout's signal method can only run its handler when the interpreter regains control, and the test spends its wall inside the native (XLA) compile and solve. A per-test timeout is therefore not a bound for this class of test; only the SLURM job wall stops it. This is the mechanism behind the earlier "no summary in 90 minutes" H200 result.

Change: the raster test is marked slow with its reason

tests/test_forward_receipt_raster.py gains @pytest.mark.slow on its single test, with a comment naming the mechanism (the case builds an oracle machine and runs a full production request-seam solve past the default lane's bound). No assertion was deleted and no tolerance was loosened; the receipt assertions are unchanged. After the change the default-lane collection of the file reports no tests collected (1 deselected), so the fast lane no longer carries the heavy solve.
