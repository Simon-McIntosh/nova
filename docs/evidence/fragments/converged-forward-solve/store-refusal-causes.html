store-refusal-causes — a present invalid entry is refused by name

The store now separates "absent" from "present but invalid". nova/database/content_store.py:verified_destination returned a single None for three states, so a caller could not tell a cold cache from a broken entry. It now returns None only for an entry that is absent, and refuses a present entry whose completion marker is missing, is a symlink, or is otherwise not a regular file, naming that cause. Both tests/test_mast_artifact.py failures on main (test_existing_empty_destination_is_not_overwritten and test_resolver_rejects_symlinked_manifest) now pass.

The three states, before and after

The refusal behaviour was already correct — both cases refused and neither overwrote the empty destination. Only the message was wrong, because the state was collapsed before any caller saw it. The reproduction, quoted from the base arm: Actual message: 'cache object sha256:5ffc1dc… is missing under …/cache/sha256' for the symlinked manifest against the expected manifest.*symlink, and cache object sha256:… is missing after publication for the empty destination against the expected manifest is missing.

One place decides this: verified_destination, on the path every caller shares. The duplicate marker check inside publish_files is removed, and resolve_machine_artifact drops its own restatement of the missing-marker and symlinked-marker refusals, so the artifact caller now surfaces the store's error rather than composing a second wording for the same fact. _lifted still re-raises it as MachineArtifactError, so artifact callers keep catching one vocabulary.
