Classify the red topology read tests by cause

Measure. Sixteen node ids of tests/equilibrium/test_topology_read.py × three revisions = 48 runs, one fresh process each, per-test timeout disabled, on one allocation with nothing else in it (job 1290186, --partition=sirius, 12 CPUs, 96 GB, four hours). Revisions: base 6cce876e3, contour-tree-mesh merge 5d40e0155, main 32cb743e97. The per-test timeout is disabled, so a timeout is always the shortfall measured against a bound (pyproject.toml timeout = 300), never an accident of the harness.

Of the 48 runs, 30 pass, 9 are setup errors and 9 fail. The 9 failures are 3 GPU-gated ids × 3 revisions. The 9 setup errors are 3 ids × 3 revisions, all from one module-scoped fixture bound.

The three causes

Device gate. test_kernel_compile_growth[132|300|550] asserts jax.default_backend() == "gpu" inside its own measurement child, so on a CPU partition the child exits 1 before compiling anything and the test fails on assert code == 0, f"kernel compile {arm} refused: {log}" in 10.6–19 s, identically at all three revisions. On the H200 (job 1290213) the same three ids xfail green at 706–726 s, which is the declared KernelCompileBarrier outcome — the read's cold compile exceeds its own 60 s / 50 MB qualification clause. The test is red on the CPU lane by construction, not by regression.

Shared compile barrier. The seven ids drawing kernel_compile_budget — test_biot_moment_point_derivatives, test_kernel_backed_carrier_read (4 parameterisations) and test_null_position_implicit_tangent (2) — all carry @kernel_compile_expected_failure, a strict xfail that admits only KernelCompileBarrier. That fixture compiles the 132-cell Biot harmonic kernel in a child under process.wait(timeout=600), and the child does not finish inside it at any revision: the evidence log reaches KERNEL_COMPILE_INPUT_READY and then stops. Where the fixture's own terminate produces EXIT=-15, the declared barrier is raised and the test xfails green (measured at 5d40e0155). Where the child is killed outright (EXIT=-9) the fixture raises RuntimeError: kernel prerequisite exited -9, which the strict xfail does not admit, so the id goes red.

Bound below the read's cost. Against the configured 300 s bound, test_topology_class_and_membership[diverted] (359/386/371 s) and test_saddle_support_order[diverted] (419/383/385 s) exceed the bound at all three revisions. These are also the two ids the base revision already recorded as failing, so no merge introduced them.

What does not reproduce

The three additional head failures in the brief — test_closed_form_resolution_probe[diverted], test_topology_class_and_membership[limited] and test_saddle_support_order[limited] — pass at every revision once the bound is lifted, at 153–156 s, 126–130 s and 128–132 s. The gate that recorded them (contour-mesh-capacity/verify-gate.log, 2026-10-19T13:57Z) ran them from the login node, cwd=/home/ITER/mcintos/Code/nova, serially, with pytest-timeout active, and all three died at exactly Failed: Timeout (>300.0s). The same work on a compute node takes a little over 40% of the bound, so the difference is the lane, not the code.

The root tangent changed nothing. The nova/equilibrium/fixed_points.py root tangent (merge 100bc5828) lies between the two later revisions measured here and is an ancestor of main, so its content is exercised by the main arm. No id changes verdict across 5d40e0155 → main except the biot id's setup error form (declared barrier vs SIGKILL), which is set by the host killing the compile, not by the read. Every wall that moves between the two revisions moves in both directions across similar ids and within the same-revision spread — 126→130, 386→371, 128→132, 383→385, 213→286, 623→617 — so no wall is attributable to the tangent.
