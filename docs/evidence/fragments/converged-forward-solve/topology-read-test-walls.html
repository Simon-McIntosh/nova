Classify the red topology read tests by cause

Measure. Sixteen node ids of tests/equilibrium/test_topology_read.py at three revisions — base 6cce876e3, the contour-tree-mesh merge 5d40e0155 and main 32cb743e97 — one fresh process per id, per-test timeout disabled, on one allocation with nothing else in it (job 1290186, --partition=sirius, 12 CPUs, 96 GB, four hours). Any timeout in this set therefore measures a shortfall against the 300 s bound, never an artefact of the harness.

The three causes

A device gate. test_kernel_compile_growth[132|300|550] asserts jax.default_backend() == "gpu" inside its own measurement child, so on a CPU partition the child exits 1 before compiling anything and the test fails on assert code == 0 in 10.6–19 s, identically at all three revisions. On the H200 (job 1290213) the same three ids xfail green in 686–726 s, which is the declared KernelCompileBarrier — the cold read compile exceeds its own 60 s / 50 MB qualification clause, exactly as that test's xfail reason says. Red on the CPU lane by construction.

A compile child killed by its allocation. The seven ids drawing kernel_compile_budget all carry a strict xfail that admits only KernelCompileBarrier. Their shared child compiles the 132-cell Biot harmonic kernel and never finishes inside the fixture's 600 s bound, at any revision — the condition the xfail declares. On a node that can the compile, the id is green: job 1290248 ran test_biot_moment_point_derivatives alone with 450 GB and it xfailed in 615 s, and the same id xfails at base (614 s) and at the contour merge (626 s). Where the allocation takes the child away first the child ends EXIT=-9 instead of the fixture's own EXIT=-15, the fixture raises RuntimeError: kernel prerequisite exited -9, and a strict xfail that admits only the barrier reports an error. That is what all 21 fixture rows did in the first job, at every revision, under six concurrent native compiles in 96 GB; the two-id job under 250 GB reproduced it and then ended OUT_OF_MEMORY.

A bound below the read's cost. test_topology_class_and_membership[diverted] (359/386/371 s) and test_saddle_support_order[diverted] (419/383/385 s) exceed the 300 s bound at all three revisions. Both are already in the base revision's failing list, so no merge introduced them.

What does not reproduce

The three additional head failures in the brief — test_closed_form_resolution_probe[diverted], test_topology_class_and_membership[limited] and test_saddle_support_order[limited] — pass at every revision once the bound is lifted, at 153–156 s, 126–130 s and 128–132 s. The gate that recorded them (contour-mesh-capacity/verify-gate.log, 2026-10-19T13:57Z) ran them from the login node, cwd=/home/ITER/mcintos/Code/nova, serially, with pytest-timeout active, and all three died at exactly Failed: Timeout (>300.0s). The same work takes a little over 40% of the bound on a compute node, so the difference is the read's lane, not the read's code.

The root tangent changed nothing. The nova/equilibrium/fixed_points.py root tangent (merge 100bc5828) lies between the two later revisions measured here and is an ancestor of main, so the main arm exercises its content throughout. No id changes verdict between 5d40e0155 and main, and the walls that move do so in both directions and within the spread one revision shows across ids — 126→130, 386→371, 128→132, 383→385. The one apparent exception dissolves on inspection — see the biot control above: the same id that errored in the two-id job xfails green in the one-id job at the same revision. Over the same interval only three nova sources changed: nova/equilibrium/fixed_points.py (+34), nova/biot/tiledassembly.py (+6) and nova/jax/config.py (+9), and the latter two touch only the persistent compilation cache, which every measurement here disables.
