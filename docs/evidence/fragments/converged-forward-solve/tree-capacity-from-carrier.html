Contour-tree capacities derived from the carrier

The receipt's node and edge capacities are the carrier's own vertex and edge slot counts, and the neighbour table's width is the carrier's own degree. At the base revision 7430c618f657a0a169c9fa04135654514e2298c6 the 10,000-cell limited read refused with valid=False and the receipt's overflow true; at head the same read is valid=True, reason=0 and qualified=True. The seven receipt fields keep the build's own arithmetic; the fixture comparison that pins them is red at both revisions for an unrelated carrier-size refusal in its data, recorded below.

Rule, in nova/equilibrium/contour_tree.py. carrier_node_capacity(declared, vertex_slots) returns the carrier's vertex slot count when nothing is declared and the declaration otherwise, and carrier_edge_capacity does the same over the carrier's edge slots. build_contour_tree takes both as static parameters and reports a declaration below what the carrier produces through overflow rather than truncating the tree. The adapter's own comment is bootstrapped from the carrier's slot count, never from a value the tree computes, because the receipt's rows are carrier-vertex slots: node_valid.at[vertex].set(...) drops an out-of-range write silently, so a node capacity below the carrier's vertex count loses critical points without refusing. Those two capacities therefore cannot be tighter than the carrier's own slot counts without changing what a row means.

Neighbour width, which is where the cost was. The neighbour table is (vertex_count, width) and each visit compares every pair of a vertex's neighbours against it, so the width enters the build twice. A caller that declares nothing now takes the carrier's own maximum live degree, counted host-side by measured_degree_capacity; a carrier that exists only as a traced shape cannot be counted and falls back to its edge count, which no graph can exceed. A declared width below the degree still refuses. The production read was never exposed to this: topology.read has always passed the mesh's measured degree as static metadata.

The cost, measured. At base both sweeps were already called with mesh_node_capacity and mesh_edge_capacity — the carrier's slot counts — and the 10,000-cell sweep-bounds file took 112.63 s. The neighbour default alone was fixed at min(edge_count, 32). At head, with the edge count as the width, it became 31,225 against the profile carrier's degree of 10, and test_largest_profile_fixture_bounds_root_hops alone was still executing after twenty minutes thirty-five seconds of wall clock at 791-818 % CPU (pid 5118), against 112.63 s for the whole file at base. With the degree counted host-side, the three capacity tests plus that same profile test complete in 116.67 s for four tests, inside the base file's own 112.63 s; the overflow probe's three tests take 29.64 s.

The overflow probe refuses on a constructed carrier. scripts/prototypes/contour_tree_overflow/test_overflow.py still reads its MAST-U carrier through probe.mastu_inputs and keeps it the owner of those inputs, but the refusal is now asserted on a fan whose hub degree is a property of the construction: one hub joined to twenty-four leaves, refused at a declared width of sixteen and fitted at its measured twenty-four. The MAST-U degrees are recorded as data in MASTU_MEASURED_DEGREES — 9, 11 and 12 at resolutions 16, 24 and 32 — and asserted against what the theory is the assumption. The refusal record measured 19, 22 and 18 on the pre-repair carrier; the wall-coverage repair re-cut it, so the fixed width of 16 no longer sits below the degree and a test written around that width could only pass by not being about the carrier.
