How the counter now attributes a barrier to its marker

_marker_barrier_count(marked_function, unmarked_count, *arguments) lowers the program twice and returns the difference. The unmarked arm is lowered with the guard's marker not installed, and its barrier count is passed in; the marked arm is lowered with the marker installed. Only barriers the marker adds survive the subtraction, so the fence contributes to both arms and cancels.

The two arms must be lowered through distinct callables. jax.jit caches a lowering on the callable it traces, so re-lowering the same function object after a monkeypatch returns the first program and the difference reads zero. Measured on this allocation: the plain solve lowers to 2 barriers; the same function object lowered after the marker is installed still reads 2, while the same body passed as a lambda or a partial reads 3. Both guards therefore lower each arm through its own functools.partial, and the Newton guard's solve is lifted to the module-level _newton_solve so both of its arms are partials of the same helper.

The assertion intent is unchanged. A count of one still means the trip body is lowered exactly once; a doubled body now counts two, which the negative control shows.
