Cell-batched current booking

Followup f-cfs-vectorize-booking. nova.equilibrium.current.book booked cells in a sequential jax.lax.scan with unroll=1, the bottleneck of the hot path (0.9, 2.8 and 8.1 s per step at 2,000, 5,000 and 10,000 cells on the H200). The loop is now a single jax.vmap over the cell index; the per-cell body — fragment rings, membership and normal-form conditioning, and the clipped support quadrature — is unchanged. One compiled program remains, with effects batched over cells, so the booking no longer serialises across cells. The work is committed at adeff8346 (product) and 486d369ad (test).

Identity against the sequential reference

The test file tests/test_current_book_vectorised.py holds the pre-batching booking verbatim as _reference_book, and its own copies of _conic_rings and _normal_rings as _reference_conic_rings and _reference_normal_rings, so the oracle is independent of the product's ring builders and not only of its iteration. Negative control

Declared mutation: a padded fragment counted twice turns the vectorised identity test red by test id. Applied to _conic_rings in the product (the mutation doubles the ring batch and its live counts), the identity test fails at all three rungs and the run exits non-zero; the log is logs/negative-control.log. The control proves the test is sensitive to padding, which the first, dead slice's duplicate did not exercise — hence the whole-batch double.

Autograd

tests/test_current_book_fragments.py::test_booking_jvp_matches_central_difference runs jax.jvp of the booked moments through the vectorised book against central finite differences on the smooth, axis, boundary and support stages, and passes. This is the precondition for the moment-space Newton.

Caveat and follow-on

The H200 rung cost (item 3 of the done-when) and the 2,000 / 5,000 / 10,000-cell identity rungs (item 2) were not measured within the 60-minute node budget. The harness for them exists: scripts/prototypes/support/book.py::measure already times the traced-book stage and requires the GPU lane; running measure for each rung on the base tree and on this head tree gives the before/after wall and compile seconds. The certified 2,000 and 5,000-cell machines are cached; a 10,000-cell machine must be built with build_machine. This measurement is left to a follow-on node.
