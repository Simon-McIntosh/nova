Why the free vertical-pin request moves its booked height

Determination. At HEAD (9beab06a4) the free request does not move its booked height: the terminal flux is bit-identical to the seed and the booked height is exactly 0.6. The recorded 3.86e-3 offset does not reproduce at HEAD, nor at the recorded base revision a711e2b0 with the recorded command, nor under a one-core or four-core host configuration. The test test_one_augmented_newton_program_servers_free_and_pinned_requests passes, both alone and as part of its file. Neither party named by the brief is wrong at HEAD: the solver holds the unknown the free layout should hold, and the test's expectation is the correct physical expectation for this seed.

Mechanism and measured value

The inactive CurrentCentroidConstraint row returns the normalised radial-field unknown itself (nova/equilibrium/constraint.py, residual), so compensator_step applies step = -row = -unknown and drives the held unknown to zero. The carrier's forced sixth row is the pure constant VERTICAL_FORCING / ELONGATION² = 0.0308641975, whose gradient in the flux is exactly zero, so the least-squares/Krylov Newton increment on the five satisfiable rows is exactly zero; the seed already satisfies those five rows, so it is retained unchanged as the terminal iterate.

The recorded offset

The recorded failure (r-20261019T042319449201, baseline_suite.log) shows the terminal flux [1.0, 0.8, 0.24, 1.0, 1.2, 0.95228395]. That value is exactly 0.96 - 0.25 · (VERTICAL_FORCING / ELONGATION²), i.e. the held radial-field unknown had settled at -0.25 · row₆ instead of 0 — precisely the defect the brief names, "a solver that moves an unknown the free layout should hold". That state does not occur at HEAD or at a711e2b0: the only source differences between the two are in nova/biot/tiledassembly.py, nova/equilibrium/contour_tree_mesh.py, nova/equilibrium/fixed_points.py, nova/equilibrium/topology.py and nova/jax/config.py (the XLA per-fusion autotune cache switch), none of which is imported by this test's route.

Negative control

The declared mutation — "revert the fix" — has no fix to revert, because the free-request height assertion already passes unchanged at both revisions. The closest applicable mutation is applied instead, at runtime from a pytest plugin, so no repository file is written and none needs restoring: the inactive centroid row is made to take the held branch.

Under that mutation the free request no longer stalls — it converges (residual 1.887e-15, terminal flux [1.0, 0.8, -0.36, 1.0, 1.2, 0.36]) — so the mutation is caught one assertion earlier, at line 357's stall floor (assert not bool(converged)), before the height assertion is reached. The booked height under the same mutation, read directly from the diagnostic probe, moves from 0.6 to 0.7 (offset 0.1). The mutation therefore fails three of the file's six tests, and test_one_augmented_newton_program_serves_free_and_pinned_requests is one of them — an id the passing head arm does not fail — so the free-layout assertions are sensitive to the held row and are not vacuous.

The offset under the applied mutation (0.1) is not the recorded 3.86e-3, and that mismatch is itself the finding: the mutation the brief declared describes a defect that is not present at HEAD. The recorded 3.86e-3 would require the held unknown to settle at -0.25 · row₆ while still stalling, and no revision reachable here does that.
