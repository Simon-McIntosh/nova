Vertical pin on the converged forward solve

An elongated equilibrium is degenerate vertically: the plasma centre can translate in height with almost no change in the diagnostic-magnitude residual, so a converged forward solve of an elongated state has no reason to sit at any particular height. The pin gives the solve one compensating unknown — the current in a declared vertical-field coil set, or the amplitude of a declared uniform radial field where the machine names no such set — and one extra residual row that holds the current-centroid height at a commanded target. Both the target and the unknown enter the map as runtime operands, so the compiled program is identical whether the solve is pinned or unpinned and whatever the target value.

Mechanism

The pin lives in the generic chord-Newton fixed-point solver (nova/equilibrium/solve.py), which owns no physics: it drives a pure map residual_fn(state, operands) to a tolerance. A pin extends the state by one element, the compensating unknown, and augments the map by one row (observation(extended, operands) - target) / pin_scale. The base map reads the unknown off the state's last element and adds its declared field through the runtime operands, so the traced program never captures the field shape, the target, the scale or the seed. VerticalPin carries target, scale and seed as runtime leaves; pin_residual builds the augmented map, pin_state extends the state, and pinned_fixed_point drives it. The centroid-z definition is the existing booked-support moment: the observation is the same current-centroid quantity CurrentCentroidConstraint uses, here read directly as the carrier's height coordinate.

Negative control

The declared control removes the compensating unknown's leverage by holding the vertical-field source fixed (FIELD_LEVERAGE = 0.0). The pin row then has no gradient in the unknown, the augmented Jacobian is singular, and the corrected state goes to nan. The control log (vertical-pin/negative-control.log) ends with EXIT=1 and names two failing ids: test_pinned_solve_holds_the_target_height_at_two_targets and test_one_compiled_program_serves_every_target. Restoring the leverage returns the focused gate to green.

What remains

The pin mechanism and its gate land on the generic solve. Two done-when items are not closed. The pin is not yet wired through the forward-solve seam (nova/equilibrium/forward.py, solve_request.py, constraint.py): no ForwardSolveRequest field carries a pin, and no production route builds a ConstraintPair whose unknown is the pin. And the 550-cell lobe carrier cold solve that stalls at 1.54987e-3 has not been re-run with the pin, so whether the stall clears is unmeasured. The elongation and flux-panel done-when items were demonstrated on the analytic carrier rather than on the production lobe geometry.

All three suite-wide and production items are recorded as follow-ons in the node manifest.
