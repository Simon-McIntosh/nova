Cached store keyed on the convention of its fields

landing: SignalStore.cache_key now carries the COCOS convention of the stored fields through hash_attrs/canonical_key, so a store group is keyed on its source identity and the convention its fields are in rather than on the identity alone. The store derives the convention from the DD version it was read at (DD3 → COCOS 11, DD4 → COCOS 17) through the one owner, IdsIngest drops its fixed cocos: int = 11 default and writes the convention the DD version carries, and a group written under the pre-convention key — which declares no convention at all — is refused by name on read() rather than served. A two-store test writes a DD3 and a DD4 store and shows two distinct keys and each store's declared convention; an old-entry test writes a group under the legacy key and asserts the refusal.

The recorded defect, reproduced at the base before the change. The census (dd-cocos-census, its writers and caches rows) records both halves. At base e69f4b60a the snapshot under the run directory shows them directly: nova/io/signalstore.py carries no cocos in its key (a search of that file for cocos returns nothing), and nova/io/ingest.py declares cocos: int = 11 at base. So a store written from a DD4 source at the default declared COCOS 11 whatever its DD version, and the convention travelled as a dataset attribute that was never a key input. Both halves are repaired here.

The key gains the convention, and IdsIngest derives it. SignalStore gains a cocos field, derived from dd_version in __post_init__ when unset, and cache_key hashes {uri, dd_version, cocos} through hash_attrs/canonical_key — the owner named by §4, used unchanged. IdsIngest drops the fixed default; tensorize reads the convention from the DD version it is handed (through nova.io.sourcemap.dd_equilibrium_convention, the one DD→COCOS owner) and writes it as the store's cocos attribute, the same convention the store keys on. The sourcemap imports this module's PROVISIONAL_NAMESPACE, so both new imports are function-local rather than module-level, to keep the import graph acyclic.

(1) Two stores of the same identity in two conventions key apart and declare their convention. tests/test_signalstore_convention_key.py constructs a DD 3.42.0 store and a DD 4.1.0 store over one source URI and asserts store.cocos is 11 and 17, that the two cache_key values differ, and that each tensorized dataset carries the matching cocos attribute. A second test varies the convention alone — the same DD version, cocos=17 against the derived 11 — and requires the keys to differ, so the key is shown to turn on the convention rather than only on the DD version that already fed the identity. A third asserts the convention-keyed group is distinct from the legacy group the pre-convention key produced. All three pass at head; the file is new, so it has no base arm.

(2) An entry written under the old key is refused, never served silently. The old key hashed the identity alone. SignalStore.read asks stale_group() first: when the convention-keyed group is absent while the identity-only group is present, the stored fields' convention is unknown, so it raises StaleConventionError naming the stale group, the URI, the DD version, the expected COCOS and the missing keyed group. The old-entry test writes a dataset under legacy_cache_key, then asserts the refusal on a fresh store, then re-ingests and shows the convention-keyed group is written and served. The refusal is by name and the stale group is never returned as data.
