Why the inverse negation goes rather than stays

The value was coupled, not internal: tests/test_pulsedesign.py::test_ids_file_cache shows psi_boundary tracking an input IDS field, so it arrives in the source read's convention. Under DD3 that is COCOS 11, whose psi is the negative of COCOS 17's, so -psi_11 was exactly the internal COCOS 17 flux and the negation was an implicit 11 → 17 conversion. The reader now performs that conversion once, so the negation would apply it twice. For a DD3 source the value handed on is unchanged (the factor is -1); for a DD4 source the sign is corrected, which is the defect the line carried.

The reader renormalises to psi_norm, and a psi sign reversal leaves (psi - psi_axis) / (psi_boundary - psi_axis) unchanged, so no normalised quantity moves and only a signed one can show the translation at all.

The unmet condition

The measure's first clause needs a live pulse read through the reader. EquilibriumData.build ends with self.wall.insert(self.data), which reads the machine description. The machine description is present, but at the wrong Data Dictionary version, and the resolver that chooses the version is outside this node's write scope:

pathstate
what the reader asks for/work/imas/shared/imasdb/ITER_MD/4/116000/2 — absent (ls: No such file or directory at …/4/116000/)
what is installed/work/imas/shared/imasdb/ITER_MD/3/116000/2/ — present, carrying wall.h5 and ids_001.tree

So the failure is not a missing machine description and not a case-sensitivity problem (ITER_MD and the iter_md the error prints both resolve on this filesystem): the DD4 branch of the machine tree does not carry pulse 116000, and the reader resolves the machine at DD4 regardless of the DD3 version its own equilibrium data was written in. The code that picks that version is nova/imas/machine.py, which is not in this node's write scope.

The two refusal cases fail earlier still, at the read of the pulse's own tree: Invalid node name '0' in path: 0, raised while the pulse is opened at DD 3.38.1 and before build_convention is reached. The DD version this test uses for each refusal pulse is not sourced from the project's manifest of written versions: tests/data-manifest.json carries iter_corsica_130506 and iter_dina_105027 among the efitpp validator layers at DD 4.1.0, and carries none of 130506/6, 105069/3, 105014/1, 105013/1. The instruction to open these pulses at their written DD version therefore has no source in this environment, and the versions this test hardcodes are not attested anywhere the repository can check.

Both of the clauses the measure rests on are consequently unmet, and neither is repairable inside this node's write scope. This is reported as a scope breach and an evidence gap rather than worked around: choosing the machine's DD version, and sourcing the four pulses' written DD versions, each belong to another node.
