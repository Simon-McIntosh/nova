Internal and writer sign sites take their convention from the COCOS 17 owner

Base e69f4b60a. The internal convention now has one owner, and every census sign site in a writer or an internal consumer either takes its sign or factor from that owner or is named as coupled to the equilibrium reader that still passes raw Data Dictionary values through.

The owner

nova/equilibrium/convention.py states nova's internal convention once, as the value nova_cocos.convention(17) returns, and exports three names from it: CONVENTION (the four Sauter–Medvedev digits), COCOS (CONVENTION.identifier, 17) and SIGMA_BP (CONVENTION.sigma_bp, −1). Nothing else in the module restates the number, and the sign chain below it is unchanged: TOTAL_FLUX_FACTOR, the total-flux and current-density definitions and the p'/FF' sense are exactly as they were. The module docstring therefore remains true of the same algebra, now with its digits named.

Why inverse.py:245 is coupled, not internal

The census recorded this site as an internal consumer with no IDS read. The InverseDesign row extracts its ψ constraint with self["psi_boundary"], and Control is PlasmaPoints over Profile(Flux, Equilibrium, GetSlice, CoilData), so the item resolves through the sample built from the equilibrium source rather than through the levelset solve the writer reads in the table above. The evidence is the covering test: tests/test_pulsedesign.py::test_ids_file_cache sets time_slice[0].boundary_separatrix.psi = 66 on the input IDS and then reads back design_a["psi_boundary"] == 66 — the raw stored value, tracked with the input. A plasma's own solved boundary flux could not follow a change to an input IDS field. So the value this line negates is in the source read's convention, not nova's, and the negation is an implicit COCOS 11 → 17 conversion that only holds while the source is DD3. That conversion belongs at the reader, which is the node carrying f-ddc-002 for nova/imas/equilibrium.py and nova/imas/getslice.py. Coupled field: Equilibrium/EquilibriumData.psi_boundary as reached by GetSlice. The line is left byte-identical.

The COCOS 17 tests, and the values they pin

tests/test_internal_cocos_sites.py, 8 tests, 8 passed. It fixes the COCOS 17 state and checks each changed site's sign-sensitive output against the value the base produced, so a renamed-but-flipped sign is red:

  • the owner: CONVENTION.identifier == 17, CONVENTION.digits == nova_cocos.convention(17).digits, SIGMA_BP == −1, and TOTAL_FLUX_FACTOR == tau ** CONVENTION.e_bp;
  • the writer: dd_equilibrium_factor("3.42.0", PSI_LIKE) == −1.0 and dd_equilibrium_factor("4.1.0", PSI_LIKE) == +1.0, with dd_equilibrium_convention("3.42.0") == DD3_CONVENTION and dd_equilibrium_convention("4.1.0") == DD4_CONVENTION tying the version to the convention. dd_equilibrium_factor("3.42.0", PSI_LIKE) * [100, −50, 12.5] equals the base literal's -[100, −50, 12.5] element for element;
  • the display levels: both tests call the production Extrapolate.plot_2d_masked on a bare instance whose flux plot is replaced by a recorder, so the levels the site hands on are read from the site rather than re-stated beside it. One pins the value (the internal convention's sign applied to a 51-point array equals the base negation, reversed order included); the other pins the site's dependence on the owner, by monkeypatching the module's NOVA_CONVENTION to COCOS 11 and requiring the handed-on levels to come back un-negated. That second test is the one a bare negation cannot pass only because both signs agree today: SIGMA_BP is −1, so a value assertion alone cannot separate the two forms. Reverting the site to -levels[::-1] fails it, and it is the only test reverted by that change.

Changed expectations: none. Every factor is −1 for a DD3 target, so the writer, the display and the tests all carry the base's values.
