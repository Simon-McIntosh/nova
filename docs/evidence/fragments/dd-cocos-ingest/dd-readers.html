The IDS readers on the COCOS translator

The reader changes below are committed and their gates are recorded. Both heavy files have now been run at head: every test of tests/test_unseen_source_full_plant.py passes, and tests/test_coupled_plant.py passes except two tests that build a plant with no plasma source at all and fail on a cached sectioned reference, which no code path this node touched reaches. The one done-when item still unmet is stated in the last section.

PlasmaSource translates every convention-bearing quantity into COCOS 17

The one entry point is nova.io.sourcemap.translate_equilibrium. PlasmaSource.from_imas now reads the DD version from equilibrium.ids_properties.version_put.data_dictionary and, before any PlasmaSlice is built, takes that slice's ip, psi_axis, psi_boundary, q_95 and b0 through the translator. The translated SourceSignalMap is then applied quantity by quantity — profiles_2d/psi, profiles_1d/psi, dpressure_dpsi, f_df_dpsi, global_quantities/psi_axis, global_quantities/psi_boundary and global_quantities/ip — so no raw IDS value reaches a slice. A blocked map is raised by name, with the DD version, the expected COCOS and the measured digits, before the slice exists.

The factors the DD3 to COCOS 17 mapping applies are those of the algebra, not a table here: psi_like −1 and dodpsi_like −1 (COCOS 11 and COCOS 17 differ in sigma_Bp), ip_like, b0_like and q_like all +1. The profile coordinate (psi−psi_axis)/(psi_boundary−psi_axis) is therefore invariant, and with both flux functions flipping alongside the flux map, the current density, the integrated current and the boundary outline are unchanged by the translation.

The plasma-source guard stays, re-expressed as the internal COCOS 17 check

PlasmaSlice.prescribe still refuses a slice whose flux ordering contradicts the current, and it is still the only sign site in any reader. Its digit now comes from the algebra — nova_cocos.convention(NOVA_CONVENTION).sigma_bp, which is −1 — rather than from a literal, so the condition is sigma_Bp · (psi_boundary − psi_axis) · ip > 0. The refusal message keeps the substring psi ordering disagree that test_mast_flipped_psi_is_refused matches. This is the one permitted hit of the sign search and is named here as the exemption.

The MAST flux conversion is declared once, in one module

nova/media/sources/mast_efit.py is the one module that owns the MAST flux conversion. The archive is not a DD read, so its convention is declared rather than implied: nova.io.sourcemap.MAST_SOURCE_CONVENTION = 3 and mast_flux_factor(), which is convention_transform(source=3, target=NOVA_CONVENTION).factor(psi_like) = 2π. All three flux rows carry that declared factor in place: the flux map in _flux_map and the axis and boundary flux in read_frame. PlasmaSource.from_mast applies no further factor, so the 2π is applied exactly once on every ψ-like row. COCOS 3 and COCOS 17 share sigma_Bp = −1, so a conforming MAST slice passes the internal check and a reversed flux family is still refused.

Rows read_frame does not convert, and who converts them. p_prime (pprime), ff_prime (ffprime) and any q row are passed through raw. Their COCOS 3 to 17 factors are dodpsi_like 1/(2π) and q_like −1, and no caller on that route converts them: the media painters, mast_parity_gate, the transport route and the scripts/ entry points all take the frame values as they are handed over, so a raw COCOS 3 p′ or FF′ reaching COCOS 17 code is a 2π error. That is a finding for §4, not a change made here — the two flux functions and q are unchanged for every caller by this node.

Sensor readers: identity and geometry only

nova/imas/io_magnetics.py reads sensor identity (name, identifier), geometry (position, area, gm9, indices_differential) and the diagnostic kind. It reads no signal sample, so it carries no convention and is exempt. nova/imas/magnetics.py::Magnetics.flux_loop reads name and identifier through from_AoS and is likewise exempt. No consumer in nova/ or scripts/ reads a flux-loop or pick-up signal sample from either module, so there is no sensor signal whose sign follows ψ or B_p on this route to convert. Should one be added, the conversion belongs at this boundary through SourceSignal.convention_factor.

Extrapolate.update

The # COCOS11 literal in Extrapolate.update is gone. Its negation was the internal convention's poloidal orientation, so the line now reads convention(NOVA_CONVENTION).sigma_bp * self.psi_rbs(radius, height), computed once from the algebra. The display negation at plot_2d_masked is unchanged and remains §4's.

The reconstruction route reads through the translator too

The reconstruction-style source in tests/test_coupled_plant.py presents a discharge the way a reconstruction arrives — the last closed flux surface named as the boundary the polygon closes on, no separatrix; and the coil currents on a coarser cadence — but it must not re-orient the flux by hand. It now reads through PlasmaSource.from_imas and differs from the generic source only in presentation, so the DD3 to COCOS 17 translation is applied exactly once. Before that change the reconstruction carried a raw COCOS 11 flux family beside a COCOS 17 plant and the internal check refused it, which reddened the route comparison and the flipped-sign refusal with it. The same hand-orientation was removed from tests/test_unseen_source_full_plant.py for the same reason.
