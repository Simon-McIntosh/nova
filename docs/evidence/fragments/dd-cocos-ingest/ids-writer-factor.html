The reproduction, quoted before the repair

The new test was run against the unmodified writer first. It failed at the first site and named it:

assert np.isclose(
    float(time_slice.global_quantities.psi_axis), factor * PSI_AXIS
), "time_slice.global_quantities.psi_axis carries no factor"
E   AssertionError: time_slice.global_quantities.psi_axis carries no factor
E   assert np.False_
E    +  where np.False_ = ...(-95.0, (-1.0 * -95.0))

The entry held -95.0 where the DD3 target requires +95.0: the attrs_0d loop (["li_3", "psi_axis", "psi_boundary"]) ran after the factoring loop and rewrote both psi rows unfactored. The same test then passed with the loop merged.

What the two new tests fix

Writer, tests/test_pulsedesign_write_convention.py, 4 passed. A WriterState supplies the three attributes the writer reaches — the input dataset, the IDS to fill, the metadata hook — so the writer body runs without the machine that made it database-bound. A known COCOS 17 state (psi_axis −95, psi_boundary −102, a 2×3 psi2d) is written and read back:

  • all three sites carry the factor: global_quantities.psi_axis, global_quantities.psi_boundary, boundary_separatrix.psi and profiles_2d[0].psi, each compared against dd_equilibrium_factor(DEFAULT_DD_VERSION, PSI_LIKE), which the test asserts is −1;
  • rows that are not psi-like do not move: li_3, minor_radius and boundary_separatrix.type are asserted unchanged;
  • the writer names the one default: nova.imas.pulsedesign.DEFAULT_DD_VERSION == nova.imas.sample.DEFAULT_DD_VERSION;
  • a DD4 default reaches the source convention unchanged: monkeypatching the module's DEFAULT_DD_VERSION to 4.0.0 makes every site pass the state through, which no site can do if it states its own version.

Wall, tests/test_equilibrium_wall_dd_version.py, 2 passed. The property body is driven on an instance built without the reader's initialiser, with a recorder in place of Wall and the pulse's URI and written version supplied directly. The tests assert the constructor receives uri and dd_version == "3.38.1", and that the version passed is not the bare major the URI carries — dropping the major, or omitting the argument so the wall resolves a latest default, is red.
