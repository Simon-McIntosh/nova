Re-ingest reclaims the refused pre-convention store group

landing: SignalStore.write removes the identity-only group for the same source before storing the convention-keyed one, and prints the group it removed. Re-ingesting a legacy cache now leaves exactly one group on disk and reports which one it reclaimed, instead of leaving the refused group beside the new one as an orphan that no later read can detect. The self-fulfilling dd_version comparison in the convention-key test is replaced by assertions on the derived conventions and on the identity-only key, which the convention-bearing key must differ from.

The recorded defect, reproduced. The followup records that SignalStore refuses a pre-convention group with StaleConventionError but nothing removes it, and that write reaches only store_overwrite, whose delete_group deletes the store's own convention-keyed group. The reproduction is the declared negative control: a scratch copy of this head with the reclaim call removed (behaviourally the base) writes a legacy group, re-ingests, and the one-group assertion fails because two groups remain. The log logs/negative-control-reclaim-removed.log shows AssertionError: assert {'675ba56bcee…c21911b2efd0'} == {'89b5c21911b2efd0'}, the extra item being the legacy group, and exits 1 naming test_reingest_reclaims_the_legacy_group.

The reclaim, and why it cannot be a read-time path. legacy_group() reports the identity-only group whenever it is present, independent of the convention-keyed one; stale_group() keeps its narrower meaning — present only while the keyed group is absent — so the refusal on read is unchanged. write calls reclaim_legacy_group(), which deletes the identity-only group when it exists and is not the group being written, and prints its name, the source URI, the DD version and the convention-keyed group that supersedes it. The read-time detector cannot do this job: once the new group exists stale_group() returns None by design, which is exactly the state in which the orphan would persist. Deleting it on write is the one moment both groups are known.

(1) A legacy group is removed on re-ingest, and the removal is reported. test_reingest_reclaims_the_legacy_group writes a dataset under legacy_cache_key with a store whose group is set to that key — the shape an older nova left — asserts the store holds exactly that one top-level group, then re-ingests through IdsIngest.ingest on a fresh store. It asserts the store now holds exactly {cache_key}, that legacy_group() is None, that the served data match the ingested current, and that the captured stdout names the removed legacy group.

(2) The assertion that could not fail is replaced by one that can. The previous line compared two stores' dd_version where both were constructed from the literal DD3, so it re-derived a constant it had just supplied. The replacement asserts the two stores share DD3, that their conventions are 11 and 17, that their convention-keyed names differ, and that both legacy names are equal to each other and different from their convention-keyed names.
