Sampled flux functions take a finite edge value

The sampled flux function now has a finite-edge form that returns a supplied boundary value at psi_N = 1, and the DIII-D builder prescribes EFIT's p-prime and FF-prime on the boundary shell.

The capped form holds the last knot's value and slope and reaches zero one sample spacing past the knot, so a table stopping at 0.95 is zero at the boundary. The finite-edge form adds the third Hermite basis over the span from the last knot to psi_N = 1: value and slope stay continuous at the knot, and the supplied value is returned exactly at the boundary and held beyond it. A table that already reaches 1.0 is refused rather than reinterpreted.

The builder keeps its 19 shell centres, 0.05 to 0.95, and takes the boundary value from the same extraction continued to psi_N = 1; scripts/prototypes/diiid_finite_edge_flux/extract.py calls the builder's own _profile_edge_values, so the receipt is what the builder prescribes. On frame 137, diverted, the finite-edge arm converges to 9.06e-9 and its lower X-point lies 1.250 cm from EFIT's null, against 2.317 cm for the capped tables with support retained at 339 of 346 cells: 46 percent of the offset.

Three of the four rows could not be solved on the finite-edge arm, and the cause is the input rather than the code: the corpus directory /work/projects/imas_gpu/sophelio/raw/data/diii_d_train existed when the capped rows ran at 01:36 and was gone by 02:33, so the builder's frame selection found zero eligible frames and the three rows stopped before any solve. Their capped receipts and the builder's boundary extraction are recorded; none of them is presented as a finite-edge solve.

Seven tests in tests/equilibrium/test_finite_edge_flux_function.py hold the behaviour: the boundary value returns to the bit, the zero-edge form returns 0 there, both agree on every interior knot, the profile is continuous across the last knot, a vmapped profile returns the boundary value on every entry, a table reaching psi_N = 1 is refused, and the builder reproduces the committed extraction at 1e-10 relative for all four rows. The declared negative control restores the zero end cap for the finite-edge form: three of the seven fail, including the boundary value itself.
