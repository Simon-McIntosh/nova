The production-solver receipt writer stamps source_revision itself

The writer at docs/figures/gs-absolute-accuracy/production-solver-receipt/measure.py recorded the running revision under its own revision key but assembled the payload by hand and never applied the source-revision stamp that every benchmark receipt writer routes through (solovev_certificate.stamp_source_revision). A reader could not name the tree the measurement ran at from the payload alone, and the revision key stood in for a fact nobody had stamped.

The payload assembly is factored into a build_payload builder that returns certificate.stamp_source_revision(payload), so the persisted receipt carries source_revision equal to its revision key with no hand edit. main reads the revision through certificate._source_revision() so the key and the stamp share one source.

Pre-existing break repaired to make the module importable

The base revision's measure.py still imported set_support_clip_mode from nova.equilibrium.forward_operator, a process-global selector removed when clipping became request-owned state (commit f80a679b9, today). The module was unimportable at base with ImportError: cannot import name 'set_support_clip_mode', reproduced in the first head-arm log. The repair carries clip_mode="chord" on the ForwardSolveRequest instead, matching the production default.
