A tree-wide guard for the clean renderer wall scan

The wall-mask cleanup landed the repairs; this node pins the invariant they establish. The scanner (fsa-renderer-wall-scanner-guard-form) was a per-file entry with no corpus-wide tenant, and two of its positive controls still pinned sites that the cleanup had repaired, so the unit file was red on the clean tree.

What changed

  • tests/test_renderer_contours_inside_wall.py — new. Runs renderer_wall_scan.scan_paths over benchmarks/ and docs/figures/ and asserts the result is empty, naming every offending file and line in the failure message. The roots come from NOVA_RENDERER_SCAN_ROOTS when set, so the same entry scans a scratch tree for the negative control.
  • tests/renderer_wall_scan.py — an explicit wall=None on draw_flux_contours no longer counts as guarded: the painter then blanks nothing, so the call is reported exactly as if the argument were absent. A None handed at the wall's ninth positional is treated the same.
  • tests/test_renderer_wall_scan.py — the two positive controls that pinned now-repaired corpus sites are recast as crafted sources, so the file is green on the clean tree and still reddens if the painter or tricontour rule is removed; a wall=None control pair is added.
