The wall scanner as a per-file guard, not a defect snapshot

The scanner this node inherits (fsa-renderer-wall-scanner) reported each unguarded renderer call by base name and line, pinned the rule to a frozen 78-site inventory, and could not see a wall handed to draw_flux_contours positionally. Those three properties made it a snapshot of one revision of the defect rather than a guard a repair batch can run on its own files. This node closes the review's five follow-ons: relative paths, positional-wall recognition, a documented exemption list, and the move of the corpus reconciliation out of the test file into a committed report script.

What changed

  • tests/renderer_wall_scan.py — UnmaskedCall.path is now the repository-relative path, so the two centroid-constrained-oracle-solve/repaired-remeasure{,-receipt}/measure.py files and the several render.py / measure.py / draw_trips.py files across the trees are distinct records. The painter guard treats a call as wall-guarded when the wall arrives positionally as well as by keyword: draw_flux_contours declares wall as its ninth positional parameter (nova/media/poloidal.py:147, before **kwargs), so a call with nine or more positional arguments is guarded. Every entry of NON_RENDERER_CALLS is now keyed by its repository-relative path and carries the reason it is exempt, including the third entry (render_mechanism_evidence.py:360) the previous record omitted.
  • tests/test_renderer_wall_scan.py — keeps the five named controls against the corpus, adds a crafted positional-wall control, and asserts no total count of unguarded sites. A repair that fixes an inventory site no longer turns the file red.
  • docs/figures/figure-and-solver-audit/fsa-renderer-wall-scanner-guard-form/reconcile_wall_scan_sites.py — a committed report script that prints the scanner's current list with relative paths, then names the inventory sites no longer reported and the current sites the inventory does not carry. It always exits zero.

Rule (positional wall)

nova/media/poloidal.py:138 declares draw_flux_contours(axes, radius, height, flux, levels, style, color, linewidth, wall=None, **kwargs). wall is the ninth parameter, index 8. A call site that passes nine or more positional arguments hands a value for wall and is guarded; the scanner returns no record for it.

Corpus drift is now reported, not asserted

At this base the two trees hold 82 unguarded sites, against the reviewed inventory's 78 and the 80 the prior record pinned. The report script prints the current list with relative paths, the 4 inventory lines no longer reported (one in shafranov_combination_discriminator.py and three in shafranov_pair_receipt.py, shifted by concurrent work) and the 8 current sites the inventory lacks — six of them those same shifted or newly-added lines and two the disclosed repaired-remeasure painters. It exits zero. The count is therefore a reader's observation rather than a test expectation a repair batch trips, which is the change the review's snapshot finding asked for.
