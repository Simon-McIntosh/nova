Leaf benchmark clip-mode migration

Twelve leaf benchmark drivers no longer set the process-global support clip mode. Each mode the file chose is now threaded explicitly to the operator, profile or solve request that evaluates support, and to the clip_mode keyword of every certificate or fixture helper it calls. No helper signature became mandatory: the migrated helpers keep an additive clip_mode: str | None = None keyword whose default None preserves the prior behaviour.

Verification

Eleven of the twelve modules carry no reference to the retired global; the one residual grep hit is a test-module path literal in the limited_row_shadow_census CPU-delta roster, not a symbol reference. Every module compiles and imports under the shared interpreter. No test module imports any of the twelve, so the importer set is empty; the clip-mode contract tests that would catch a bad migration run in a fresh CPU pytest process at the archived base and at the migrated head and are identical by test id. The run manifest records the literal commands, the per-module logs and the failure identifiers.
