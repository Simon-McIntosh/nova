The recorded TCV and ITER stored-state refusals, reproduced from the comparison's own fixtures

The magnetics-fit comparison records that a public forward solve started from the stored imas-efit flux map, with imas-efit's fitted conductor currents, stops unqualified on TCV at relative residual 0.030364200526436996 with reason 12 and on ITER with no magnetic axis admitted. This record rebuilds both cases from the comparison's own machinery — its case reader, fixture machine, receipt mesh, stored seed, fitted-current binding and policy, imported rather than restated — and runs each as four arms in one batch job on a single titan card, one receipt per arm.

Two arms run the comparison's default policy, which is the policy the record's TCV attempt ran, and two run the construction the record used for the arm it shows qualifying on MAST-U: internal stopping tolerance 1e-12, forty Newton steps, sixty-four active-set steps, seeded from the default arm's terminal state. The tightened arm is the positive control. It reaches the recorded refusal in both cases, and the default arms do not, which is stated below arm by arm.

The fixtures are not the bytes the record measured

The record's values cannot be re-derived from the fixtures on disk today, because the imas-efit test data was rewritten on 2026-11-18 at 21:25, and that directory is untracked in imas-efit, so the bytes the record read are not in any revision. The profile coefficients drift with it: TCV's live FF-prime coefficient reads 0.38252056 today against 0.38275327 in the earlier run, and ITER's leading coefficient 14731.018 where the earlier run read 13465.688.

The code revision is not the cause. Running the same runner on an archive of the record's own revision, 9047a3fe50708d6dd20ebe672d0dc22f40b0ae50, gives TCV a default-arm residual of 0.0005241157425587287 against 0.0005241157519662908 on this revision — the same terminal state to seven significant figures. The difference from the recorded 0.0303 therefore belongs to the input data and not to the solver. That control was stopped once the TCV default arm had landed, so ITER was not re-run at the record revision; its receipt is published at ~/.cache/nova-stored-state-refusals/record-revision/.

MAST-U, and why it is not measured here

The record's MAST-U solve is the only arm it shows qualifying: a continuation at 5.307643379157493e-16, inside a complete case wall of 3508.560784 s on a titan P100, of which one call is recorded at 213.338199 s. The record states no device memory figure for it, so the requirement is taken from the card the solves ran on: the backend on that card reports a 12 801 015 808-byte device limit.

MAST-U is left unmeasured here, pending the H200. It is not run on this node because its recorded wall is more than twice the longest arm measured here and its continuation needs the larger card's memory; no claim is made about its outcome on today's fixtures beyond the record's own.
