No per-test timeout mark is needed on the H200 lane

The node premise was that the project's timeout = 300 ini default governs the forward-solve tests and must be raised per test. The measurement refutes it. Since 55bca9b99/75495edb0, scripts/nova_lane/run.sh in pytest mode appends --timeout ${NOVA_LANE_TEST_TIMEOUT:-3600} whenever the payload carries no --timeout, so every test routed through the H200 lane is already bounded at 3600 s. The slowest test in the file measures 312.57 s, well inside that bound. A @pytest.mark.timeout(660) mark would lower that test's lane bound from 3600 s to 660 s and is therefore withdrawn; the file at this node's head is byte-identical to the base.
