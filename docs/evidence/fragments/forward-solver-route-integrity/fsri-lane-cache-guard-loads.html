The payload prelude now reaches pytest, so the cache guard loads on the lane

The lane launcher ran its payload prelude as bash -euo pipefail -c "${prelude}", a subshell. The H200 lane's prelude sets the environment the target runs under, and every export in it (PYTEST_ADDOPTS carrying -p cache_guard, JAX_COMPILATION_CACHE_DIR, and the cache flags) died when the subshell exited. The fix evaluates the prelude in the payload shell itself ({ eval "${prelude}"; }), so the target inherits the environment the prelude sets. Commit b091aa8d8996de2b8e98a974b0f40b4b098f256e carries the launcher change and the regression case in tests/test_nova_lane_launcher.py.

Did JAX_COMPILATION_CACHE_DIR reach the tests before the repair? No. The prelude exported it in the subshell on every lane run, so pytest never received it, never loaded cache_guard, and the served directory the guard reports was never set for the tests. The new test proves the mechanism: the prelude exports a probe, and the target records the value it was given. At the base revision (9300a771470c97ca268927933c98d9ead604cd09) the target records MISSING and the case fails; at the fixed head it records delivered and the case passes.

Positive lane run (titan, job 1280629). With the pin present the guard loads and accounts for the run: the prelude emits the cache header (CACHE_GUARD_DIRECTORY, CACHE_GUARD_SERVED), and the session finish prints per-program rows and CACHE_GUARD_MARKER=wall-clock-reliable misses=13 budget=100000 with EXIT_STATUS=0. The guard was inactive on the lane before the repair, so this marker had never been printed.

Negative control (titan, job 1280631). Budget 0 against a served directory that lacks the programs (source_revision=000…0, empty directory) forces a miss. The run ends CACHE_GUARD_MARKER=WALL-CLOCK-UNRELIABLE misses=13 budget=0 with EXIT_STATUS=1: the guard refuses a timing result it cannot support. Before the repair the guard never loaded, so this refusal could not fire. The first negative attempt against the real pin reported misses=0 because the earlier positive run had written its programs into the shared pin directory, which is the persistent-cache behaviour; the controlled empty directory removes that dependence.

Rung. Both lane jobs ran on titan. The H200 reservation was fully allocated for the whole window (all eight gpu:h200 cards held by other jobs), and submissions queued PENDING (Resources); titan is the next rung under the compute hierarchy and carries the same launcher path, so the mechanism it exercises is identical. An H200-specific rerun is listed under follow-ons.

One correction to the expected criterion. The guard is loaded with -p cache_guard, and pytest does not name a -p-loaded plugin on its plugins: line — that line lists installed entry-point plugins only. Demonstrated directly: a dummy plugin passed with -p dummy_plugin prints its header but does not appear on the plugins: line, and cache_guard behaves the same while plainly running (it emits the header, the rows and the marker, and enforces the budget). The guard's loading is therefore evidenced by its header, rows and marker lines, not by the plugins: line.
