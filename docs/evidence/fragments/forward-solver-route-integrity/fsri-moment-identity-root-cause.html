The moment-identity failure is not a regression from either merge, and the divergence is the separatrix clamp in the solve path

tests/test_equilibrium_forward_solve.py::test_solve_path_current_moments_match_profile_owned_support fails on CPU at every revision named for this node: the parent and the merge of the frozen-Newton lineage (f863867a8, db580bec8), the parent and the merge of the clip-mode request field (3ecff38e, af7403bc0) — and main 96845bc64. The failure is bit-identical at all five: Mismatched elements: 31 / 625 (4.96%), Max absolute difference among violations: 173.43143596, Max relative difference among violations: 0.31223999, and the same first mismatch [135]: 660.3190283954135 (ACTUAL), 641.0264598166705 (DESIRED). It is therefore not a regression from these merges; it predates both.

What the test compares

The test builds a profile-owned support from the atomic mesh chord clip, geometry.atomic_mesh.traced_clip(ones).qualify(masks.profile_participation), and compares two ways of integrating the cell currents on it:

  • support_current_moments — the direct arm: operator.support_current_moments(operator.source.core, masks.psi_norm, sample_psi_norm, profile_support), passing the bare source.core profile. The docstring claims solve moments equal direct integration on the profile-owned support.
  • the solve arm: operator.cell_current_moments(seed), which routes through ForwardSource.current_moments and wraps the profile in _FluxSelectedProfile(self.core, self.common_sol).

The wrapped profile reproduces the solve arm exactly (maxabs 0.0, 0 mismatches); the bare profile reproduces the failure exactly (same 31 indices, same maxabs 173.4314359564). The entire divergence is the profile argument. common_sol is undeclared here, so _FluxSelectedProfile.current_density returns jnp.where(flux > 1.0, 0.0, confined): it zeroes the current density above the separatrix (psi_norm > 1) at every quadrature point, while the bare source.core profile integrates the same straddling cells with the core profile extended past psi_norm = 1. The 31 cells are exactly the cells the separatrix crosses; there the two arms differ by up to 31 % relative, everywhere else they agree.

Responsible code change

The pointwise separatrix selection entered ForwardSource.current_moments together with _FluxSelectedProfile in 8b88abb7a (fix(equilibrium): select open support from live flux, 2026-09-01), which made the solve arm clamp the profile where the direct comparison arm does not. That commit predates the test's authoring/aligned body (ac945c19f 2026-09-04, 87a7f3499 2026-09-04) and both sampled merges (2026-10-02). The failing comparison is a contract mismatch in the test arm — a different clip/profile branch, not a reduction-order or support-mask change — and it is not a regression from the frozen-Newton or clip-mode merges.

Follow-on

The test arm and the solve path disagree by construction, so the test cannot pass until one of them changes. The repair is the reconciliation of the two moment paths, not a tolerance change: either the direct comparison arm adopts the pointwise separatrix clamp the solve path applies, or the solve path stops applying it on the straddling cells. Choosing between those is the follow-on, and it needs a decision the plan does not settle. The five gate logs and the numbers above are enough for a reader to reach it.
