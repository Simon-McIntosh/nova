One nova lane launcher for SLURM placement

Landed. scripts/nova_lane/run.sh takes a pytest target or a script, a rung preference (default h200,titan,cpu), cores, memory and an absolute log path; it applies the repository's SLURM rules and records the rung used, the job id and the git revision in the log header. scripts/h200_test_lane/run.sh is now a thin caller of it, carrying the reserved-H200 pre-warm cache contract in a payload prelude.

  • Rungs. H200 → --partition=betelgeuse --reservation=gpu_0003_grpA --gres=gpu:1; titan → --partition=titan --gres=gpu:1; CPU → --partition=all_debug with JAX_PLATFORMS=cpu.
  • Explicit memory. --mem=0 is refused before it can reach sbatch; the job would otherwise pend on Resources while blocking the queue.
  • Environment. TMPDIR=/tmp exported at submit and in the payload; UV_NO_SYNC and UV_RUN_RECURSION_DEPTH unset; no uv on the compute node (the shared interpreter runs directly with PYTHONPATH).
  • Admission. a rung is tried only after a real submission is shown still PENDING on a resource or configuration reason after a bounded wait; the decision is never taken from an sbatch --test-only estimate. A session already inside an allocation runs in place (--force-submit overrides).
  • H200 lane steps. the thin caller carries the lane's cache contract as a payload prelude (...PINNED_REVISION with the mismatch diagnostic when the served pin was compiled for another revision) and a concurrent sampler (cache_guard.sample_gpu_utilisation), whose output the launcher appends after the target exactly as the pre-change caller did; the dry-run prints the resolved payload steps for each rung.
  • Reason match. a submission pending on Resources, Configuration, ReqNode* or NodeDown falls to the next rung.
