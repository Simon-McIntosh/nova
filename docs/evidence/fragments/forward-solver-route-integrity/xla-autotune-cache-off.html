xla-autotune-cache-off

Every nova route that enables JAX's persistent compilation cache also turns off XLA's per-fusion autotune cache. JAX defaults jax_persistent_cache_enable_xla_caches to the GPU per-fusion autotune directory, so a configured cache writes XLA's autotuner records beside the compiles — thousands of synchronous small-file creates per revision on GPFS, and none of them needed, since the autotuner re-decides the same way on the next process.

Change

  • nova/jax/config.py: configure_persistent_compilation_cache sets jax_persistent_cache_enable_xla_caches to none before it computes the runtime identity, so the identity records the setting and the pin and the lane resolve one directory.
  • nova/biot/tiledassembly.py: compilation_cache applies the same setting on its own route.
  • scripts/h200_test_lane/run.sh payload prelude and scripts/h200_test_lane/prewarm.sh payload environment both export JAX_PERSISTENT_CACHE_ENABLE_XLA_CACHES=none.
