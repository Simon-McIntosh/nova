The held-map iteration over 200 slices of both drift sequences, each column on its own rows

This node fits the held-map pass of the equilibrium iteration — FluxIterationFit, the column the plan's lead ruling names for this study — over 200 slices of the white and of the 1/f reference sequence, and reports the per-slice and 50-slice-mean error of the axis position, the boundary flux and q95 beside the lag-one controls defined in plan §7.

The generating state is the section-1 ITER fixture at 500 cells: its state, the noise model and the pulse writer are probe_rows/study.py's, the held-map driver is probe_rows/iteration.py, every measure is probe_rows/analyse.py's reduction, and the gate is probe_rows/check.py reading that reduction's own summary. Each column states the row set it was fitted from: nova reconstructs the study's 72-row magnetics set, imas-efit's arm fits the 24 flux loops. No number below is restated by a second rule.

Clause 2: the lag-one control

The white sequence is the negative control: a code that reads noise rather than the state must show no slice-to-slice memory, so its lag-one must sit within 0.15 of zero on all three quantities. The 1/f sequence is the positive control: the colouring itself carries memory, so a code that reproduces the reference must show lag-one above 0.5 on all three.

The white control holds for both codes; the 1/f control fails for both. The gate reads CHECK-FAILED nova: the 1/f lag-one clause failed and CHECK-FAILED efit: the 1/f lag-one clause failed at revision d941a9598fc978753324d714067c6f25e3b6d5ff: 24 passed, 2 failed, exit status 1. nova fails on all three quantities (0.047, 0.085, 0.105). imas-efit is nearest the floor and fails on the axis only (0.462), its flux and q95 lag-one sitting above it (0.544, 0.606).

That is reported, not tuned: the 0.5 floor is a property of the reference spectrum at this colouring and was not lowered to pass a run. The finding it supports is that at this noise size neither code's reconstruction tracks the slow component the 1/f draw adds. What the control does rule out is its own degenerate readings. The white column shows neither code inventing memory, so no run of the pipeline manufactures correlation. The 1/f draw is itself correlated, and the same draw's imas-efit arm shows it: lag-ones of 0.462, 0.544 and 0.606 on that sequence against 0.047, 0.118 and 0.058 on the white one are the measurement that the draw carries colouring the reduction can see at all. A gate that reported no memory on either sequence would say the reduction was blind to it; this one says nova's two-pass residual is below that memory, not detected.

The comparison is not stated. plan §7 makes the control a condition of reading the comparison: a generator or pipeline that fails this is repaired before any comparison is read. The control fails here for both codes, so this record states no cross-code comparison of the error measures, and it does not do so in a footnote either: the two tables above hold per-code readings, and the row sets they were fitted from differ in any case. The repair the clause calls for is a fit that resolves the injected colouring, which is the converged arm the cost section sizes; the row-matched arm that would let the two columns be compared, job 1338386, did not complete. Both are the remaining work of this node.
