imas-efit on nova-written ITER magnetics rows: the generating state does not exist in the solver's resolved basis

This node set out to write noise-free ITER magnetics rows from a nova forward state lying inside imas-efit's own resolved basis, run the solver on them with its pressure and q0 priors disabled, and compare its reconstruction and the nova fit against that generating state within the section-8 bands, with a 1.10-scaled negative control. The rows-and-pulse wiring was proved end to end and imas-efit reads nova's pulse. The comparison could not be made, and the reason is not wiring: no generating state in imas-efit's resolved basis qualifies as an equilibrium — the basis restricts the pressure gradient to zero and the diamagnetic function to one live Bernstein coefficient, and every source in that space either has no qualified magnetic axis or drives the solve away from the seed.

The finding is measured rather than asserted, and it is reported as the node's outcome because the alternative — substituting a source outside the solver's basis — would have made the comparison answer a question nobody asked.

The solver's resolved basis, measured

imas-efit is checked out at revision fe13365d5 with binary build/sdcc/src/efit. The shipped ITER magnetics-only configuration (configuration/machines/ITER/efitOptions.xml) carries pressurePriorBetaPol="0.5" and a <q0 weights="4" values="1.3" sigmas="0.3" interpolationMethod="1" timeWindow="0" timeMargin="1"/> constraint. The case configuration used here disables both priors (pressurePriorBetaPol="0", q0 weights="0"; the q0 attributes remain mandatory even at zero weight, or the solver aborts with “The ‘interpolationMethod’ parameter has not been specified”). With the priors disabled the solver announces its own resolved space on every run:

AUTODEGREE: regime=magnetics-only/large-aspect detector_regime=magnetics-only
  pp_ndeg=0 ff_ndeg=2 live_pp=0 live_ff=1 max_pp_ndeg=0 max_ff_ndeg=2
  R0=6.1680 a=2.2259 kappa=2.088 epsilon=0.3609
  (mag=true press=false mse=false fara=false intf=false)

So the pressure gradient carries no live function and the diamagnetic function carries one, on Bernstein basis func=8 with edge=1, which drops the B_{n,n} term so the retained function vanishes at the edge: the live shape is FF' ∝ 1 − psi_norm with ypsi = (psi − psi_axis)/(psi_bnd − psi_axis). A generating state inside this space is therefore p' ≡ 0 and FF' = A(1 − x), which the case expresses as ascending-power coefficients [1, −1] with a scalar normalisation — verified identical between the pressure and diamagnetic composition.

What did work: nova writes the pulse and imas-efit reads it

nova writes one HDF5 pulse at DD 3.39.0 through imas.DBEntry("imas:hdf5?path=…", "w", dd_version="3.39.0"), carrying magnetics (the machine's own 24 flux loops at their declared positions and 48 poloidal probes at −poloidal_angle, because nova projects with cos(angle) R̂ + sin(angle) Ẑ while the dictionary normal is cos(θ) R̂ − sin(θ) Ẑ), the measured ip, pf_active with its 9 circuits and 14 coils, pf_passive with its 103 loops, the 57-point wall, and a synthesised tf (b_field_tor_vacuum_r = r0·b0 = −32.86), because the source pulse carries no tf IDS. Three IMAS contracts had to be met that the probe run found: the entry takes a URI and not a bare path; put() takes the IDS object and not its name; and every time-coordinate leaf must be cut to the single written slice, since the source IDS carries a 986-slice time base and validation refuses a leaf longer than the time base.

imas-efit then read that pulse and ran to completion (job 1318577, sun_debug):

Output is written at DD 4.1.0, whose stored flux reads as nova's total poloidal flux with a positive sign (nova = +psi_DDv4, since psi_DDv3 = −psi_DDv4 and section 2 fixes nova = −psi_DDv3).

Why the generating state does not qualify: every lane, measured

The generating solve is a nova forward solve on the section-1 ITER machine (pulse 135011 run 7, slice 353, DD 3.39.0, 9 circuits and 14 coils, 103 passive loops) with the basis-restricted source above, seeded by the stored reference map. Its amplitude is fixed to reproduce the pulse's plasma current through a unit-amplitude trial; the device build reported amplitude = −2.171341847778325 at the 500-cell reference mesh and −2.207671692113146 at 120 cells. The seed itself resolves cleanly (axis (6.3709, 0.5344), X-point (5.1059, −3.4152), axis flux −85.99 Wb, boundary flux −4.73 Wb, span 81.26 Wb), so the failure is in the solve, not in the data.

What this means for section 8, and what a future run needs

Section 8 asks for a generating state inside what imas-efit actually resolves, at the live count it selects, including its edge constraint. Measured against the solver's own announcement, that space is one function wide on the diamagnetic side and empty on the pressure side, and a magnetically confined ITER torus with p' ≡ 0 and a single edge-vanishing FF' does not appear to admit a qualified axis at the reference resolution on the lanes measured here. The premise of the comparison, not its arithmetic, is what failed: plasma current, axis position, axis and boundary flux and q95 for imas-efit and for the nova fit would have been compared against a state that cannot be constructed, so no band, and no 1.10 negative control that was built on that state, can be reported as measured.

A future attempt has three honest options, in order of cost: give imas-efit a pressure prior to open the pressure direction and compare against a generating state that the solver's space then really contains; run the solver's pp_ndeg at a value that admits pressure and record the resolved basis that results; or reproduce this section's target on the reference-equilibrium reproduction path, where the source space is nova's own and the certificate is already measured. What must not be done is what this node could have done cheaply — write rows from a two-term source, let imas-efit reconstruct them, and report agreement that says nothing about whether the basis is adequate.

No poloidal flux panel accompanies this record because no terminal forward state exists: every candidate ended in a non-converged or non-qualified state, and the figure rule forbids drawing a solved field alone on a non-converged state as if it were the answer. The seed map, which is a real state and does qualify, is the stored section-1 reference and is already published on the section-1 record.
