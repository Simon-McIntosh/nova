imas-efit closed-shell control: the dependency refuses XML-only input, so no S exists

Verdict. No shielding factor was measured from imas-efit, and none is reported. The control produced no capability evidence: on imas-efit develop, a closed-shell case authored entirely in XML cannot run a plasma slice at all, so imas-efit is neither implicated nor cleared on the shell representation. The exact reference values this control was to be scored against stand at S = 61.101838 (a/b = 0.9) and S = 195.1 (a/b = 0.5) at μr = 1000; the 2 % scoring rule was never reached.

What the control did establish

The annulus geometry is accepted and the iron boundary-element assembly runs on it. A ironBoundary.xml carrying one closed half-annulus contour (polynomialOrder="1" breakpointContinuity="-1" boundaryType="2"), with magneticPermeability relativePermeability="1000" and no B–H table, produces a populated iron response set. At 20 knots the assembly logs IRON_FORM: nObs=20 nBasis=20 and IRON_RANK: rank_dgelsd=20 cond=1.000000E+00, and at 200 knots on the same shell IRON_FORM: nObs=200 nBasis=200. The 40-knot assembly is recorded in responseFunctions.nc: /ironModelResponses holds gridToIronNorm (40, 257, 257) with max |·| = 8.753194 × 10−5, ironNormToIronCurr (40, 40) with max |·| = 6.236109 × 10−7 and ironCurrToGrid (40, 257, 257). The shell is therefore parsed and its operator assembled; what is missing is a source, not a geometry.

The blocker, traced to two lines of the dependency

No circuit reaches the solver. src/pfSystems.cpp reads the machine file's passive structures and coils and then stops:

      passiveStructures.readXml(xmlDocument,"passiveStructures",pulseNumber);
      pfCoils.readXml(xmlDocument,"pfCoils",pulseNumber);
      //      pfCircuits.readXml(xmlDocument,"pfCircuits",pulseNumber);

with PfCircuits::readXml called from nowhere else in src/. Every run therefore logs PFCURR_INIT(startup): ncircuits= 0 sum|pfcurr|= 0.0000E+00, the <efitCircuits> selection in efitOptions.xml binds against an empty machine circuit list, and responseFunctions.nc carries circuitsToIronNorm (20, 0) and gridToCircuits (0, 257, 257). With no active circuit there is no active coil geometry, and the axis search refuses to choose one: FINDAX: active coil geometry absent; rejecting axis, followed by CONVERGENCE_SUMMARY: status= -2 iterations= 0. The slice never reaches an iteration, so the iron step that runs at call=0 carries sumAbsBrsp= 0.00000E+00 — a zero-source solve.

This is not a defect in the authored case. imas-efit's own tests/FTU/singleTimeTest, run unmodified through the same binary in XML mode, logs the same ncircuits=0 and terminates on the stored vacuum slice (status= 2). The circuit-bearing CI cases obtain their circuits from a pulse, not from XML.

Second finding: the cold seed rejects any grid whose first radius is zero

seedWallCircle (src/EFIT/inicur.f90:110) returns failed = .true. before any containment test when any(radii <= 0.d0). A regularGrid starting at rMin="0.0" — the natural way to describe a machine whose wall begins on the axis — therefore ends every slice at currnt: wall-bounded cold current seed has no interior support. rMin="0.001" clears the guard and the slice then advances to the iron step and to the FINDAX refusal above. The guard is silent about which condition failed, and the message names the wall rather than the grid.

What would make the measurement possible

Either of:

  • a pulse supplying pf_active circuits and their coil geometry, so ncircuits > 0 — the shell then becomes one more XML-authored machine element beside an IMAS-described coil set, but the case is no longer XML-only and its machine description is no longer the analytic annulus alone; or
  • an upstream change that reads machine <pfCircuits> in XML mode (restoring the commented line), or that lets FINDAX fall back to strongestAdmissibleGridNode when the coil list is empty.

Both are imas-efit changes, not nova changes. No nova source, test or plan state was altered by this control.
