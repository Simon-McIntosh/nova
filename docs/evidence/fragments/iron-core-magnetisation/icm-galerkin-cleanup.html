§4 — Galerkin interaction cleanup

Node icm-galerkin-cleanup closes the review findings on the volume-tested iron interaction. Two duplicated capabilities now call their owners: the filament loop flux of every distinct quadrature pair comes from nova.biot.greens.traced_filament_greens, and the averaged external field is integrated by nova.biot.sectionaverage.section_nodes with the axisymmetric 2*pi*r volume weight. The volume-tested route is a named _galerkin_interaction, so _interaction evaluates point targets only and the measurement caches key on what they are handed. The reciprocity test is no longer vacuous: it measures the defect of the raw contraction before the two triangle halves are averaged, and a scratch mutant that mirrors one off-diagonal edge-pair quadrature fails it.

One pair type cannot delegate, and the reason is numerical rather than architectural. The owner derives its squared separation from the target and source coordinates, (ar-r)**2 + dz**2, which cancels to exactly zero at the graded corner nodes of a coincident pair once the parameter square is folded about its diagonal at quadrature order 16 and above; the flux then returns a non-finite value and the energy guard refuses the assembly. A coincident pair therefore keeps the exact squared separation of the folded square, |b-a|^2 (x^3 y^3)^2, which is derived from the parameter nodes instead. Every other pair bit-matches the owner's arithmetic path.

One probe is reported and deliberately not asserted. It is recorded because it bounds how far the rules can part company, not as evidence about the averaged field, which is smooth where the iron sits.

Negative control

A scratch extraction of the head revision mirrors one off-diagonal edge-pair quadrature entry, mutual[columns[0], rows[0]] = 1.001 * value[0], so one pair is no longer reciprocal while everything else is exact. The runner asserts that the imported nova.biot.tiledassembly is the scratch copy and that the marker is present in galerkin_cell_energy, runs the selected defect tests, and afterwards compares the worktree's source blob against git show HEAD:nova/biot/tiledassembly.py. All five selected identifiers fail (5 failed, 43 deselected in 90.81s, EXIT=1) and the product source blob matches HEAD, so the test reports an assembly defect rather than restating a symmetry the assembly already imposed.

One mutant harness

Two negative controls had been written as separate programs, and each carried its own copy of the same seven steps: resolve the revision, keep the tracked blob, extract the sources with git archive, mutate one file in place, prove the imported module is that extraction, run the selected tests, and prove the product source is unchanged. mutant.require_rejection now owns that sequence, and a second control supplies only what differs about it: the file it edits, the mutation as a string edit, the marker the mutation introduces, the test selection and the log path. A change to the extraction set or to the identity guard is made once.

duplication.py is the check that keeps it that way. It reports every module carrying the whole extract-mutate-verify sequence and requires exactly one carrier, mutant.py:
