The per-end denominator, the packed-kernel port, and a gate that now closes

Each entry of the tiled interaction matrix is now divided by the absolute sum of its own per-end antiderivative terms, which is the denominator the section specifies. The packed closed form no longer returns NaN beyond a sloped edge's end. With both changes in place the whole-mesh comparison closes: over 11,505,664 entries the worst disagreement between the padded tile and its flat walk is 2.083×10-15 relative to the per-end terms, nothing exceeds 1e-13, and every entry is finite. The strict xfail that recorded the gate as unmet is removed, and the reversed-normal control now fails with its own test id and a nonzero exit status.

The gate was routed to betelgeuse first, as the section names, and that job stayed PENDING on resources for twenty minutes with all eight cards allocated to serving jobs. The same payload then ran on titan, where it started immediately. These are titan walls and titan is a P100: the 126 s includes a cold compile against a 16 GB device, and none of it is a headline for the H200. The arithmetic is unaffected — the comparison runs in float64 on either device, and the test module asserts that flag rather than trusting the environment, because the bare probe process in the job header reads x64 False by construction (it never reaches configure_dtypes) while the test process is double throughout.

The CPU lane is not a fallback at a smaller size. A 32-row subset — about a minute of compute at the measured per-pair cost — was left to 540 s and produced no summary line: the parent pytest process was alive at 1.2% CPU nine minutes in with no spawned shard beside it, so the multi-worker path blocks before it computes. That is the same signature as the two full-mesh attempts, and it made one accelerator the only route to this number.

The finiteness clause was failing in this node's own scope

nova/biot/sheet.py was fixed to take the phi = 0 curvature argument and the r1 + r panel centre as magnitudes, because a target beyond a sloped segment's ends or on the far side of its line puts r1 + r b12 below zero and the square root returns an imaginary. The tile does not call that code: it evaluates a packed transcription of the same closed form in nova/biot/tiledassembly.py, which still carried the pre-fix signed forms. So the tile and its own reference both returned NaN for a whole field component on targets beyond an edge end — the two sides agreeing perfectly on an undefined value while the gate failed on finiteness rather than on agreement. Both terms are magnitudes now, and _sheet_arsinh_gradient grades the end nearer the azimuth where its arsinh denominator vanishes, mirroring the host route. The packed form evaluates a block at once, so that end selection is broadcast over the rule's node axis rather than applied to a scalar.

The denominator

packed_sheet_end_scale returns, per pair and per component, the sum of the absolute values of the two segment-end terms that packed_sheet_field subtracts. It mirrors the field's branch structure — the sloped route's two end gradients, the flat route's two pancake ends — so a block mixing flat and sloped edges remains one program, and it reuses the same _sheet_closed_gradient and _sheet_pancake_terms rather than re-deriving the closed form. The tests contract it against the cell incidence exactly as they contract the field, so the gate and its negative control share one denominator.

The reference that is independent of the code under test

Comparing the tile with an unbatched evaluation of the same traced closed form measures the tile's batching and padding and nothing else: both sides read their edge directions, normals and shared-edge signs from the same cell_edges coefficients, so a sign or deduplication defect there is invisible to it by construction. A second test therefore builds the same interaction matrix from the prototype's own edge-ring quadrature and exact ring Green's function (scripts/prototypes/iron_magnetisation/magnetisation.py), which derives its own edge directions, outward normals and shared-edge sum from the polygons.

The disagreement moves only in the eighth digit between orders 32 and 128, so the quadrature has converged and what remains is the gap between a ring sum of the ring Green's function and a closed-form edge integral. It is not the tile's error — the tile reproduces its own flat walk to 2×10-15 on the same mesh. The bound is therefore set at 1e-6, about thirty times the measured floor, which leaves it a defect detector rather than a precision gate: a sign error in Kphi, or a shared-edge pair collapsed the wrong way, moves an O(1) fraction of an entry, as the control below shows.

The negative control

Reversing one cell's edge normals in the device build and running the same gate test produces a failed test — tests/test_sheet_tile.py::test_tile_agrees_with_the_unbatched_closed_form, exit status 1 — with a worst entry of 2.000 and 62 of 108,544 entries above the gate. That is the O(1) response the denominator is supposed to expose, and it is now visible as a red test rather than as an expected failure: under the strict xfail the same run reported 1 xfailed and exit status 0, which is why the marker had to go before the control could mean anything.

What remains

  • Nothing in this section's done-when. The gate closes with every entry finite and the worst entry inside 1e-13, the heavy tests carry the slow marker so the default lane skips them, and the control is red through pytest with a test id and an EXIT= line.
  • For the next reader: the 3.05×10-8 formulation gap is documented and bounded, not explained pair by pair. If a later node needs the ring reference as a precision instrument rather than a defect detector, that gap is where it starts.
  • Naming test files on the command line clears pytest's inherited -m 'not slow' filter, so a suite arm written that way runs the 1500 s and 1200 s gates and reads as a hang rather than as work. Both arms here pass -m 'not slow' explicitly and report their deselected count beside their result.
