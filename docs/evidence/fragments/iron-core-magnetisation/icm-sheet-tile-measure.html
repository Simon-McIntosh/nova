The per-end denominator, and why the gate is still unmeasured

The agreement gate now divides each entry by the absolute sum of that entry's per-end antiderivative terms, which is the denominator the section specifies, and the packed closed form no longer returns NaN beyond a sloped edge's end. Both changes are committed and the fast lane is green. The gate itself is not measured: at the measured cost a 1696-target run is about 46 minutes of compute on eight cores across its three passes, and it did not return inside this node's fence.

The 46 minutes is pure compute. Import and JIT compile are paid again by every spawned shard, and the two suite arms are outside it, so the whole-mesh run does not fit a 60-minute CPU lane. The section already routes heavy gates to betelgeuse under gpu_0003_grpA, which is where this one belongs; the gate was re-run there by nothing yet.

The finiteness clause was failing in this node's own scope

nova/biot/sheet.py was fixed to take the phi = 0 curvature argument and the r1 + r panel centre as magnitudes, because a target beyond a sloped segment's ends or on the far side of its line puts r1 + r b12 below zero and the square root returns an imaginary. The tile does not call that code: it evaluates a packed transcription of the same closed form in nova/biot/tiledassembly.py, which still carried the pre-fix signed forms. So the tile and its own reference both returned NaN for a whole field component on targets beyond an edge end — the two sides agreeing perfectly on an undefined value while the gate failed on finiteness rather than on agreement. Both terms are magnitudes now, and _sheet_arsinh_gradient grades the end nearer the azimuth where its arsinh denominator vanishes, mirroring the host route. The packed form evaluates a block at once, so that end selection is broadcast over the rule's node axis rather than applied to a scalar.

The denominator

packed_sheet_end_scale returns, per pair and per component, the sum of the absolute values of the two segment-end terms that packed_sheet_field subtracts. It mirrors the field's branch structure — the sloped route's two end gradients, the flat route's two pancake ends — so a block mixing flat and sloped edges remains one program, and it reuses the same _sheet_closed_gradient and _sheet_pancake_terms rather than re-deriving the closed form. The tests contract it against the cell incidence exactly as they contract the field, so the gate and its negative control share one denominator.

The reference that is independent of the code under test

Comparing the tile with an unbatched evaluation of the same traced closed form measures the tile's batching and padding and nothing else: both sides read their edge directions, normals and shared-edge signs from the same cell_edges coefficients, so a sign or deduplication defect there is invisible to it by construction. A second test therefore builds the same interaction matrix from the prototype's own edge-ring quadrature and exact ring Green's function (scripts/prototypes/iron_magnetisation/magnetisation.py), which derives its own edge directions, outward normals and shared-edge sum from the polygons. Its bound is the quadrature's convergence rather than the tile's rounding, so it is stated at 1e-8 and is a defect detector: a wrong sign in Kphi, or a shared-edge pair collapsed the wrong way, is O(1) there.

What remains

  • Run the gate on the H200 rung over the whole mesh: every entry finite, worst entry within 1e-13 of the per-end scale, with the distribution recorded here. The job is submitted — betelgeuse, gpu_0003_grpA, one card, eight cores, 45 minutes — and was still pending on resources at this fence's end, so the gate is submitted and unmeasured rather than measured and failing.
  • Run the negative control there too. It is wired — setting NOVA_SHEET_TILE_REVERSE_NORMALS=0 reverses one cell's edge normals in the device build — and it is now a test that fails with its own id, driven as the second run of the same job so it writes a log closing with its EXIT= line. No red log exists yet, so the declared mutation is still unproven.
  • The denominator does not by itself close the gate. A read-only attempt measured the worst finite entry at about 1e-8 under the per-end scale across eleven target rows, against 0.077 to 1.67 under the per-edge one, so the residual is a disagreement between the padded tile and the flat walk and not an artefact of a cancelling sum. The independent reference is what tells whether that residual lives in the coefficients or in the padding.
  • The CPU lane is not a fallback at a smaller size. A 32-row subset — about a minute of compute at the measured per-pair cost — was left to 540 s and produced no summary line: the parent pytest process was alive at 1.2% CPU nine minutes in with no spawned shard beside it, so the multi-worker gate path blocks before it computes. That is the same signature as the two full-mesh attempts, and it makes one free H200 card the only route to this number.
  • Naming test files on the command line clears pytest's inherited -m 'not slow' filter, so a suite arm written that way runs the 1500 s and 1200 s gates and reads as a hang rather than as work. Both arms here pass -m 'not slow' explicitly and report their deselected count beside their result.
