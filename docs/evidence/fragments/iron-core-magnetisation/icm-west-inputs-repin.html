The deleted WEST 62751 solve-inputs pin is restored, and its probes, B-H table and air-core field match every value already committed

An unrelated worker's recursive removal deleted the evidence root on 2026-11-19, taking the WEST solve-inputs pin with it. west_inputs() rebuilds the region, source field and CEA table live and asserts them against that pin, so every WEST arm failed before reaching a solve. The pin is regenerated here through the same code path the arms use, under the new storage root, and then checked against the numbers committed in git rather than against itself. Nineteen comparisons pass: the three probes exactly, the air-core field to 1e-12 relative, and the table knots exactly at the precision each record holds them.

Provenance of the regenerated pin

The pin was written from a clean tree by scripts/west_iron_inputs/pin.py, which refuses to write when the working tree carries uncommitted changes and when its own blob is not the blob the revision commits. It stamps the revision and that blob, so a later reader can name the code that wrote it. The source pickle is verified against the SOURCE_SHA256 both measurement scripts assert before it is read.

west_inputs() against the pin, and without it

The check runs on CPU on rigel from this node's worktree, with the reference path pointed at the new location in-process because the tracked constants still name the old root. west_inputs() passes with a probe air-field drift of exactly 0 and all six segments present. Removing the pin in a scratch copy only, under TMPDIR, and pointing the reference there makes the same call fail on FileNotFoundError, which is the negative control: the assertion that matters is against the pin, not against a rebuild compared with itself.

The pin and its receipt are the only files written under the new evidence root: the pin above, and west-62751-solve-inputs-regeneration.json beside it, which carries every comparison and the pin's SHA-256. Nothing was written under the old sophelio root, which this node did not touch; no rm, mv or cleanup ran anywhere under /work/projects.
