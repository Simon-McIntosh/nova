The 105052 12 mm arm rebuilt on the re-keyed sectioned set, and every arm now names the set it was built on

landing: write_arm in scripts/iter_vessel_evolution/evolve.py now stores, beside the currents, the sectioned-set key the arm's circuits were loaded under (sectioned_set_key) and the sha256 of that entry's linkage.npy (linkage_sha256), and the arm directory is chosen with --output-dir (defaulting to the cache). The 105052 arm at 12 mm was regenerated against the repaired entry and now carries 1,432 passive columns where the retired arm carried 1,312.

1. The arm names the sectioned set and the linkage it was built on

The key alone does not pin an entry's contents: the same key can be rewritten with different contents, which is what the VS3 repair did when it re-spliced the finite-source coil block into the stored matrix. So the arm carries both the key the loader resolved and the digest of the matrix it was actually propagated through. --output-dir defaults to today's cache directory, so the existing write path is unchanged while an arm can also be produced into a run directory.

The test test_*_arm_names_the_sectioned_set_it_was_built_on writes a small arm to a scratch directory and asserts both provenance fields against the entry on disk: sectioned_set_key equals the loaded key, and linkage_sha256 equals a digest the test computes itself from that entry's linkage.npy rather than a value the writer hands back. On the entry it loads they read 66c10162f3e37adb2679 and 12ac17b5eb3129a8f3f01cb065c892b57b37fd9e14cdcee14f52375b9e775440.

Negative control. Dropping the two provenance fields from the np.savez call — a scratch copy outside the repository, only that line removed — reddens the new test alone: KeyError: 'sectioned_set_key is not a file in the archive' at the assertion, 1 failed, EXIT=1, on a test id the head arm passes. The fields are load-bearing for the check rather than decoration on it.
