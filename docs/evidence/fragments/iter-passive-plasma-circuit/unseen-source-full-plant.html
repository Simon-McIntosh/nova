An unseen plasma source reaches the sectioned-set cache, and the plant build stops one layer past it

landing: the sectioned-set cache was exercised with sources the plant cache has never seen. Both real entries were copied to a scratch cache root and the build wrote geometry.npz there at their unchanged keys, with linkage.npy and system.npz byte-identical before and after; load_sectioned_machine then assembles the full 1,607-filament ITER machine from that copy, and an entry with the geometry removed is refused by name. The plant build itself, which is where these sources were to be driven through coupled_plant, stops on a defect one layer past the loader, in a module outside this node's write fence. The two DINA arms and the reconstruction-tolerance arm are therefore not met and are reported as not met.

The cache root is written, not rebuilt. The copy of each real entry (68df15665ab2ea45f427 at 12 mm and 06ff06d3eb7a4448f0fe at 6 mm) was handed to scripts/iter_sectioned_conductor_set/build.py, which wrote geometry.npz into the existing entry directory at the key that already covers every geometry input. Measured in scratch/part1_report.json: for both entries the sha256 of linkage.npy and of system.npz are identical before and after the run, and each entry gains exactly one file, the geometry, whose sha256 is recorded there. The plant cache under coupled-plant/ is listed with sha256 and mtime, the pinned entry 28148563521d92a2198b/plant.npz included; neither DINA case nor the reconstructed pulse has an entry, which is what makes them unseen.

A new source cannot drive an entry whose geometry is gone. The literal negative control copies the real 12 mm entry, unlinks geometry.npz, and drives a DINA 105069/3 source at it: load_sectioned_machine raises SectionedGeometryMissing matching geometry.npz rather than rebuilding the sectioned set or serving a reduced machine. Passed at head in 97.25 s; log at scratch/negative_control.log.

The plant build stops in nova/imas/prescribed_plasma.py. Driving DINA 105069/3 through coupled_plant on the cached machine reaches plasma_linked_flux_history (nova/circuit/coupled_plant.py:304) and then plasma_linked_flux (nova/imas/prescribed_plasma.py:98), which raises ValueError: polygon circuit 828 has no quadrature points. The function grids a polygon's bounding box at section_spacing=0.05 capped at section_n_max=8 and refuses when no grid point lands strictly inside; a subdivided passive filament is thinner than that spacing, so its box admits no interior point and the refusal is correct by the function's own rule. This is a property of the sectioned machine the cache supplies — every sectioned passive circuit is now a polygon of that kind — so it is the sectioned-set path that exposes it. Full traceback with the serving nova.__file__: scratch/probe_time.log. nova/imas/prescribed_plasma.py is not in this node's write fence, so the repair is handed on rather than made here.

Three review follow-ons are repaired. The plant's dimensions are counted against the fixture's own inputs (SMALL_COIL_NAMES, SMALL_SECTION_COIL) rather than against the machine the loader returns, since comparing a plant with the machine it was built from cannot show that either carries the right number of channels. The zero-rebuild spy walks sys.modules and replaces every attribute that is subdivide_passive_thickness or circuit_linkage_matrix, asserting the bound set is non-empty, so the count no longer reads a false zero while a live binding survives in another module. And conductor_geometry in scripts/iter_vessel_evolution/evolve.py is renamed sectioned_conductor_geometry with its single caller updated: its first return element was the unsectioned source winding when the function rebuilt the geometry, and is now the refined sectioned set the loader exposes as subdivision, so the old name promised the caller something the return no longer held. The sibling fragment for the cache node names the older spelling.
