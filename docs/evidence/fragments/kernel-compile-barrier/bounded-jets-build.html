The point program exists twice, and the two forms differ

The owner is _source_jets at nova/equilibrium/fixed_points.py:323, whose batched program is _row_program at :524. The prototype copy is _source_jets at scripts/prototypes/read_route/jets.py:229. Both functions are 60 and 57 lines; the only textual difference is the sharing of the gradient's value:

owner:  def gradient_with_value(target):
            value, gradient = value_gradient(target)
            return gradient, (value, gradient)
        hessian, (value, gradient) = jax.jacfwd(gradient_with_value, has_aux=True)(point)

copy:   value, gradient = value_gradient(point)
        hessian = jax.jacfwd(lambda target: value_gradient(target)[1])(point)

The owner already carries the auxiliary-reuse form, so the copy is the older shape. Neither file contains a lax.scan or any other term-order scan: the program that compiles at 217.9 s and 267,438 post-splitter instructions on the H200 (§3's stated base, ordered-sharing) is the unrolled form in both files, and the §3 levers named in the plan — a fixed-capacity scan over the term order, then a cheaper regular Hessian at corner heights — have not been applied to either.

Cutover risk to settle before the copy is deleted

The operator bank rows that exist today were built by the copy's form, and the owner's has_aux form differentiates the same value_gradient closure, so the two are expected to agree; the tree carries no test that compares them, and this node could not add one inside its fence. The migration needs a byte comparison of the two jitted programs on one coupling; the two blocks above already show the exact source shapes to compare.
