Classification and recommended repair

Class A — the 300 s default timeout, not a value (11 of the 14 edge failures). Five test_tangent_compiles_within_bound rows, three test_truncated_tangent_fails_identity rows and three test_tangent_matches_base_jvp rows fail with a bare Failed: Timeout (>300.0s) from pytest-timeout: no assertion executed and no measured value was produced. The log carries XLA's own alarm for one of them, The operation took 7m52.731798174s, so a single CPU compile of the base JVP rule exceeds the whole per-test budget by 1.6 times. pyproject.toml sets timeout = 300, and the sibling module in the same suite already overrides it for the identical row: tests/biot/test_elliptic_tangent_recurrences.py:466 puts @pytest.mark.timeout(1800) on test_tangent_compiles_within_three_primals. The edge module's compile row (test_edge_term_tangents.py:319-321) and its three SLOW_IDENTITY_ROWS carry no override, so they inherit 300 s while each runs 21 fresh cache-disabled compiles (seven repeats of three arms) or one 472 s compile. This is a test defect, and the bound it asserts is not implicated: the ratio was measured at or below 3 for all fourteen rows on the H200 on 2026-10-08 (docs/evidence/fragments/converged-forward-solve/cfs-edge-term-tangents.html). Recommended repair: add @pytest.mark.timeout(1800) to test_tangent_compiles_within_bound and to the three slow identity rows, matching the sibling module; the gate is then the ratio, and a CPU arm that cannot finish is reported as cut short rather than as an assertion failure.

Class B — an exact bound asserted on a device that does not reproduce it (test_tangent_matches_base_jvp[second_residual]). The row measures 3.370e-12 against the 1e-13 EXACT_TOLERANCE, with 0.9996 of the 10 000 samples inside it: four samples of one domain. The same row is exactly zero on the H200 — 0.000e+00, covered fraction 1.0000, in the 2026-10-08 H200 record cited above — and the same fragment records this row's CPU behaviour as 1.720e-9 maximum with 603 samples over 1e-13. The bound is therefore attainable on one device and not on the other, and the CPU figure moves between runs because it is round-off. This is a device-qualified bound. Because the plan's decision of 2026-10-06 forbids relaxing the identity tolerance without the lead, the recommended repair is not a lowered number: run the exact rows where the exact bound holds (the H200 lane) and record the CPU arm's measured maximum beside them as a device-qualified figure, leaving the 1e-13 assertion intact on the device that reproduces it. Changing the CPU bound needs the lead's ruling.

Class C — a hand tangent left behind by the primal it differentiates (test_tangent_matches_base_jvp[flux_line_moments]). The row measures 1.021e-03 against 1e-09, with 232 of 10 000 samples over. Nine orders of magnitude above round-off is not a device effect, and this row is also exactly zero on the H200 in the 2026-10-08 record. Between that record and this measurement the flux-moment primal was rewritten three times with no tangent line changed: b54a1af9b (2026-10-11, "accumulate flux moments in local source coordinates", 291 lines of nova/biot/polygonanalytic.py), c805c781a ("form only the elliptic combination used by flux") and 44345de22 (2026-10-12, "resolve angular peaks in polygon flux moments", the near-target graded quadrature in _flux_area_rule and _flux_area_integral). Each of the three touches zero lines of _EdgeScalar, _EdgeReductionTangent or any *_tangent function (git show <commit> -- nova/biot/polygonanalytic.py | grep -cE '_tangent|_EdgeScalar|_edge_' returns 0 for all three). The tangent under test is _edge_flux_line_moments_tangent at nova/biot/polygonanalytic.py:3769; it consumes the construction fields of the current _Edge/_Vertex while the identity compares it with jax.jvp of base revision 716d859f, so a construction or quadrature change alone breaks the row. This is a product defect in the sense that the tangent no longer differentiates the program it is asserted against; the H200 column of the table decides whether the discrepancy is device-independent, which the 1e-03 magnitude predicts. Recommended repair: re-derive _edge_flux_line_moments_tangent (and, because it shares _EdgeReductionTangent, _edge_flux_and_moment_terms_tangent at nova/biot/polygonanalytic.py:3814) against the current construction and confirm the 10 000-sample identity, or repoint the identity's base revision at the commit that rewrote the primal so the row measures a change it actually covers. The first is the repair; the second only clears the red.

Class D — a stale strict expected failure (test_near_edge_tangent_meets_reference). The test is marked @pytest.mark.xfail(strict=True) at test_edge_term_tangents.py:449 with the reason "the differentiated graded edge quadrature near endpoints leaves the exact integral's tangent (measured maximum 5.160e-7 relative)". At main it passes its own assert hand.max() <= SCAN_TOLERANCE, so strict xfail reports XPASS(strict) and the file is red on a guard that is satisfied. The 5.160e-7 in the reason is the 2026-10-08 figure from the fragment cited above, and the near-target angular quadrature repair 44345de22 (2026-10-12) is the change that would close exactly that gap. This is a test defect: the marker outlived its measurement. Recommended repair: delete the xfail marker so the row asserts the 1e-9 agreement it now meets, and carry the measurement history in the commit body. Do not relax SCAN_TOLERANCE.
