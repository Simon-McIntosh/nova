The pinned entries are split across two runtime directories, and no consumer resolves both. The runtime key hashes the compiler options including jax_enable_x64, so a process that enables extended precision before it configures the persistent cache resolves runtime-dfec7ea6a46f05232fe7 while one that configures first resolves runtime-d23b975337df890821f8. Every one of the four expensive programs (jit__source_jets-…, 332.0/345.0/328.0/328.0 s and 11–12 MB each) is in dfec; all of their helper programs are in d23b. The point-program driver resolves dfec and hits; a pytest process resolves d23b and therefore misses the point program while hitting its helpers. The pin payload does not paper over this: PREWARM_SERVED_ENTRIES=6270 counts d23b alone, so the entry the pre-warm exists to add is outside the count it reports. The census read below is therefore served from a job-local copy of both directories, which is what proves the pinned entries sufficient without writing the pinned root.
