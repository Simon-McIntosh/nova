CUDA executable-graph lifetime across distinct programs

One Titan job measured XLA's own graph creation and destruction counter while compiling twenty distinct shapes, then dropping executable handles and clearing caches.

The count is executable-scoped, not process-cumulative

The enabled arm held exactly one alive executable graph at every completed-program marker: 1 at program 1, 1 at program 20, and zero growth over the ladder. The runtime transiently reached 2 while replacing a graph, then destruction returned it to zero. Dropping 10 of 20 executable handles and clearing JAX's compilation caches changed the count from 1 to 0. The disabled-command- buffer arm completed the same twenty programs with zero graph-count events. The positive arm emitted 418 count observations, so the control's zero is distinguished from a silent instrument.

The production failure at 1,669 alive graphs therefore does not read as one retained graph per program ever compiled. It instead points toward graph multiplicity inside complex solve executables or production references retaining many active instances. This node records that distinction and writes no repair.
