Standing-suite declaration

What landed. Nova's project flight layer docs/state/nova/flight.yaml now declares review.suite as the one command [bash, scripts/nova_lane/standing_suite.sh] under a 3h whole-run budget. The wrapper scripts/nova_lane/standing_suite.sh runs every collected test file in a fresh pytest process, routes the files whose measured CPU wall exceeds ten minutes through scripts/nova_lane/run.sh to the H200 rung, keeps -m "not slow" on the CPU pass, announces any file that could not run as ERROR <file> plus a final N errors during collection, and prints one aggregate pytest-style summary line carrying every category. A --list mode prints the per-file plan without executing anything.

What the design draft said, and what the repository shows. The draft (~/.config/reckon/crew/reports/reckon/s25-coord/nova-standing-suite-draft.md, §4) routed seven files with CPU-wall figures drawn from ledger rows, and named the routing threshold from the project's own lane policy. Checked against the repository at HEAD 9a7af04e2:

  • All seven routed files exist: tests/test_connectivity_boundary.py, tests/test_equilibrium_forward_solve.py, tests/test_equilibrium_forward_reference.py, tests/test_steering_frames.py, tests/test_topology_boundary.py, tests/test_jax_topology.py, tests/test_solve_receipt_topology.py.
  • A record newer than the draft's citations changes one figure. tests/test_equilibrium_forward_solve.py carries test_the_accelerator_routes_agree_on_the_fixed_point (line 591), measured at 4649 s CPU / 749 s H200 in S21 run r-20261002T084121851662, merged at db580bec8. The draft predates it. The file stays routed — the single test alone exceeds the draft's whole-file >59 min figure by 18 min, so routing it is confirmed rather than relaxed.
  • The draft's §4.3 claim that the routed files' H200 walls are "not recorded anywhere I could find" is now false in one instance: the accelerator-routes test's H200 wall (749 s) is recorded, so the evidence fragment corrects the claim rather than repeating it.
  • The target arithmetic is corrected. The draft wrote 545 targets (538 tests/**/test_*.py + 1 tests/**/*_test.py + 6 testpaths doctest modules). At the draft's head those two globs describe 538 files, not 539, because tests/test_moment_path_separatrix_test.py matches both and is one file, so the union was 544 targets and 537 CPU sessions. At HEAD 9a7af04e2 the union is 539 test files (the guard file this node adds is one of them) plus 6 doctest modules = 545 targets / 538 CPU sessions after the 7 routed. The wrapper's --list prints exactly cpu_pass_files=538 and h200_routed_files=7.
