Benchmark receipts come from the caller

Forty-five benchmark modules and four supporting scripts carried 61 absolute paths into ~/.config/reckon/crew/reports or ~/.config/reckon/crew/runs. Both are reclaimed: a crew report resolves only while the run that wrote it is live. Every one of those literals now resolves through benchmarks/receipt_locations.py, which reads NOVA_CREW_REPORTS or NOVA_CREW_RUNS and raises under the variable's own name when the location is unset. The accessor is not a resolver: it joins one caller-supplied root with a repository-relative tail, keeps no default, rewrites nothing.

The path resolves on first use rather than at import, because 171 test modules import a benchmark module to reach one of its functions and must import without the environment set: all 47 changed modules import cleanly with both variables unset. Three sites that had derived a second location from a first (with_name, parent) were respelled as their own caller-supplied path so no derivation forces resolution at import. No benchmark changes what it computes, and none gained or lost a receipt it was reading.

grep -rnE "\.config/reckon/crew" benchmarks/ scripts/run_amplitude_census.sh scripts/media/efit_nova_overlay.py scripts/labeller_batch/shard.py scripts/analytic_oracle_fixtures/ --exclude-dir=prototypes returns 61 lines at 624860447 and 0 lines at dff94725f. No docstring was kept: every hit was code that read or wrote the path.

tests/test_evidence_tooling_paths.py runs that scan and fails naming each offending line. It carries its own positive control, because a scan that finds no file reports a clean tree for the same reason a clean tree does: the pattern is proved against text known to carry both prefixes and the candidate list against benchmarks/receipt_locations.py. Scripts under scripts/prototypes/ are outside this node's scope and are excluded. The scan carries the worktree root name beside the crew prefix; this record does not spell that name, because the repository's own worktree check refuses any file that does, which is why the test composes both patterns from joined pieces.

Gate: the eight test modules importing a changed module, one fresh pytest process per file, four at a time, as one sirius job (1297670). The base arm ran at 624860447 from a git archive and the head arm at dff94725f from the worktree; each per-file log records its arm, tree, revision and the resolved nova.__file__, and every file ran to its summary line. Base reports 7 failure ids, head 2; nothing present at head is absent at base, so the change adds no failure. The two remaining head failures are pre-existing: test_exact_clip_moments and test_labeller_parallel fail in both arms, the latter with 4 failures at base and 1 at head across the same 11 tests.

Negative control: one absolute crew report path restored in a scratch copy of benchmarks/ makes the scan fail naming benchmarks/sample.py:1 and exit 1; the same file passes in the worktree-side test file, whose own arm logs 1 failed at base and 1 passed at head.
