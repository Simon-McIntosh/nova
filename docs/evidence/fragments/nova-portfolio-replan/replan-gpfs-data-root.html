Removed rather than routed. nova/imas/mast_fitted_parameters.py carried VACUUM_COHORT_STORE, an unused string copy of the level-1 store; it is deleted. nova/utilities/IO.py carried a dead qsub helper, with no callers anywhere in nova/, scripts/, apps/ or tests/; it named a remote home and an anaconda interpreter, names a tool rather than data, and is deleted with its now-unused subprocess and shlex imports.

Audit. grep -rn "/work/projects\|/home/ITER\|~/" nova/ --include=*.py now returns literals only inside nova/database/filepath.py (the named-root defaults, plus the ~ in the worktree-path character class, which is a regex, not a path). Three further hits are in nova/equilibrium/solve_request.py docstrings, which describe the forward-compilation cache's location in prose; that module is outside this node's write scope and is listed under outside_scope.

Measure. A new tests/test_filepath_data_roots.py has 24 tests. At head it passes (24 passed in 18.93s, run in the worktree); at base it cannot collect the FilePath accessors and fails with AttributeError: module 'nova.database.filepath' has no attribute 'mast_level1_shots', 2 errors in 2.78s. The tests pin all three properties the root contract requires: each named root resolves through FilePath, each honours its environment override, and each keeps its former literal when the variable is unset.

Both arms completed all 38 files. Base arm: 5 failed files, EXIT=5. Head arm: 3 failed files, EXIT=3. No file fails at head that passes at base. The base-only failures are the new test (by design: it imports accessors that do not exist at base) and test_artifacts_carry_no_worktree_paths.py, because a git archive carries no .git. The head arm's single test_filepath.py failure passes standalone in this worktree at head (45 passed, 3 skipped) and did not appear in the first arm pair, so it is read as a race under eight concurrent git-touching processes; the gate records per-file summaries rather than failure ids, so the test id is not claimed here. The slowest file, tests/equilibrium/test_topology_read.py, takes 32 min in the base arm and 30 min at head on its own, which is why the arms ran concurrently and why the earlier 14-file subset understated the set. The scheduler records the job as OUT_OF_MEMORY from the node's own pressure after both arms had printed GATE-DONE; both arm logs are complete and end in their EXIT= line.

The first arm pair (job 1297775) completed all 38 files with the same per-file outcomes, but an edit to that job's two log headers rewrote the files down to the header alone, so their per-file bodies were unrecoverable. Rather than reconstruct them, the arms were re-run as job 1297841 and its logs are the evidence cited above; the destroyed files are kept beside them as gate-full-*.log.headeronly-lost.

Provenance stays portable. nova/calibrate/sweep.py records each correction set's evidence location in the document it writes. Routing that path through the cache root produced an absolute per-user home directory in the written YAML, which is a statement about one workstation rather than about the evidence. The resolved path is what the code opens; the written document carries the portable ~/.cache/nova-mast/vacuum-signatures/archive/signature_series.npz form it carried before, produced by filepath.portable_path rather than by a literal at the site.

One override idiom. operand_cache_root and the named-root accessors had each spelled the same three-line environment-override pattern; both now resolve through filepath._env_root(variable, default), and tests/test_filepath_data_roots.py still pins every default and every override, so the consolidation is behaviour-preserving by construction.

Route coverage. Two routes had no test that would notice their literal being restored: the sweep provenance site and Connect.rsync's public imasdb tree. The first is pinned end to end — a chunk is measured, written and merged, and the written recorded_corrections.yaml is asserted to carry the portable form and no home directory. The second is pinned by parsing rsync's body and asserting it names public_imasdb_root and no /home/ITER literal, because nova/imas/connect.py imports fabric, which the shared environment does not carry, so the module cannot be imported to be called.
