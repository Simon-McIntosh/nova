Delete the unused h5py reader of IMAS-written HDF5

nova/imas/hdf5_read.py opened IMAS-written HDF5 directly through h5py, bypassing imas-python, and had zero callers. IMAS data is read only through imas.DBEntry, so the module is deleted rather than routed (commit c326a7653).

Caller search, before and after

$ grep -rn "hdf5_read" nova/ tests/ scripts/ benchmarks/
(no output; exit 1)

The search is quoted with its command. The same command was run before the deletion and after it, returning exit 1 with no output both times: nothing in the product tree, the tests, the scripts or the benchmarks names the module.

Remaining h5py imports under nova/

$ grep -rn "h5py" nova/ --include=*.py
(none: the only match in the whole package was the deleted line)

No module under nova/ imports h5py at all, so there is no h5py read of IMAS data and no non-IMAS h5py read to list.

Two-arm suite gate

Every test module importing nova.imas (103 files) runs as one fresh pytest process per file with a separate --basetemp, base and head arms concurrent in one sirius job, no timeout around any arm. Logs: <run>/gate/base-suite.log and <run>/gate/head-suite.log.
