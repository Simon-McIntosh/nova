Terminal-state analytic-panel draw-order guard

Adds tests/test_plasma_cell_terminal_state_draw_order.py, a committed pytest that renders the terminal-state figure from the committed receipt docs/figures/plasma-cell-read-fidelity/terminal-state-trip-arms.json with no solve and asserts, on the pixel census the benchmark computes from that render itself, that the small panel-state markers do not overpaint the large reference markers on the analytic panel.

The guard renders through render with no draw_order argument, so it reads the committed default rather than a value the test supplies, and it asserts that the CLI's --draw-order default agrees with render's default so the two cannot drift. To express that, benchmarks/plasma_cell_terminal_state.py gains one module-level DEFAULT_DRAW_ORDER feeding both render's signature and the CLI, and the argument parser moves into build_argument_parser() so a test can read it. The change is behaviour-preserving: a re-render of the committed figure from the committed receipt is byte-identical between the base revision and this one (sha256 9cc670c1 … both; the committed PNG blob differs for environmental reasons only, so the refactor's own effect is the base-vs-head comparison). The benchmark's census needed no extraction, so no committed figure was re-rendered.

Measure (fleet allocation node cn 98dci4-clu-2018, job 1277272, TMPDIR=/tmp, JAX_PLATFORMS=cpu, no solve). Under the committed default the analytic panel of case 0 (diverted-single-null) reads reference_pixels=675, panel_pixels=0: the reference markers are present and detected (675 px, so the box is a positive control that the instrument sees known-present paint) and no panel-state pixel lands on them. pass.log (2 passed, EXIT=0).

Negative control 1 (explicit; declared: draw the panel-state markers after the reference markers; the overpaint assertion must fail). NOVA_TERMINAL_STATE_DRAW_ORDER=panel-last draws the panel-state markers last; the analytic panel then reads reference_pixels=300, panel_pixels=333, and the assertion fails with AssertionError: 333 panel-state pixels overpaint the analytic reference markers. negative-control-panel-last.log (EXIT=1).

Negative control 2 (flipped default). A scratch copy of the benchmark with DEFAULT_DRAW_ORDER set to panel-last makes the no-argument render pick up the reversed order, and the same guard fails with 333 overpainted pixels while the defaults-agreement test still passes. negative-control-flipped-default.log (EXIT=1, 1 failed, 1 passed).
