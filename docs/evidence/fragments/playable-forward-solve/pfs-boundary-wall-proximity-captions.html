Separate the two boundary-wall-proximity panels and bind every caption number to its receipt

The two boundary-wall-proximity panels under docs/figures/playable-forward-solve/boundary-routing/ were served in docs/evidence/archive/playable-forward-solve-landed.html under one identical caption — “boundary-wall-proximity. Recovered from worktree pfs-boundary-routing at 6ab5ae30” — while the two images state opposite results, so a reader could not tell which sentence belonged to which panel nor which census is current. This record gives each panel its own caption naming the gate that produced it, and every number in each caption is written as a named JSON path resolved in the boundary-wall-proximity.json beside that panel.

The driver that draws these two scatter panels is imas_ambix.worldmodel.boundary_wall_proximity.write_figure in the imas-ambix repository, outside this node's write scope; the panels are not poloidal flux maps, and the panels' own data are correct (each panel's numbers re-derive from its receipt). The repairs the driving followup names are caption-level — separate the shared caption, date the two censuses, and state that the diverted group is empty — so no panel is re-rendered here. The two panels are drawn from the same pfs-boundary-routing session and the same source revision, once without and once behind an explicit branch guard, and the gate that differs is named in each title below.

Which census is current

The explicit-branch-gate census is the current one and the non-gated census is superseded. The gate census was generated later (17:49:16Z against 17:11:13Z) and its boundary-to-limiter distances are non-degenerate, while the non-gated census reports every one of its eleven distances as data value .aggregate.all.boundary_to_limiter_distance_mm.maximum = 0.0 mm. A census that reads a uniform zero column cannot distinguish measured tangency from a measurement that collapsed, so it is dated and withdrawn rather than carried as the current result.
