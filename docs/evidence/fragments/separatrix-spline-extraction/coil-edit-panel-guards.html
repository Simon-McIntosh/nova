Guards behind the coil-edit panels

Four review findings said the coil-edit panel checks could not fail on the defect they claimed to guard. Three compared the build against its own reported outputs: the nearest promoted node was measured to the saddle coordinate the build chose, the saddle offset likewise, and the promoted count was read back from the same mask the build had already truncated. The fourth was the truncation itself, promoted_nodes[:node_count], which discarded the tail of a state-wide mask with nothing asserting what that tail was. This node replaces those comparisons with checks computed from the published field and the solve's own mask, and refuses a mask whose discarded tail is not the operator's non-lattice rows.

The state vector a solve returns carries its wall rows after the plasma lattice: the committed forward-solve-api panel archive holds a 1,126-entry promoted mask against a 1,089-node lattice, the difference being the archive's 37 wall rows. The map counts only the lattice prefix, so the guard is that the discarded tail's length is that wall's row count: _wall_rows reads the operator's wall coordinate count, and when a mask does discard rows the builder raises if the discarded count differs, or if the operator exposes no wall coordinate at all. The check compares counts, not row identity: it catches a mask whose discarded rows are not the wall, and it does not claim to prove which rows they are. A lattice-length mask over a state-wide state discards nothing and is accepted without the check running, which is how the producer scripts call it.

The caption control reddens at the second assertion, not the canvas-size one: assert 'terminal poloidal flux' not in '<?xml versi...s>', with the text present in <!-- terminal poloidal flux on shared levels -->. Restoring the suptitle leaves the 1,400 by 720 canvas unchanged, so the size guard passes and only the caption guard can catch it.

Profiling the committed-panel test found that the machine build, not the display map, carries the cost: _prepare_case takes 773.6 s against 17.2 s for the archive load, and the full-resolution map over 195 by 401 points adds a few hundred more. The repository's default pytest timeout is 300 s, so no test that builds the machine can be a normal test at all: the committed-panel test reached its own 3,300 s ceiling even when it was the only load on the allocation (1 failed, 56 passed in 3,671.29 s, Failed: Timeout (>3300.0s) from pytest-timeout, about 7.1 cores and 4 h 40 min of CPU). The promoted count and the saddle polish are therefore read from the committed archive and receipt alone, which costs 20 s, while the full-resolution render keeps its size, branch and receipt checks and stays marked slow so the default gate does not run it.

The focused gate ran at the base revision and at the head in the assignment's CPU lane, over tests/test_coil_edit_panel_render.py, tests/test_display_flux.py and tests/test_flux_surface_connectivity.py, with the slow marker deselected exactly as the default lane does.
