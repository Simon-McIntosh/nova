This establishes the executable capacity boundary but does not resolve a speedup under that decision rule. The 1 ms/slice throughput target remains unmet. The async arm was requested as one extra process: it has no fresh-process agreement estimate, and its 0.9039% lower cost than the default width-78 mean does not justify an allocator-default or speedup decision.

Width means independent pulses or ensemble members, each advancing its own current slice. TORAX-coupled slices within a single pulse remain sequential. Thus 451.149 ms is the batch latency at width 78; 5.783966 ms/slice is aggregate throughput cost, not a reduction of that pulse's causal latency. The driver reuses the common sixteen-member root population cyclically, advances three drive steps of 1e-5, and times the third slice with a secant predictor. This is a homogeneous flattop fixture, not a measurement of mixed topologies or the TORAX coupling itself. Every executed lane took two counted reads and one Newton update.

Compiled admission and runtime allocation are distinct

The allocator limit is 112.585605120 GB. The driver reserves 10%, yielding a compiled-memory ceiling of 101.327044608 GB. Compiled working bytes are temporary + argument + output − alias bytes, not a measured peak of all live device allocations. Widths 79, 80 and 96 pass this guard but fail when the executable requests a large temporary alongside other live buffers. Their logs respectively report requests of 72.91, 73.83 and 88.60 GiB. A representative refusal is:

jax.errors.JaxRuntimeError: RESOURCE_EXHAUSTED: Out of memory while trying to allocate 88.60GiB. [executable_name='jit_solve']

The probe classifies only the witnessed JAX runtime allocation error as runtime-oom; unrelated process errors still fail the probe. Width 256 exceeds the compiled ceiling and exits 77 without execution, supplying the required negative control. Width 64's completed solve and precision checks supply the positive control. The retained-receipt classifier check also changes the runtime error category and verifies that it is rejected as an unrelated failure.

At width 96, setting TF_GPU_ALLOCATOR=cuda_malloc_async permits execution under the same reported allocator limit and compiled working bytes. Both width-96 arms have optimized HLO SHA256 699fa5548431f7e73b18e05b0cbde32f07d2dac6d5ce16d8b350080e1d69f946. The result concerns runtime allocation, not a changed arithmetic program. The logs do not separately measure peak residency or apportion the default refusal between live-buffer occupancy and fragmentation.
