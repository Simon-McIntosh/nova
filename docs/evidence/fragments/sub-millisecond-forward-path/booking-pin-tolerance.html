What changed

tests/test_bank_step_booking.py::test_book_primal_keeps_exact_diverted_moments pinned the SHA-256 digests of the six booked arrays for two CPU families. The digests are red at the base revision because the same case now produces different bits on the same CPU, so the pin measured bit identity rather than the result.

The test now asserts each booked field against reference arrays stored in tests/data/booking_primal_diverted.npz, within 1e-12 relative. Fields with exact zeros and sign changes (cell_current, the two moments) use an absolute floor of 1e-15: the fields peak between 1e-3 and 1e-1, so the floor sits far above the roundoff a reordered sum leaves on a zero entry and far below any entry carrying a physical contribution. valid is boolean and compared exactly.

The reference arrays were written from the diverted case at revision b48deaa93f55ad2c759c5977ed611b9047e393fb on the CPU lane; the command is recorded in the test docstring. The digests survive only in the failure message, so a red run names the field that moved without pinning bits.

Controls

Perturbation (fails as required). Scaling the reference radial_moment by 1 + 1e-9 in a scratch copy of the tests tree gives FAILED tests/test_bank_step_booking.py::test_book_primal_keeps_exact_diverted_moments, 1 failed, exit 1.

Bit-only reorder (not produced). Four reorderings of the same terms — a reversed reduction, a reversed quadrature integrand (a tangent-only path, so invalid), a strided-half split, and a sequential fori_loop accumulation — all returned bit-identical booked arrays on this path. XLA canonicalises the floating-point reductions here, so a reorder in the booking cannot be made to move the bits, and the tolerance is therefore not exercised against a genuine reorder. The control is reported unmet rather than substituted: a one-ulp perturbation would show the test admits roundoff noise, but it is not the reorder the clause asks for.
