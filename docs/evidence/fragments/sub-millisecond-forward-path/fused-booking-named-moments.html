The fused booking seams read booked moments by field name

Fusing primal moments and assembly channels into one conic traversal left two seams reading the moment triple by position: _normalize_booking summed moments[0] for the current channel, and book_and_local_sensitivities handed the positional slice raw[:3] of a Booking back to it. Field order was therefore an unnamed invariant, and a reordering would have booked the radial moment as the current with no field name and no test to say so. Both seams now read and rebuild the named fields of the existing moment and booking types: the current channel is read as moments.cell_current, and the Booking returned by _normalize_booking is built field by field. No container was added; the moment order no longer decides anything at either seam.

The plan's own moment primitive was left alone: the channel axis of the stacked array inside the fused traversal is the clip-quadrature channel layout, not the booking field order, and it is not read at either seam.

A reordered moment triple no longer changes the booking

tests/test_fused_booking_assembly.py builds the moment triple with the current channel last and asserts the normalized booking is identical to the same moments supplied in field order, and that raw_current is the sum of the current channel.
