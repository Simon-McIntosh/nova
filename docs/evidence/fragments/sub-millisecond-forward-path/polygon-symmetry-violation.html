A value displaced from its own one-sided limit

On the up-down plane the packed reduction returns a Z gradient that its own two-sided limit does not have. The two branches offered as suspects are excluded by construction: turning off the corner-height stencil and turning off the joint corner layer leave every booked value bit-identical, and enabling the stable pole product on the value row moves the largest violation from 6.06230122870705e-6 to 4.546725922061994e-6 without removing it. What remains is a one-sided comparison: at node 1770 the booked gradient is 4.54672592175249e-6 at +1 nm, -4.546725921491127e-6 at -1 nm, and 6.06230122870705e-6 at zero. The offset pair is odd, so the limit at the plane is zero — which is what up-down symmetry demands — and the value at exactly zero is displaced from that limit by the whole 6.06e-6. The file contains exactly this kind of branch, an exact-equality special case on the corner level whose comment at polygonanalytic.py:612 says the configuration is evaluated "rather than approached". The measurement says the value taken at exact equality is not the limit it was written to be. Which exact-equality comparison produces it is not established here: the small-corner arc's own selector at :425 belongs to the band the no-layer arm excludes, so the search for the comparison that fires at these targets is the next step, not a claim of this node.

Group B: neither kernel's values are correct

The independent reference is a central difference in Z of the kernel's own flux row, taken on the head tree whose flux row is bit-identical to the base kernel's. Its step-convergence envelope on the eleven-step ladder ends below 3.0e-12 for every group-A entry, and for group B it converges to a median 3.212122448040574e-07 with a largest value 4.921537812515756e-07. Against that, the booked values are a median 2.570816423826914e-06, and the worst entry differs from the reference by a relative 74.76. The base kernel's exact 0.0 is a defect — the flux row does move with Z at those nodes — but the repaired values are not that derivative either: they are larger by roughly an order of magnitude and do not follow the reference. Two conclusions follow. The base zeros were a dropped contribution, not a cancellation. The repair replaced a dropped contribution with a value the kernel's own flux row does not support.

The receipt does not reproduce its own base column

At the receipt's own coordinates the base kernel and the repaired kernel return the same group-A values (6.06230122870705e-06 in both), while the receipt records base values near 3e-16 for those entries. Only 9 of the 23 violations reproduce as the receipt's head_value through this route; the remainder match other sweep offsets. The booking route here is the one nova/equilibrium/fixed_points.py::_source_jets uses — the nine packed rows, the 2πr(B_z, -B_r) gradient and the same einsum("cbq,cbm->cmq") against the inverse second moment — so the disagreement is in the receipt's recorded route or its staleness, not in the reproduction of the split, which matches to the last digit.

The smallest change, and what it costs

A target exactly level with a corner already has an exact symmetric construction in this file: on the cell's reflection plane the flux channel builds its vertical row from the reflected edge pairing (reflected_vertical, applied under on_reflection), and the field rows have no such construction. The smallest supporting change is to extend that existing where(on_reflection, …) to the basis-1 radial field row, so the booked Z gradient on the plane is the exact symmetric value — zero — instead of the exact-zero branch's value. That removes all 23 group-A violations by parity, and it cannot touch group B, whose nodes are off the plane and therefore never select the branch.

Cost is bounded by the mechanism: the flux channel already forms pair_weight * (edge_flux + partner_flux) over the live edges, so the same reduction for the field terms is one more weighted sum over per-edge field values that are already materialised in the graph, plus one where on the returned row. It adds no program to the compiled set. Estimate: instruction count within 1% of head and cold compile wall unchanged within noise, to be measured if the change is implemented. The measured anchors are the production row's 1.565208× instructions and 1.871670× cold compile against main, both inside the unchanged 2.3 limits of polygon-stable-evaluator.html.

Two limits are stated plainly. First, this is a construction fix rather than a limit fix: the honest repair of the branch would evaluate the ordinary expression at level == 0, which requires proving the ordinary expression is finite there, and this node did not attempt it. Second, group B remains wrong after the change; the near-corner field rows disagree with the flux row's own derivative by up to 74.76 relative off the plane, and that disagreement is a separate defect that survives the repair.
