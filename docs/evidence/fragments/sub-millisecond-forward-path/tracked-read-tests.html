Two test gaps in the tracked read

The carried-decision review left two findings that were test gaps, not product defects. Both are closed in tests/test_tracked_read.py with no product change: a certificate request is now observed to execute the whole-mesh topology read, and a limited-contact case now requires a rebuild when the wall-contact winner changes.

The certificate path reads the whole mesh

The previous certificate test compared continuous geometry at an unchanged state. At an unchanged state a carried result relabelled as rebuilt agrees with a fresh read on every continuous quantity, so that comparison could not show the certificate had executed the full read. The new test wraps topology.read_at_stationary_points, the whole-mesh read, and records each execution through jax.debug.callback. A carry must record none; a certificate request must record at least one, beside the raised rebuilt flag and the incremented counter.

Under control (a), which answers a certificate request from the carried result marked rebuilt with an incremented counter, the test fails on the absent whole-mesh read while both of those reported values still hold.

A limited boundary must rebuild when another wall event wins

Every real-geometry tracking case in the file used diverted_case, where the boundary is the saddle and no wall-event list is formed. Dropping wall_stable from the carried read's validity therefore changed nothing the suite could see. The new case builds the limited reference, performs one full read, and shifts the exterior jets by 0.005 * (-1, 0), which leaves the tracked cell, the fragment links and the cut-cell classes unchanged, so the wall-contact winner is the only support decision that differs from the carried one. The read must rebuild, and a second read at the same state must not.
