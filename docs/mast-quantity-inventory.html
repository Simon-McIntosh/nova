MAST machine description: the quantity ledger, the identified source COCOS, and how many machine descriptions the corpus actually needs

Measured 2026-07-27 over the whole FAIR-MAST level-1 mirror at /work/projects/imas_gpu/mast/level1/shots — 17,111 shots on disk, 14,633 of them carrying readable static setup geometry, 11,154 carrying a converged reconstruction with appreciable plasma current. The driver is nova/scripts/identify_source_cocos.py; the verdict is pinned by tests/test_mastcocos.py (19 tests); the artifact is docs/figures/mast-machine-description/source_cocos_audit.json. Companion to the mast-machine-description plan, whose stage 1 this is.

1. The three results that change the plan

The COCOS-3 hypothesis is confirmed, and one of its stated consequences is not. All four Sauter & Medvedev digits were measured, not assumed: σBp = −1 (unanimous over 11,154 shots), eBp = 0 (measured, not read off a units string), σρθφ = −1 (99.99% of shots), σRφZ = +1 (declared — see §2.4). That is COCOS 3. But the plan's §3 offers "the MAST convention has ψaxis > ψboundary" as a landmark, and it is not one: 379 shots (3.40%) have the axis as a flux minimum while being the same COCOS, because their plasma current and toroidal field are both reversed. The convention-invariant statement is σBp = −1; the extremum is a consequence of the sign of Ip in a given campaign. Any guard hardcoding the flux maximum misfires on those shots.

ψ does not change sign on the way to DDv4, and q does. The prior ambix work identified the MAST-vs-IMAS mismatch as "axis = flux max vs axis = flux min", correctly — against DDv3, which is COCOS 11 (σBp = +1). This plan targets DDv4, which is COCOS 17, and COCOS 17 has σBp = −1 — the same as COCOS 3. The celebrated mismatch evaporates at the DDv4 target: the ψ map is a pure ×2π with no sign flip. What survives, and what nobody had flagged, is the σρθφ digit: q changes sign, so a forward MAST shot authored in DDv4 carries q < 0. That is the live hazard for stage 6, not ψ.

The corpus needs five machine descriptions, not three. The efm fingerprint the ambix tables use — probe and loop positions, probe angles, coil filament centroids and turns, limiter contour — resolves the whole corpus to exactly 3 states, and this audit reproduces ambix's three published digests byte-for-byte. But that fingerprint covers only the active conductors and the sensors. The passive structure lives in a different group entirely (amm array descriptions) and is invisible to it; it carries 3 substantive states of its own, and the two vary independently. The cross product is 5 machine descriptions. None of the five occupies a shot range: one description's span is 87.6% foreign shots.

2. The source convention, digit by digit

2.1 σBp = −1, from two independent reads

Sauter Eq. 23 gives sign(ψedge − ψaxis) = σIpσBp. Evaluated on the peak-current slice of every shot with |Ip| > 100 kA, σBp = −1 with unanimity 1.000 across all 11,154 shots — including the reversed cohort, where both factors flip together. The independent check sign(dp/dψ) = −σIpσBp agrees on 97.2%; the 2.8% dissent is concentrated in slices where the mid-radius median of pprime is small and noisy, not in any coherent cohort. Two different arrays, one digit, no disagreement.

2.2 eBp = 0, measured rather than read

This is the digit a units string would answer, and therefore the one worth measuring. efm/psi_axis declares units = 'Wb / rad' and efm/pprime declares 'Pa-rad/Wb', both consistent with ψ = Φpol/2π. Rather than trust that, the audit uses the fact that a poloidal flux loop physically links the total flux Φ = 2πR·Aφ [Wb] while the flux function ψ = R·Aφ [Wb/rad] does not. Interpolating the reconstructed psirz map onto each loop's own (R, Z) and dividing the loop's fitted flux silop_c by it must return 2π for eBp = 0 and 1 for eBp = 1.

Result: median 6.3007 over 2,662 loop-slices in 60 shots, every one of the 60 per-shot medians within 2% of 2π, and a per-shot interquartile spread of 0.2–0.6% — the bilinear interpolation error on a 3 cm grid. Verified on all three coil/sensor fingerprints separately, so this is a property of the reconstruction code and not of a campaign.

Two things had to be got right for that number to mean anything, and both bit first. psirz is stored two different ways across this corpus: dense on its native (gridz, gridr) grid in some campaigns, and scattered onto a longer shared radial coordinate with NaN in the unused columns in others. gridr is the live radial grid under both layouts; a shot's own profile_r is a different array of a different length and radial span, and pairing the finite columns with it silently produced a wrong grid — a plausible-looking ratio of 0.49 on one campaign and −1.48 on another. Second, a shot whose silop_c is largely unpopulated at the sampled slice yields a ratio scattered over orders of magnitude; such a shot is now rejected rather than allowed to report a meaningless number. The quality gate is what surfaced the grid bug rather than averaging over it.

2.3 σρθφ = −1, and the q sign flip it forces

From sign(q) = σIpσB0σρθφ. MAST's forward configuration is Ip > 0 with Bφ < 0 (the reference vacuum field bvac_val is −0.28 to −0.41 T throughout), and q is stored positive, giving σρθφ = −1 on 99.99% of shots. The single dissenter is shot 15963, whose bvac_val is exactly 0.0 on its peak slice — an unfilled field, not a convention dissent; σBp is −1 there as everywhere.

COCOS 17 has σρθφ = +1, so the same physics expressed in DDv4 requires q < 0 for a forward MAST shot. This is not a knob and not a defect: anything downstream that assumes positive q on DDv4 MAST data is wrong, and test_target_q_is_negative_for_the_forward_cohort exists to say so.

2.4 σRφZ = +1, declared and not determined

Recorded honestly as a declaration, because no combination of scalar equilibrium quantities can determine it. Sauter Eq. 23 cannot distinguish (R, φ, Z) from (R, Z, φ): every toroidal quantity's sign is expressed in the very frame under test, so the question is circular at the level of scalars. What is available is a consistency check — irod and bvac_val share a sign only if both refer to the same φ̂ sense, and they do on 11,153 of 11,153 shots. That is a genuine constraint on internal coherence and it is not a determination. Resolving it needs a signed vector quantity whose frame is fixed externally — a probe's measured BR against a known coil polarity, which is exactly what stage 3's vacuum forward model produces. Until then this digit is an assumption, and it is the only one.

2.5 A limitation in the identification tooling worth recording

imas_codex.cocos.calculator.determine_cocos returns COCOS 3 on the raw efm quantities for 3,999 of 4,000 shots tested, which corroborates the verdict. But its eBp digit comes from a magnitude heuristic — e_bp = 1 if max|ψ| > 0.5 Wb — and that heuristic is unreliable at MAST scale. Applying the 3→17 transform and re-asking gives COCOS 7 for 3,923 of 4,000 shots and 17 for only 76, because after ×2π the median max|ψ| is 0.332 Wb and only 2.5% of slices clear the 0.5 Wb threshold. COCOS 7 is COCOS 17 with the wrong eBp and every other digit right, which is the heuristic failing in exactly the predicted way: a small, low-field machine has small ψ in Weber, and magnitude does not carry the convention. validate_cocos_consistency(declared=17) is unaffected and behaves correctly — 1 of 4,000 inconsistent on the transformed quantities against 3,999 of 4,000 on the untransformed — because Eq. 23 places no constraint on eBp at all. The lesson for the maps: eBp must be measured or declared per source, never inferred from magnitude, and the calculator's other three digits can be trusted.

2.6 The transform, and the DD's own taxonomy for it

Composing the digits — σeff = σinσout per digit, eeffBp = eout − ein — gives σeffBp = +1, σeffRφZ = +1, σeffρθφ = −1, eeffBp = +1. The DD publishes its own transformation-type tags per field, and the four factors land on them exactly:

Because σeffRφZ = +1 rests on the §2.4 declaration, every ip_like and b0_like factor above is conditional on that declaration — those are precisely the rows a wrong σRφZ would flip. The ψ and q rows are not: they carry σeffRφZ too, so a σRφZ error would move ψ and q as well, and the loop-flux round trip in §2.2 would catch it. Stage 3 closes this.

Description #4 is the load-bearing one: it is the 938-filament coil set carrying the other campaign's passive state, 93 shots scattered through #3's span. It is not a boundary effect — it is a genuine point in the cross product, and it exists only because the two fingerprints move independently.

Two coverage facts bound what any registry can promise. 4,508 of the 14,633 fingerprinted shots (30.8%) carry no parseable amm passive description at all, so their passive state is unresolvable from the source and must be either inherited from a neighbour by explicit rule or excluded — it cannot be assumed. The probe-angle gap deserves its own sentence, because of the ten it is the one that can corrupt physics rather than merely block a map. magpr_ang sets the BRcos θ + BZsin θ projection every magnetics forward model applies; it is tagged pol_angle_like by the DD, i.e. COCOS-dependent; and it is the one MD quantity with no standard name to carry its convention. The catalogue has three of the four (probe family × angle) cells filled and this one empty.

4.3 The two DD gaps

efm/fcoil_xmult — the weight with which each filament shares its circuit's current — has no DDv4 path. DDv4 expresses a coil as elements with turns_with_sign and circuits as a connections matrix; there is no per-element current-share fraction, because in the DD model the turn count is the share. That is representable: fold xmult into turns_with_sign so Σ turns reproduces the circuit's amp-turns. It is a genuine modelling decision for stage 2 rather than a copy, and it must be recorded, because the folded product is no longer the physical turn count.

efm/silop_dphi — each flux loop's toroidal angular extent — has no DDv4 scalar either. DDv4 represents a toroidally-partial loop by giving flux_loop/position multiple (R, φ, Z) points, which carries the extent implicitly and is strictly more expressive. The map is therefore a construction, not an assignment.

5. Source defects found, and what each one costs

These are reproducible defects in the FAIR-MAST source metadata, not transcription slips on our side. Each was checked on at least three shots spanning all three coil fingerprints.

  • The amm end-crown Z signs are transposed. endcrown_l ("Lower centre column end crown") carries Z=2.46 and endcrown_u ("Upper") carries Z=-2.46 — on every shot checked, in every campaign. Anything parsing R/Z out of these descriptions places both crowns on the wrong side of the midplane. Cost: two mis-placed passive elements at the largest |Z| in the machine, where they couple most strongly to the divertor-region sensors. Resolution is to trust the name over the parsed sign here, and to flag rather than silently correct.
  • Three efm unit strings are wrong. fcoil_turns and fcoil_xmult both declare units = 'deg' (they are a turn count and a dimensionless weight); silop_dphi declares 'm' for what its own description calls a "toroidal angular extent". Cost: any unit-aware ingest that trusts the metadata converts a turn count as an angle. This is the concrete reason the plan's rule that source metadata is untrusted for conventions should extend to units, not just to dd-path tags.
  • The obv* probe descriptions say "Br". Every obv01…obv18 channel is described as "Outer discrete Br magnetic coil array" while magpr_ang = 90 says vertical — the copy-paste defect ambix already documented, confirmed here. Orientation must come from magpr_ang; the channel description is a position lookup key and nothing more.
  • Flux-loop descriptions carry placeholder and mis-signed positions. fl_cc01 through fl_cc09 all claim the identical r=0.180, z=1.215; fl_p4u_4 and fl_p6u_1 — both upper-named — claim z=+1.083 and z=-1.089 respectively. Cost: this is why 8 of the amb flux-loop channels cannot be matched to a silop index at all and are honestly left unmatched rather than force-fitted.
  • psirz has two incompatible on-disk layouts (§2.2). Not a metadata defect but an ingest one: the array's attrs['shape'] says [86, 65, 65] where the stored array is (86, 65, 129), and the extra columns are NaN-scattered rather than trailing-padded. Cost: it silently produced wrong answers in this audit until the quality gate caught it, and it will do the same to any 2-D map read in stage 6.

6. What this invalidates in the plan's §3

  1. "the MAST convention has ψaxis > ψboundary" is not a landmark. True for 96.6% of shots, false for 379 of them (two blocks, 13469–13696 and 22376–22626), and the COCOS is identical either way. Replace with σBp = −1, i.e. sign(ψbnd − ψaxis) = −σIp.
  2. "sign flips on ψ/Ip/Bφ/q" overstates the ψ case and understates the q case. Against the DDv4 (COCOS 17) target: ψ scales by 2π and does not flip; Ip and Bφ do not change at all; q flips. The DDv3-era "axis max vs axis min" mismatch does not exist at this target.
  3. "ambix carries total flux Φ = 2πRAφ [Wb]" describes ambix, not the source. The efm reconstruction is Wb/rad (eBp = 0) and the measured flux loops are Wb. Both are true and they differ by the 2π; the ledger has to name which one each row means, and §4.1 does.
  4. "per-campaign versioning" needs a fingerprint the plan does not yet describe. §2 assigns pf_passive to "efm passive-element boxes", but the passive geometry is not in the efm arrays the fingerprint hashes — it is in amm descriptions, it moves independently, and 30.8% of shots do not carry it. The MD count is 5, not 3, and the fingerprint must be extended before stage 5 can fan out.
  5. The pf_passive/loop/element subtree is DDv4 lifecycle alpha. Not an invalidation but a risk the plan does not record: the MD's passive description depends on a subtree the DD may still change. Worth pinning the DD version for that reason alone.

7. Reproducing this

Scan, verdict and all four figures come out of one command. The full-corpus pass over 17,111 shots takes 1 m 58 s on 16 cores — cheap enough that it should be re-run rather than trusted whenever the mirror changes.

full-corpus run srun --partition=sun_debug --cpus-per-task=16 --mem=32G --time=01:00:00 \
  uv run python nova/scripts/identify_source_cocos.py --stride 1 --workers 16
redraw figures only uv run python nova/scripts/identify_source_cocos.py --figures-only

The script needs zarr and scipy, which are not nova dependencies — uv pip install "numpy<2" "zarr<3.1" scipy in the working environment (the numpy bound matters: an unpinned zarr pulls numpy 2.x and nova requires < 2). Compute nodes here have no network, so install on the login node first and run with --offline.

The script deliberately reimplements the campaign digest rather than importing ambix, so nova carries no dependency on it — and the reimplementation reproduces all three of ambix's published keys (9425ae4a8bf3bc15, edd753d282903679, 1cb6f2ee742c4ee4) exactly, which is the cross-check that the two codebases agree about what a campaign is.
