§1 — Objective

Nova is the home of the full physics spine — including transport. The nova-spine-refactor umbrella (§10) already commits ambix to consuming nova 2.0 as a dependency; this plan carries the detailed execution: the solver nomenclature that keeps the growing model zoo unambiguous, the model-by-model port of ambix's remaining physics tier into nova (refactored to nova style — dataclasses over native nova data types), the translation of the torch current-diffusion prototype to JAX for consistency with the rest of the library, and the reverse rewiring of imas-ambix imports. Ambix retains only the ML tier (tokenizer, decoders, world model, training) as thin consumers of the spine's numpy/JAX math.

Nova doing physics does not mean CPU-only: the spine is expected to run large-scale GPU solves and labeling campaigns. The short-term capability goal — the full MAST L2 catalog (11,573 shots, every timestep) reconstructed in ~1 hour on 8×H200 — is carried by the dependent mast-catalog-gpu-solve plan; this plan delivers the solver family it batches.

§2 — Solver nomenclature (locked)

Names are built from a two-axis constructor — problem × representation — so every solver states what is given/sought and how the plasma current is carried, and new combinations name themselves. Domain packages group the zoo; classes are ProblemRepresentation dataclasses.

Package layout and class names:

nova/equilibrium/forward.py          ForwardProfile        (today's forward free-boundary GS)
nova/equilibrium/inverse.py          InverseDesign         (PulseDesign solver core)
nova/equilibrium/moment.py           ReconstructMoment     (ambix boundary_disc + boundary_moment, one order ladder)
nova/equilibrium/harmonic.py         ReconstructHarmonic   (ambix boundary_harmonic)
nova/equilibrium/profile.py          ReconstructProfile    (ambix gs_solve, re-architected on nova.biot)
nova/circuit/passive.py              PassiveCircuit        (ambix temporal_operator + passive_resistance)
nova/circuit/screening.py            ScreeningCircuit      (ambix plasma_screening)
nova/transport/current_diffusion.py  CurrentDiffusion      (ambix current_diffusion, torch → JAX)

DOF naming (kills k=2/k=4): moment orders are multipole words behind an enum — MomentOrder.CENTROID (Ip + R,Z centroid), QUADRUPOLE (elongation/tilt), OCTUPOLE (triangularity). Profile-ladder sizes are explicit counts n_pressure/n_diamagnetic (the p′ and FF′ families). Circuit mode counts are n_modes. A bare k never appears in a public signature, config field, or symbol name; docstrings state what each rung adds physically. The "disc" model is retired as a name: the uniform-disc read is exactly the self-sized CENTROID-order member of ReconstructMoment, and its gated quadrupole is the next rung — one model, one ladder, no overlap with the monomial moment basis.

§5 — Style contract for ported code

  • Dataclasses: frozen config dataclasses + small stateful solver classes, matching nova idiom; no torch, no pandas.
  • Native types: columnar frame for conductor sets, xarray for gridded state, JAX pytrees for jit surfaces; numpy in/out at package boundaries.
  • JAX-first where solves batch: ReconstructProfile / ReconstructMoment / Topology / CurrentDiffusion carry fixed-shape, vmap-safe primary paths with a leading batch axis (the umbrella's §5 convention); numpy fallbacks only where an eager path already exists.
  • Naming hygiene: mechanism names only — no plan labels, no bare k, no version suffixes; module docstrings state the physics (the donor docstrings are good — carry them, updating names).
  • Conventions: total flux Φ = 2πRA_φ [Wb], explicit μ0, raw SI preserved through every port; sign conventions documented at module level and pinned by test.

§ Decisions

Naming grammar for the solver zoo — how are solver/model types named so the growing family stays unambiguous?

User selection 2026-07-24: two-axis constructor — problem token (forward / inverse / reconstruct / evolve) × representation token (profile / moment / harmonic / circuit / grid / filament), classes ProblemRepresentation in domain packages nova/equilibrium, nova/circuit, nova/transport. New combinations name themselves; the §2 matrix is the registry.

Rename for the ambix staged-disc boundary read (uniform current disc + gated quadrupole)?

User selection 2026-07-24: fold boundary_disc + boundary_moment into one ReconstructMoment model with a MomentOrder ladder — the uniform disc is the self-sized CENTROID-order seed, its gated quadrupole the next rung. Zakharov–Shafranov current-moment terminology; "dipole" under-describes, "shafranov_moment" collides with the Shafranov vertical-field/shift naming in the diagnostics.

How are basis sizes / prior DOFs named (replacing k=2, k=4)?

User selection 2026-07-24: MomentOrder enum (CENTROID / QUADRUPOLE / OCTUPOLE), profile ladder as n_pressure / n_diamagnetic, circuit modes as n_modes. No bare k anywhere in public API or symbol names.

ReconstructProfile topology reads: unify on nova's JAX connectivity/topology stack (vmap-safe, GPU-batchable — required by the catalog goal), or keep a host scipy.ndimage labeller path for the eager/debug lane alongside it?

User selection 2026-07-24 (mid fleet session): one vmap-safe, GPU-batchable topology path on nova's JAX connectivity/topology stack — required by the MAST catalog GPU-solve goal; no parallel scipy.ndimage labeller to keep in parity. Formulation note (user, same session): implement the ambix fill / boundary-push read — it is the only truly parallelizable formulation. The older stationary-points-first-then-surface-identification approach produced sharp gradients when switching between limited and diverted plasmas, not smooth enough for autograd or accelerator schemes (Anderson mixing, Newton–Krylov).

Where does the current-diffusion transport model live, and in what framework?

User direction 2026-07-24: nova is the home of the full physics spine including transport; the ambix torch prototype translates to JAX for consistency with the rest of the library. Torch remains an ambix-only (ML-tier) dependency.
