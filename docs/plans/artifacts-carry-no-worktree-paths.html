§3 — Launch scripts resolve the repository root when they run

Each launch script in the census taken at the node's dispatch base is read and handled in one of two ways. Where the worktree path is a cd target, an output root or any other path the script uses, the script derives its repository root at run time from its own location. It uses the idiom nova's launchers already settle on in scripts/nova_lane/run.sh, scripts/playable_server/run.sh and scripts/regenerate_solovev_certificate.sh: first resolve the script's own path with script_path="$(realpath -e -- "${BASH_SOURCE[0]}")", then repository_root="$(git -C "$(dirname "${script_path}")" rev-parse --show-toplevel)". Resolving the path first keeps a script invoked through a relative path, or one that changes directory before that line, on its own file. BASH_SOURCE rather than $0 makes a sourced script resolve its own file, not its caller's. A Python launch script runs git rev-parse --show-toplevel from Path(__file__).resolve().parent. It does not use nova.definitions.root_dir, which is fixed at import time to whichever tree nova was imported from. Through the shared environment's editable install, that is the canonical checkout even when the script runs in a worktree. The resolved root is the toplevel of whichever checkout the script runs in, a worktree or the canonical checkout, and output directories are written beneath it. Where the worktree path appears only in a comment or an echoed banner, the script file is passed through the §2 function instead. Paths to the canonical checkout, such as the shared environment at /home/ITER/mcintos/Code/nova/.venv, stay as they are.

Done when: no launch script contains the pattern. Every changed shell script passes bash -n, and every changed Python script compiles under the project interpreter. No script is executed against a solver or a SLURM partition.

§4 — The guard: nothing committed may name a worktree again

Two read-only checks share one exemption set: docs/state, docs/plans and docs/research (see §5), and nova/database/filepath.py, where the rule, the pattern constant and the exemption constant live. The checks skip those paths. Every other file, including the tests, the subcommand and the hook, imports the constants or calls the subcommand rather than spelling the pattern, so it needs no exemption.

  • tests/test_artifacts_carry_no_worktree_paths.py lists the tracked files with git ls-files, passes them to worktree_path_offenders with a reader over the working tree, and fails naming each offender the predicate returns. It does no pattern matching of its own. A positive control proves the scan reaches files in every top-level directory. It supersedes the directory-limited scan in tests/test_render_receipt_paths.py: test_no_receipt_directory_json_records_a_worktree_path and its positive control test_the_scan_reaches_every_receipt are deleted, together with the helpers that serve only them, _scanned_json and RECEIPT_DIRECTORIES. The test calls worktree_path_offenders over every tracked file, so the only scanning decision in the repository is that one predicate. The render-route tests in that file stay. The new test runs in the default fast lane, in seconds.
  • The commit-time check is a plain checked-in hook, scripts/git-hooks/pre-commit. pyproject.toml declares the pre-commit framework as a dev dependency and AGENTS.md describes its workflow, but nothing configures or installs it: there is no .pre-commit-config.yaml, no installed hook, and no core.hooksPath in any git configuration scope. The framework is not adopted, because it stashes and restores unstaged changes around its hooks, which the workstation policy bans in multi-agent checkouts. This hook is nova's one commit-time check. A later read-only check, such as the size ceiling in converged-forward-solve's receipts-out-of-git decision, joins this script rather than adding a second mechanism. When the coordinator enables the hook, it also corrects the AGENTS.md pre-commit section to describe it. The hook is a two-line shell shim. It runs the project interpreter on nova.database.scripts with relativize --check, setting PYTHONPATH to the hook's own checkout so that the rule applied is that checkout's. The check reads only the staged files, rejects any outside the exemptions that contains a worktree path, names filepath relativize as the fix in its message, and never modifies a file. After the node lands, the coordinator enables it once with git config core.hooksPath scripts/git-hooks in the main checkout. Worktrees share that setting, and the line goes into the new-clone setup in AGENTS.md. A worktree whose base predates the hook has no scripts/git-hooks directory, so git runs no hook there, and in-flight workers are unaffected.

Writers keep their paths relative at the source, through repository_relative, wherever they record one. The guard covers the writers nobody has fixed yet, and captured stdout, where a traceback prints whatever path the process ran under.

Done when: the test passes on the merged head and fails at the node's dispatch base, where the launch scripts still carry the pattern, logged as the negative control. In a scratch repository, the hook rejects a staged file containing a worktree path and accepts it once filepath relativize has rewritten it, both logged. The default pytest lane collects the test.

§5 — What stays outside, and why

docs/state is reckon's run ledger. Its records say where each run executed, which is provenance about a run rather than an artifact that locates content, and reckon writes it. Rewriting it would make the ledger misreport where runs ran. It is exempt from both the rewrite and the guard. docs/plans and docs/research are edited only through reckon's tools, never as files. The few comments inside plan files under docs/plans that mention the pattern discuss it as a subject. Any that use a worktree path as a link are corrected through edit_plan by the coordinator, not by the mechanical rewrite.

The worker contract that reckon composes is reckon's to change, and changing it is not a node of this plan. After §4 lands, the coordinator tells reckon that nova rejects worktree paths at commit, so that its dispatch contract can name the relativizing step. A worker running without that line still cannot land a worktree path, because the hook and the test stop it.
