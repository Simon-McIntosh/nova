§1 — Why this plan exists

Every crew worker runs in a detached worktree under /home/ITER/mcintos/Code/.reckon-worktrees/<project>-<hash>/<session>/<node>/, or, for runs from before that root was adopted, under /home/ITER/mcintos/.cache/reckon-worktrees/ with the same layout, and every worktree is removed once its run is promoted. Reckon owns that layout (reckon/crew/routing.py, where the preferred root is the repository's parent plus .reckon-worktrees and the legacy root is reckon-worktrees under the temporary directory). Nova carries no reckon dependency, so §2 re-encodes the layout rather than importing it. The lead's rule, given on 2026-10-06, is that this is permanent: a worktree always goes, so a committed artifact that names a path inside one names a path that will not exist. The evidence then stops locating its own figures, logs and scripts, and a launch script that changes directory into a worktree stops running at all.

The census is the command git grep -l -I 'reckon-worktrees' <revision> -- . ':!docs/plans' ':!docs/state' ':!docs/research', which matches both worktree roots; §5 says why those three directories stay out. Run at origin/main f574e2817 it lists 1,147 tracked files: 1,071 under docs/figures in 38 topic directories, 58 under scripts/, 12 under docs/evidence, 3 under benchmarks/, 2 under tests/ and 1 under nova/. The tree gains such files as runs land, so every node runs the census itself at its dispatch base and works from that list, never from these numbers.

In this plan a launch script is any census file ending .sh, .sbatch or .py, wherever it sits. At f574e2817 there are 65: 48, 10 and 7 of each, 59 under docs/figures, 3 under benchmarks/ and one each under scripts/, tests/ and nova/. Every other census file, 1,082 at that revision, is a data file. Data files are rewritten mechanically (§2). Launch scripts are read one by one (§3), because a literal path there may be a cd target or an output root that has to be derived at run time, or may be only a comment that the mechanical rule can rewrite.

S22 repaired the four regenerated receipts first (227a55bd5) and gave the repository-relative path helper one owner, nova.database.filepath.repository_relative (88a14b2ad). This plan applies the same rule to everything else, then closes the door with a guard so the next worker cannot reopen it.

§5 — What stays outside, and why

docs/state is reckon's run ledger. Its records say where each run executed, which is provenance about a run rather than an artifact that locates content, and reckon writes it. Rewriting it would make the ledger misreport where runs ran. It is exempt from both the rewrite and the guard. docs/plans and docs/research are edited only through reckon's tools, never as files. The few comments inside plan files under docs/plans that mention the pattern discuss it as a subject. Any that use a worktree path as a link are corrected through edit_plan by the coordinator, not by the mechanical rewrite.

The worker contract that reckon composes is reckon's to change, and changing it is not a node of this plan. After §4 lands, the coordinator tells reckon that nova rejects worktree paths at commit, so that its dispatch contract can name the relativizing step. A worker running without that line still cannot land a worktree path, because the hook and the test stop it.

§6 — Close the guard's blind spots

The review of the §3/§4 landing found four gaps, and this section closes them.

  • Binary files. The census and the guard both skip them, so docs/figures/millisecond-converged-solve/trip-quantum/host-profile/production-solve.pstats, a cProfile dump, still embeds worktree paths unseen. Its producer, benchmarks/production_solve_host_profile.py, writes absolute frame paths on every run through profiler.dump_stats, so repairing the committed dump alone would let the next run re-introduce the defect. Add one helper beside the rule in nova/database/filepath.py that loads a cProfile dump, rewrites each recorded file path through relativize_worktree_paths, and writes it back in the same format. The producer calls it right after dump_stats, and the committed dump is repaired with the same helper. The guard's reader must return a binary file's text decoded with replacement rather than an empty string, so a binary file that carries the root name is reported.
  • Benchmark defaults. DEFAULT_SHADOW_ROOT in benchmarks/backend_divergence_forensics.py and DEFAULT_PINNED_ROOT in benchmarks/pure_arm_comparison_figure.py are built from the constant, so no literal remains, but they still resolve to a removed worktree. Make each root a required argument, and say in the help text where to obtain one.
  • A record that contradicts itself. In docs/evidence/archive/figure-and-solver-audit-landed.html, the hand-repaired coil-edit receipt sentence still calls its now-relative path absolute. Reword that clause and change nothing else.
  • A slow scan. tests/test_artifacts_carry_no_worktree_paths.py reads every tracked file in full: 34 s for its two tests, against the seconds §4 promised. Give the owner module, nova/database/filepath.py, one candidate search: git grep -l -a -F on WORKTREE_ROOT, over the working tree for the test and with --cached over the index for the commit check, so binary files are covered and the hook and the test share one enumeration. Only those candidates go to worktree_path_offenders, and the predicate stays the one decision. The committed tests also exercise the predicate's offending branch directly: a non-exempt path whose reader returns the root name is returned as an offender, and an exempt one is not. An empty candidate list must not read as a clean tree: a search run from the wrong directory, without git, or after pattern drift would return nothing. So the test asserts first that the candidate search returns nova/database/filepath.py, the exempt module that always holds the root name, before it accepts an empty offender list.

Done when: the guard test fails on a scratch tracked binary file carrying a worktree path, and the hook refuses the same file staged, both logged. The test also fails when the candidate search returns nothing, logged as a second negative control. The pstats file loads with no worktree path left in it. Neither benchmark default names a worktree. The record reads consistently. The guard test runs in under ten seconds, logged.
