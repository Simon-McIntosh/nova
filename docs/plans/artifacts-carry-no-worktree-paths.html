§1 — Why this plan exists

Every crew worker runs in a detached worktree under /home/ITER/mcintos/Code/.reckon-worktrees/<project>-<hash>/<session>/<node>/, and every worktree is removed once its run is promoted. The lead's rule, given on 2026-10-06, is that this is permanent: a worktree always goes, so a committed artifact that names a path inside one names a path that will not exist. The evidence then stops locating its own figures, logs and scripts, and a launch script that changes directory into a worktree stops running at all.

A census of origin/main at 88a14b2ad found 1,146 tracked files outside docs/plans and docs/state containing the string .reckon-worktrees. 1,071 sit under docs/figures in 38 topic directories, 62 under scripts/, 11 under docs/evidence, one under tests/ and one under docs/research, which §5 keeps out with docs/plans and docs/state. By extension they are 611 logs, 433 JSON receipts, 12 text files, 10 HTML files, 8 Markdown files, 7 stdout and stderr captures, one patch file, and 64 launch scripts.

In this plan a launch script is any census file ending .sh, .sbatch or .py, wherever it sits: 48, 10 and 6 of them, 59 under docs/figures and 5 under scripts/. Every other census file outside docs/research, 1,081 in all, is a data file. Data files are rewritten mechanically (§2). Launch scripts are read one by one (§3), because a literal path there may be a cd target or an output root that has to be derived at run time, or may be only a comment that the mechanical rule can rewrite.

S22 repaired the four regenerated receipts first (227a55bd5) and gave the repository-relative path helper one owner, nova.database.filepath.repository_relative (88a14b2ad). This plan applies the same rule to everything else, then closes the door with a guard so the next worker cannot reopen it.

§2 — One rewrite rule, applied to every committed data artifact

The rule has one owner, nova/database/filepath.py. The root search in repository_relative cannot serve here on its own: it finds a repository by looking for the .git marker on disk, and the worktrees named in committed artifacts no longer exist. So the rule is lexical. The module gains one public function, relativize_worktree_paths(text), which returns the rewritten text together with the list of worktree-path spans it could not map, and one constant holding the worktree root's directory name, which every other file imports instead of spelling the pattern. repository_relative delegates its worktree case to the same matcher, so a path under a removed worktree maps the same way through either entry point and the rule has one definition. That function is the only public surface the plan adds. It cannot be folded into repository_relative, because it takes and returns text rather than a path and it reports what it left unmapped. scripts/relativize_worktree_paths.py applies it to named files in place and prints each file it changed and each span it left unmapped. The rule:

  • A path under a nova worktree, .reckon-worktrees/nova-<hash>/<session>/<node>/<rest>, is replaced by the bare string <rest>, for example docs/figures/x/receipt.json, which is relative to the repository root.
  • A path under another repository's worktree, .reckon-worktrees/<repository>-<hash>/<session>/<node>/<rest>, is replaced by /home/ITER/mcintos/Code/<repository>/<rest>, where <repository> is the worktree directory's name without its trailing -<hash>. Canonical checkouts on this workstation sit under that prefix and are never removed. A repository with no checkout there is reported as unmapped and left unchanged.
  • A bare worktree root with nothing below it, such as a recorded working directory, is replaced by the literal string . for nova, and by the canonical checkout path for another repository.
  • The rewrite is idempotent and changes nothing outside the matched spans: the same bytes elsewhere, the same line endings, and every JSON file still parses.

The node first censuses the spellings present, because the matcher must cover each one: the absolute form, a ~ form, JSON strings with escaped slashes, and a single path split across two lines by a log's line wrap. Any spelling it cannot map is listed with its file and line in the node's report, under its report path, and left unchanged rather than guessed.

The docs/figures/converged-forward-solve topic is held out of this node because S21's live runs write there. Its 74 logs are rewritten in the §3 node once S21 reports those directories quiet.

Done when: no data file outside the held topic contains the pattern. A check script re-applies the function to each rewritten file as it stood at the node's dispatch base and asserts that the result equals the committed bytes, which makes the rewrite reviewable as a mechanical transform. Every rewritten JSON file still parses. tests/test_filepath.py, which already exists, gains tests for each mapping form, for idempotence, for the repository_relative delegation on a removed worktree, and for an unmapped form that comes back in the unmapped list while the text is left unchanged. The tests build the pattern from the module constant. They fail against a scratch copy of the function with its nova mapping disabled, logged as the negative control. No launch script, PNG or SVG changes, and no solve runs.

§3 — Launch scripts resolve the repository root when they run

Each of the 64 launch scripts is read and handled in one of two ways. Where the worktree path is a cd target, an output root or any other path the script uses, the script derives its repository root at run time from its own location. In shell that is one line, ROOT="$(git -C "$(dirname "${BASH_SOURCE[0]}")" rev-parse --show-toplevel)"; BASH_SOURCE rather than $0 makes a sourced script resolve its own file, not its caller. In Python it is the same git rev-parse --show-toplevel run from the script's own directory. The resolved root is the toplevel of whichever checkout the script runs in, a worktree or the canonical checkout, and output directories are written beneath it. Where the worktree path appears only in a comment or an echoed banner, the script file is passed through the §2 function instead. Paths to the canonical checkout, such as the shared environment at /home/ITER/mcintos/Code/nova/.venv, stay as they are.

The same node rewrites the 74 held docs/figures/converged-forward-solve logs with the §2 script, once S21 has reported those directories quiet, and lands the §4 guard.

Done when: no launch script contains the pattern. Every changed shell script passes bash -n, and every changed Python script compiles under the project interpreter. For each script given a run-time root, a probe evaluates its root line from a temporary worktree of main and prints the value, which equals that worktree's toplevel and not the canonical checkout. No script is executed against a solver or a SLURM partition.

§4 — The guard: nothing committed may name a worktree again

Two read-only checks share one exemption set: docs/state, docs/plans and docs/research (see §5), and nova/database/filepath.py, where the rule and its constant live. The checks skip those paths. Every other file, the tests and the script included, imports the constant rather than spelling the pattern, so it needs no exemption.

  • tests/test_artifacts_carry_no_worktree_paths.py runs git grep for the pattern over every tracked file outside the exemptions and fails naming each offender. A positive control proves the scan reaches files in every top-level directory. It supersedes the directory-limited scan in tests/test_render_receipt_paths.py: test_no_receipt_directory_json_records_a_worktree_path and its positive control test_the_scan_reaches_every_receipt are deleted, and the render-route tests in that file stay. The new test runs in the default fast lane, in seconds.
  • nova has no pre-commit framework, so the commit-time check is a plain checked-in hook, scripts/git-hooks/pre-commit. It reads only the staged files, rejects any outside the exemptions that contains the pattern, names scripts/relativize_worktree_paths.py as the fix in its message, and never modifies a file. After the node lands, the coordinator enables it once with git config core.hooksPath scripts/git-hooks in the main checkout. Worktrees share that setting, and the line goes into the new-clone setup in AGENTS.md. A worktree whose base predates the hook has no scripts/git-hooks directory, so git runs no hook there, and in-flight workers are unaffected.

Writers keep their paths relative at the source, through repository_relative, wherever they record one. The guard covers the writers nobody has fixed yet, and captured stdout, where a traceback prints whatever path the process ran under.

Done when: the test passes on the merged head and fails at the node's dispatch base, where the launch scripts and the held logs still carry the pattern, logged as the negative control. In a scratch repository, the hook rejects a staged file containing a worktree path and accepts it once the script has rewritten it, both logged. The default pytest lane collects the test.

§5 — What stays outside, and why

docs/state is reckon's run ledger. Its records say where each run executed, which is provenance about a run rather than an artifact that locates content, and reckon writes it. Rewriting it would make the ledger misreport where runs ran. It is exempt from both the rewrite and the guard. docs/plans and docs/research are edited only through reckon's tools, never as files. The few comments inside plan files under docs/plans that mention the pattern discuss it as a subject. Any that use a worktree path as a link are corrected through edit_plan by the coordinator, not by the mechanical rewrite.

The worker contract that reckon composes is reckon's to change, and changing it is not a node of this plan. After §4 lands, the coordinator tells reckon that nova rejects worktree paths at commit, so that its dispatch contract can name the relativizing step. A worker running without that line still cannot land a worktree path, because the hook and the test stop it.
