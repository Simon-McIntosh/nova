§1 — Why this plan exists

Every crew worker runs in a detached worktree under /home/ITER/mcintos/Code/.reckon-worktrees/<project>-<hash>/<session>/<node>/, and every worktree is removed once its run is promoted. The lead's rule, given on 2026-10-06, is that this is permanent: a worktree always goes, so a committed artifact that names a path inside one names a path that will not exist. The evidence then stops locating its own figures, logs and scripts, and a launch script that changes directory into a worktree stops running at all.

A census of origin/main at 88a14b2ad found 1,146 tracked files outside docs/plans and docs/state containing the string .reckon-worktrees. 1,071 sit under docs/figures in 38 topic directories, 11 under docs/evidence and the rest under scripts/. By extension they are 611 logs, 433 JSON receipts, 12 text files, 10 HTML files, 8 Markdown files, 7 stdout and stderr captures, one patch file, and 64 launch scripts (48 .sh, 10 .sbatch, 6 .py). The data files can be rewritten mechanically. The launch scripts cannot, because a literal path there is usually a cd target or an output root, and it has to be derived at run time instead.

S22 repaired the four regenerated receipts first (227a55bd5) and gave the repository-relative path helper one owner, nova.database.filepath.repository_relative (88a14b2ad). This plan applies the same rule to everything else, then closes the door with a guard so the next worker cannot reopen it.

§2 — One rewrite rule, applied to every committed data artifact

Add one function to nova/database/filepath.py, beside repository_relative, that rewrites worktree paths inside a text. It is the only owner of the rule, and a small script, scripts/relativize_worktree_paths.py, applies it to named files in place. The rule:

  • A path under a nova worktree, .reckon-worktrees/nova-<hash>/<session>/<node>/<rest>, becomes <rest>, which is relative to the repository root.
  • A path under another repository's worktree becomes the same file in that repository's canonical checkout, /home/ITER/mcintos/Code/<repository>/<rest>. Canonical checkouts are never removed, so that path stays valid.
  • A bare worktree root with no file below it, such as a recorded working directory, becomes . for nova and the canonical checkout for another repository.
  • The rewrite is idempotent and changes nothing else in the file: same bytes outside the matched paths, same line endings, and JSON still parses.

The census of prefix forms comes first, inside the node, because the rule must match every spelling present: the absolute form, a ~ form, paths inside JSON strings with escaped slashes, and paths broken across lines in logs. Any form the rule cannot map is listed in the report rather than guessed.

Done when: every tracked data file (everything in the census except the launch scripts, docs/plans, docs/research and docs/state) contains no .reckon-worktrees string. Re-applying the script to each file's base revision reproduces the committed head bytes exactly, which makes the rewrite reviewable as a mechanical transform. Every rewritten JSON file still parses. tests/test_filepath.py pins each mapping form, including idempotence and a negative control in which an unmapped form is reported and left unchanged. No PNG or SVG is re-rendered, and no solve is run.

§3 — Launch scripts resolve the repository root when they run

The 64 launch scripts that contain a literal worktree path derive the repository root from their own location instead: git -C "$(dirname "$0")" rev-parse --show-toplevel in shell, and Path(__file__).resolve() walked up to the git root in Python, reusing repository_relative's root search rather than a second one. A script whose path names an output directory writes beneath the resolved root. A script that records the worktree path only in a comment or an echoed banner has that text rewritten by the §2 rule. Scripts that pass a shared-environment path such as /home/ITER/mcintos/Code/nova/.venv keep it, since the canonical checkout is permanent.

Done when: no launch script contains .reckon-worktrees. Every changed shell script passes bash -n and every Python script compiles under the project interpreter. For each changed script, a dry resolution of its root, run from a temporary worktree of main, prints that worktree's root and not the canonical checkout. No script is executed against a solver or a SLURM partition.

§4 — The guard: nothing committed may name a worktree again

Two checks, both read-only:

  • tests/test_artifacts_carry_no_worktree_paths.py runs git ls-files and git grep for .reckon-worktrees over every tracked file, and fails naming each offender. It is exempt only for docs/state (reckon's run ledger, see §5), docs/plans and docs/research (prose that reckon edits, see §5), and the three files that must spell the pattern: the test itself, the §2 rule in nova/database/filepath.py, and scripts/relativize_worktree_paths.py. It runs in the default fast lane, in seconds.
  • A check-only pre-commit hook in .pre-commit-config.yaml rejects any staged file outside those exemptions that contains the pattern. Its message names scripts/relativize_worktree_paths.py as the fix, so a worker whose gate log or receipt was written inside its worktree relativizes it before committing. The hook never modifies a file, as the repository's pre-commit policy requires.

Writers keep their paths relative at the source wherever they record one, through repository_relative. The guard is what makes the rule hold for writers nobody has fixed yet, and for captured stdout, where a traceback prints whatever path the process ran under.

Done when: the test passes on the merged head and fails at the base, logged as the negative control. The hook rejects a staged scratch file that contains a worktree path and accepts it once the script has rewritten it, both logged. The default pytest lane collects the test.

§5 — What stays outside, and why

docs/state is reckon's run ledger. Its records say where each run executed, which is provenance about a run rather than an artifact that locates content, and reckon writes it. Rewriting it would make the ledger misreport where runs ran. It is exempt from both the rewrite and the guard. docs/plans and docs/research are edited only through reckon's tools, never as files. The few plan comments that mention the pattern discuss it as a subject. Any that use a worktree path as a link are corrected through edit_plan by the coordinator, not by the mechanical rewrite.

The worker contract that reckon composes is reckon's to change. After §4 lands, the coordinator tells reckon that nova rejects worktree paths at commit, so its dispatch contract can name the relativizing step. A worker running without that line still cannot land a worktree path, because the hook and the test stop it.
