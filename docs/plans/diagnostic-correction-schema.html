§1 — Why corrections need a schema, not constants

The programme's own measurements broke the single-constant model three times over. The MAST store carries 19 channels whose acquisition scale steps by exactly 1/2, 1/√2, √2 or 2 across shot blocks; obr05 flips between gain states 1.25 and 0.50 shot-to-shot; obv03 steps from 1.01 to 0.586 mid-life; obr17 holds 0.50 for the machine's entire life. A correction is therefore a function of pulse range (occasionally of time), with a kind, a value, a validity interval, and evidence — and the current representation (in-code dictionaries such as PROMOTED_CHANNEL_SCALES, a JSON block table, and prose in research records) can express none of that uniformly, version none of it, and validate none of it.

One schema covers every correction class the ladder produces or will produce:

§2 — Schema design

  1. Authoring language. LinkML is the recommended choice (decision below): the schema is itself YAML, generates Pydantic models and JSON-Schema for free, carries first-class enums, slot constraints and schema versioning, and matches the tooling already used across the IMAS standard-names ecosystem. The fallback is hand-written Pydantic with YAML instances — less machinery, no generated artefacts for other consumers.
  2. Core classes. CorrectionSet (machine, diagnostic system, schema version, set version, generated-by) → ChannelCorrection (channel id or named channel-group id for set-scoped quality states, kind, value, uncertainty) → ValidityInterval (pulse_start/pulse_end or time_start/time_end; open-ended allowed; intervals within one channel+kind must not overlap) → Provenance (method, evidence URI — research record or banked array, fitted_at, fitted_by, corroborations). Ladder-quantised kinds carry their allowed rungs so validation can reject a free-floating block scale.
  3. Application semantics are part of the schema. One documented, tested order on the read path: offset → drift → acquisition scale → pair state → gain, with convention factors applied at unit boundaries. A correction a consumer cannot order is a correction that will be applied twice or not at all.
  4. Storage and versioning. Instances live in-repo under nova/calibrate/corrections/<machine>/, one file per diagnostic system, versioned by git plus an explicit monotonic set version; the artifact/registry pipeline can later ship them alongside the machine description (the registry's semantic-identity lesson applies — the set version is semantic, never a content hash alone).
  5. First instance: MAST. Encode everything already measured — the five promoted scales, the withheld channel, the 113-block acquisition table, obr17's lifetime gain with its three corroborations, the pair-failure channels with their measured intervals, the flux-loop convention — and make the nova read path consume it end-to-end (equivalence test against current behaviour, then delete the in-code constants).

Done-when: schema authored and validated; models generated; the MAST instance file round-trips through validation and reproduces current read-path behaviour to float equality on the vacuum-floor bench; in-code correction constants deleted; schema documented for the next machine.

§ Decisions

Schema authoring language?

Owner decision 2026-08-07: LinkML. Schema-as-YAML with generated Pydantic and JSON-Schema, first-class enums and versioning, and ecosystem fit with the IMAS standard-names tooling. Plain Pydantic+YAML remains the documented fallback if LinkML tooling friction exceeds its value in practice.
