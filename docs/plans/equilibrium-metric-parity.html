§1 — The metric layer is testable on its own, and has never been tested

Given one flux map, two codes should compute the same safety factor, the same volumes and the same flux-surface averages. That comparison isolates the derived-quantity chain completely: no solver runs, no sources are prescribed, no boundary condition is imposed. Both answers exist for the same input — nova computes its record from the stored map, EFIT's own values sit beside it in the same file — so every disagreement is attributable to one code's post-processing rather than to a difference in equilibrium.

That property is what makes this rung worth its own plan rather than a section of the forward demonstration. efit-forward-parity compares I_p, β_p and l_i between a solved map and a reference map — but those are metrics, so a disagreement there has two possible causes and no way to separate them: the solve produced a different field, or the two codes measure the same field differently. Validating the metric layer first collapses that ambiguity, which is why this plan blocks the forward one.

Nova already computes most of this, which sets the shape of the work. nova/equilibrium/flux_surface_geometry.py carries a FluxSurfaceGeometry record read from one converged flux map, landed at b0af2d23 with 13 columns measured 5–130× inside pre-registered tolerances:

So this is mostly a comparison, with implementation confined to whatever the reference computes and nova does not. That balance is worth stating up front because it is the opposite of the usual assumption: the risk here is not missing machinery, it is unexamined agreement.

§2 — Census the reference's derived set, then pair it up

The forward-input census established what the store holds for driving a solve. This is the complementary census: what the store holds that nova's record could be scored against. Known present already are efm/psi_norm, efm/psi_axis, efm/psi_boundary, efm/magnetic_axis_{r,z}, efm/lcfs_{r,z}, both x-point pairs, efm/plasma_current_{x,c}, efm/ppsi_c, efm/fpsi_c, and the vacuum-field entries bvac_val, bvac_r and irod; safety factor is present and carries a sign flip into COCOS 17. The census must enumerate the rest — volumes, areas, elongation and triangularity, stored energy, poloidal and toroidal beta, internal inductance, boundary geometry, and any flux-surface average the file carries — with units, shape and flux coordinate for each.

Pairing is where the real work sits, and it is not mechanical. Two codes rarely define a metric on the same coordinate, over the same domain, with the same normalisation. A safety factor on normalised poloidal flux is not the same array as one on normalised toroidal flux even when both are called q. A volume enclosed to the LCFS is not a volume enclosed to the last closed grid contour. So each pair carries an explicit statement of coordinate, domain and normalisation, and a resampling rule where the coordinates differ — and a metric that cannot be paired without inventing a convention is reported as unpaired rather than compared on a guess.

Done-when: every derived quantity the store carries is listed with units, shape and flux coordinate; each is paired with its nova counterpart or explicitly marked absent-in-nova or unpairable-with-reason; and the count of each class is reported.

§3 — Compare from the same map

Drive FluxSurfaceGeometry from the stored flux map — the same map EFIT derived its own values from — and compare column by column. Every comparison uses the conventions declared in efit-map-inversion: source COCOS 3, ψ ×2π into COCOS 17, q ×(−1), and the per-shot plasma-current sign check rather than a single assumption.

The plasma domain is the stored LCFS interior, for the same reason it is in the sibling plans: the decomposition measured 10.08 MA of absolute current outside a 0.925 MA plasma, so a surface family traced without that boundary would integrate conductor current into plasma volumes. A flux-surface average is an integral over a surface, and a surface that leaks past the separatrix silently contaminates every column derived from it.

Done-when: each paired quantity is reported as a signed relative difference profile with its median and interquartile range across surfaces, on at least one slice per frozen shot; the comparison names which differences are convention artefacts resolved by a declared transform and which are genuine numerical disagreement; and any quantity whose disagreement exceeds the tolerance class its nova counterpart was landed against is called out with the surface positions where it does so.

§4 — Implement what the reference computes and nova does not

Whatever §2 marks absent-in-nova becomes implementation here, added to the record rather than computed in a comparison script — the point is a capability, not a one-off answer. Each addition lands with the same discipline the existing 13 columns carry: a convention-pinned definition, a tolerance it is measured against, and a test holding it.

Two independent checks are available for anything added and should be used rather than trusting the reference. Analytic equilibria give exact values for several of these quantities, and nova already carries Solov'ev and rotating references from the static and rotation rungs; and internal consistency binds the set — volume_derivative must integrate to volume, the safety factor must be consistent with field_function and inverse_square_radius on the same surfaces. A quantity that matches EFIT but fails its own analytic or internal check is not validated, it is coincidentally agreeing, and the distinction matters because the reference is a code with its own conventions rather than ground truth.

§5 — The transport consumer, which is why this is a capability

This set is the geometry input of the transport forward solve, not only a validation artifact. flux-function-forward-equilibrium §5 already declares the flux-surface-averaged geometry record — V′, the ⟨1/R²⟩ and diffusion-coefficient metrics, F and q on the toroidal-flux coordinate — a public output contract of ForwardProfile, consumed by flux-function-forward-transport and supplied at both interval endpoints so the moving-grid term is correct.

So validating these columns against an independent code, on real machine data rather than manufactured fixtures, is what lets the transport work stand on them — and it is what makes the decomposition and metric routines reusable for training one-dimensional transport equations in the competition entry, where the geometry has to be derived from stored equilibria rather than from nova's own solves. A metric validated only against nova's own analytic fixtures is validated against nova's own conventions; this rung is the first time an outside code checks them.

§ Decisions

What tolerance does a paired metric have to meet? The existing record's columns were landed 5–130× inside pre-registered analytic tolerances, but a cross-code comparison on real data has no such basis and the reference is not ground truth.

§ Followups

Census the reference's derived quantities and pair them against nova's record

Nova's FluxSurfaceGeometry already carries fifteen profile columns and six scalars — safety factor, volume and area with both derivatives, field function, inverse-square radius and three gradient-rho averages, on poloidal flux, toroidal flux and rho_tor coordinates — landed at b0af2d23 with thirteen of them measured 5–130x inside pre-registered tolerances. What does not exist is the pairing: which of these the reference also computes, on what coordinate, over what domain, with what normalisation. Enumerate every derived quantity the efm store carries (volumes, areas, elongation, triangularity, stored energy, betas, internal inductance, boundary geometry, safety factor, any flux-surface average) with units, shape and flux coordinate, then pair each against its nova counterpart or mark it absent-in-nova or unpairable with a reason. Do not compare a pair whose coordinate or domain differs until the resampling rule is stated — a q on normalised poloidal flux is not the array a q on normalised toroidal flux is, and agreeing by accident is worse than reporting unpaired. Conventions come from efit-map-inversion: source COCOS 3, psi x2pi, q x(-1), and the per-shot plasma-current sign check rather than one assumption.
