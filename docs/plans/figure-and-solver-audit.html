Why this plan exists

The lead read the figures this sprint produced and found them shoddy, and the coordinator's own record of the last day agrees with the reading. Since the sprint opened on 2026-09-16 there have been 157 promotions on this project, the large majority delivered by the locally served model lane, and they touched sixteen figure directories: 78 files under constraint-augmented-newton-krylov, 54 under null-identification-authority, 52 under millisecond-converged-solve, 50 under gs-absolute-accuracy, 43 under cut-cell-current-attribution. In one day the coordinator caught a "negative control" that inverted an assertion in a copy of the test file, three manifests in a row that wrote prose after the red-log path so the promotion had to be repaired by hand, a certificate node whose diff spans sixty-three files, and a wall read certified green on a reachability verdict that the separation probe's panels show to be a discretisation artifact on both fixtures. None of this was caught by the gates the workers ran, because a gate the implementing worker writes and runs against its own diff measures internal consistency and not correctness.

The lead's ruling of 2026-09-21: an in-depth review, on a lane other than the one that did the work, figure-led first because a figure is the one artifact a reader can check without re-running anything, then the solver core commit by commit once the codex window resets. No locally served implementation node is promoted from this point without a scored review, and no new implementation node is dispatched to that lane while the review runs; it keeps investigation and reporting nodes. The findings feed two things: repair nodes on the plans they belong to, and a record in reckon that scopes where background agents of this class are fit to be deployed, because the lead's judgement is that they have a role and were deployed too liberally.

§1 — The figure-led audit, one reviewer per figure directory

One review node per figure directory touched this sprint, on the claude-opus lane because it can open the image and the review needs eyes. Each reviewer takes every PNG and SVG in its directory with the JSON receipt beside it and the evidence record that cites it, and answers four questions per figure, writing the answers as a scored table. Rules: does the figure obey the plotting rules of this repository (no axes or gridlines on a 2D plot; scalar fields as unfilled line contours on stated levels; every flux map marks its axis and admitted X-point in the null vocabulary, both null sets where a reference exists; every poloidal panel draws the wall over the unit collection)? Numbers: does every number in the caption and in the paragraph that cites the figure re-derive from the committed receipt, read out of the named JSON path, to the digit? Physics: does the figure show what its caption says it shows — a converged state's contours closing on the stated null, a limited boundary touching the wall, a diverted one passing through its X-point — or does it show a different equilibrium captioned around? Honesty: is anything drawn that the receipt does not carry, or omitted that would change the reading?

Each figure receives a score out of 100 with the deductions itemised, and each deduction names the file, the receipt path, the rule or number it breaks, and the repair. A figure that scores under 70, or that misrepresents its physics at any score, is a repair node on the plan that owns it, filed by the reviewer as a followup on that plan with the reviewer's evidence linked. The reviewer commits nothing under nova/ and regenerates nothing; the review's deliverable is the scored record.

Done when. Every figure directory touched since 2026-09-16 has a scored review record under docs/evidence/archive/figure-and-solver-audit-landed.html, one anchor per directory, with the per-figure table and the itemised deductions; every figure under 70 or misrepresenting its physics has a repair followup on its owning plan naming the reviewer's anchor; and the record states the directory's mean score, the count under 70, and the count misrepresenting physics, so the lane-fitness record of §4 can be built from it without re-reading the figures.

§4 — The lane-fitness record, handed to reckon

The audit exists to change how work is dispatched, not only to fix this sprint. From the per-directory and per-area counts of §1 and §2 a short record states, per class of work (figure rendering, record repair, mechanical refactor, measurement driver, solver change, negative-control authoring, investigation and reporting), how the locally served lane scored, which defect classes it produced, and which it did not. That record is the evidence input of the reckon plan background-agent-fitness-and-dispatch-scope, which turns it into the dispatch rules: which roles and spec levels route to the local lane by default, which need an independent-lane review before promotion, and which never route there.

Done when. The record exists as an anchor of this plan's evidence document with one row per class of work carrying the counts behind it, and the reckon plan cites that anchor as its evidence input.
