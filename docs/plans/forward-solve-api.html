Forward solve API

Raised by the lead on 2026-09-02 after one night surfaced four landed capabilities that the production routes do not apply by default, each found only because a measurement failed: the net-current pin, the persistent compilation cache, the settled exit's effect on a fixture, and the cached machine build. The capability-wiring audit (~/.config/reckon/crew/reports/nova/capability-wiring-audit.md, sixteen capabilities against eight entry points) showed the pattern: ForwardProfile.solve on the Newton–Krylov route carries the landed safeguards by default, but several drivers bypass or partially configure it, so the same solver reaches different verdicts depending on which script calls it. The work is split in three so each part ships on its own evidence: solve-default-wiring closes the audit's one-line gaps on today's routes and lands the default-wiring test first; this plan then defines the contract those routes consume, wires it into the repository's agent guidance so it is the first thing a future agent finds, and brings the transport forwards under the same declared defaults; batched-operator-boundary gives the contract the host-geometry versus member-data boundary that heterogeneous batches need. Nothing here changes solver semantics.

§1 — The request and receipt

Define the public seam as two typed objects in the spirit of the shipped coupling-surface-contract. The solve request carries the machine or persisted carrier identity, the source profile, the seed policy (a cold_seed_portfolio class or an explicit state), the target current, constraint pins, the route, and budgets. The solve receipt carries the terminal state with its qualification and termination reason, the per-trip residual and mask history, the globalisation decisions taken, the amplitude history, the topology read with its polish receipt, the compile-cache hit or miss, wall seconds, and the resolved defaults that actually ran together with the Nova package version that resolved them. Defaults live in one declared table inside Nova, keyed by Nova's own version rather than a separate interface version (lead decision, locked below): current pin on, settled exit on, exact kernels, cached machine, compilation cache on, the Newton–Krylov route with whatever acceptance solver-convergence-regression promotes. A banked row can then never be misread as having run under a policy it did not. Done-when: the two types exist under nova/equilibrium/ with a schema test, ForwardProfile.solve accepts a request and returns a receipt, and the resolved-defaults block round-trips through the JSON receipts the benchmarks already write.

§2 — Migrate the routes onto the contract

Move the drivers onto the request seam in dependency order, each migration a node gated by the seven referee tests and the route's own receipts: the exact bank route and the topology-visuals producer, the EFIT parity slice and the DIII-D GS match, the Solov'ev oracle and certificate, and the imas-ambix consumer (imas_ambix.statespace.nova_ensemble_estimator, which already captures the installed Nova revision). The default-wiring test landed by solve-default-wiring is rewritten to construct a bare request on each route and assert every declared default resolved on. The two EFIT-match evidence documents the lead asked for, one per machine, showing how the Nova forward Grad–Shafranov solve matches the EFIT solves on MAST and DIII-D with the two-source error split, are produced through this seam so their provenance is the recorded resolved defaults; their scientific content is owned by gs-absolute-accuracy-gates §3 and they are regenerated here once the routes are migrated. Done-when: the wiring audit rerun reads DEFAULT-ON in every production cell, the default-wiring test is green in the default lane against the request seam, imas-ambix's consumer gate stays green, every banked receipt produced after the migration carries the resolved-defaults block with the Nova version, and the two per-machine EFIT-match evidence documents cite receipts produced through the seam.

§3 — The transport forwards under the same defaults

Nova's transport capability is further along than the equilibrium seam: flux-function-forward-transport shipped typed native and TORAX-wrapped transport forwards with equilibrium coupling and geometry parity tightened to 1e-10 (nova/transport/forward.py, torax_geometry.py, current_diffusion.py, evolved_state.py, ensemble.py), coupling-surface-contract shipped the 60-field typed coupling state that window exchange, time-parallel boundaries, ensemble state and surrogate I/O consume, and ensemble-forward-seam (active, 0.9) batched the coupled forwards for imas-ambix. So the transport side already has its contract; what it lacks is the same declared-defaults discipline and the same receipt provenance. This section wires the transport request (native versus TORAX route, the coupling state, the equilibrium request it embeds) through the same defaults table and the same receipt block, so a coupled forward records which equilibrium defaults and which transport route ran, with TORAX pinned as the optional extra it is today (pyproject.toml transport = ["torax>=1.4.3"]). Done-when: a coupled transport forward through the seam returns a receipt carrying both the equilibrium resolved-defaults block and the transport route, the ensemble-forward-seam receipts round-trip it, and the imas-ambix consumer reads the transport route from the receipt rather than from its own configuration.

§4 — Agents find the seam first

A default that agents do not know about is a default they route around, which is how the audit's gaps arose. Wire the contract into the repository guidance at the narrowest scope that owns it: nova/equilibrium/AGENTS.md gains a section naming the request and receipt types as the only way to run a forward solve, the declared-defaults table and where it lives, the rule that a benchmark or script never calls the bare fixed-point routine or configures a default by hand, and the default-wiring test as the check to run after touching a route; nova/transport/AGENTS.md gains the same for the coupled forward; the root AGENTS.md gains one pointer line to each; and the reckon-ship prior-art scout brief for this repository names the seam so future nodes cite it in their reuse maps. Done-when: the three AGENTS.md files carry those sections with paths that exist, and a fresh read-only scout dispatched against the plan's own question ("how do I run a forward solve with production defaults") returns the seam as its first row.

§5 — The interactive consumer: coil edits at interactive latency

imas-ambix is planning a physics-supported "play the plasma" demonstrator on MAST: a user edits one coil current, Nova's forward solve returns the moved boundary, and the camera decoder renders the frame. Three things that consumer needs are not yet true of the seam and are owed here. (1) Coil currents as a traced argument. Today external_current is closed into the jitted solve as a constant, so every edit is a fresh compile of several minutes; the request must carry it (and the profile tables and target current) as traced arguments over static host geometry, so an edit is a call, not a compile, and the compilation cache hits. This is the single-member case of the boundary batched-operator-boundary generalises, and it lands here first. (2) A warm-start policy. Seed each edit from the previous edit's converged state rather than the cold portfolio, with the settled exit and the referees unchanged, and measure convergence and trip count across a bounded coil sweep on a converging MAST arm (a frozen-six shot from the persisted carrier, never a marginal diverted arm). (3) The complete labelled flux map in the receipt. The consumer's physics support is the full flux map and topology read, not the LCFS alone: the receipt carries, at no extra compile, ψ and ψN on the hex mesh, the O-point, primary and secondary X-points, the LCFS, the strike points, and the per-cell domain labels the plasma-cell authority actually resolves (32f16b3b, 260a8b44, polish receipt 588578a0): core, private flux and wall shadow, with every other cell outside the LCFS simply open. There is no scrape-off-layer class: the hex plasma cells are not fine enough to resolve the SOL (lead correction 2026-09-02), so the consumer never re-derives topology from ψ and never reads a label the mesh cannot support. The lead's framing of (1) sets the cost model: a coil-current change is a matrix product against the coil Green's matrix, and the only physical cost of an edit should be the warm-started plasma response; the per-edit recompile that follows from external_current being a trace constant is the thing this section removes. Done-when: a warm single-member MAST solve on the H200 with a traced coil edit costs tens of milliseconds per edit (stated as a measured per-edit wall time over a twenty-point sweep of one position coil), the persistent compilation cache reports hits after the first edit, the warm-started solves converge on every sweep point with their trip counts recorded, and the receipt carries the O-point, X-points, LCFS, strike points and per-cell domain labels the imas-ambix consumer reads directly.

§ Decisions

Does the declared-defaults table carry its own interface version, or is it keyed by Nova's version?

A separate api_version would let banked receipts be compared by interface generation independently of the package; the receipt's resolved-defaults block already records what ran.

Lead decision 2026-09-02: no separate API version. The defaults table is keyed by Nova's own package version and every receipt records that version beside the resolved defaults; comparability across banks comes from the resolved-defaults block, and a change of default is a Nova release note, not an interface bump.
