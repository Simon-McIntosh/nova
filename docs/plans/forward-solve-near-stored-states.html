Why this plan exists

The inverse baseline put nova's least-squares class beside imas-efit on three stored reconstructions: MAST-U 45272, one TCV slice and one ITER scenario slice. With imas-efit's fitted currents nova's observation kernels reproduce its rows within 1 % on every sensor family of all three machines, so the inputs are right. No case produced a fit, because the forward solves the class asks for beside those states refuse. On MAST-U the stored state itself qualifies at a residual of 5.3e-16 after one continuation, and the first perturbed solve the fit needs stalls at 1.2e-4 with the active-set step refused. On TCV the solve from the stored field stalls at 0.030 with the same refusal and two cold seeds lose the axis. On ITER the state reached is vacuum-like, no magnetic axis candidate is found, and the residual is not finite.

Those are forward-solve facts, measured by an inverse plan that was not allowed to edit forward or topology code. The lead ruled on 2026-11-17 that the inverse comparison land as a measured negative result and that the refusals be carried to a plan of their own. This is that plan. The measurements it starts from are recorded in docs/evidence/fragments/inverse-equilibrium-baseline/efit-comparison.html.

The boundary this plan keeps. The qualification threshold of 1e-10 does not move and no case is admitted by relaxing it. The plan sequences after converged-forward-solve, which owns the forward solve's convergence on its own case set, and takes only the cases that arise beside a stored imas-efit state, with one exception: §4 makes the public solve run under a batch, which the inverse baseline's cost section needs, and measures it on a state that baseline generated itself. It does not rerun the inverse fit: when §3 lands, the inverse baseline's own sections decide whether the nested class is run again on these machines.

Its record is docs/evidence/archive/forward-solve-near-stored-states-landed.html.

§1 — The three refusals as standing cases

Waits on the inverse baseline's comparison section, whose landing brings the cited record and the stored-case reader onto the branch.

The refusals were met inside a long comparison run. Before anything is changed they are made reproducible on their own, from stored inputs, without the inverse class: each machine's description, imas-efit's fitted conductor currents and profile coefficients, and the stored flux map used as the starting field.

Done when. (1) One batch job on the H200, falling back to titan, runs the cases in sequence and reproduces each refusal under the solver's default policy, started from the stored flux map: the MAST-U solve at the stored coefficients ends unqualified with a residual within a factor of three of 4.9e-10; the MAST-U solve at the displaced coefficients the comparison's fit asked for ends unqualified with the active-set step refused and a residual within a factor of three of 1.2e-4; the TCV solve at the stored coefficients ends unqualified with the same refusal and a residual within a factor of three of 0.030; the ITER solve ends with no magnetic axis admitted. (2) Positive control in the same job: the MAST-U state at the stored coefficients qualifies below 1e-10 when continued from the first solve's terminal state under the tighter stopping tolerance and larger budgets the comparison run recorded, and the record states that policy beside the default one. (3) The record states, per solve, the mesh, the solver route and the coefficient vector, and for the displaced solve the coordinate displaced, its size and its sign, with the terminal reason and residual and one line-contour panel of the terminal state on the stored imas-efit state, on shared levels, with both null sets and the wall.

§2 — Where each solve stops qualifying

Waits on §1, whose standing cases it measures.

A refusal beside a state that itself qualifies does not say how far the solve is from succeeding. This section measures that distance for each case, and says which displaced states can be reached at all by the solve as it stands when it is led there in smaller steps. It makes no claim about whether an unreached state exists.

Done when. (1) For MAST-U the record states, along the coordinate and sign §1 recorded, the largest fraction of the recorded displacement at which the solve qualifies below 1e-10, and the smallest at which it does not where one exists, over the fractions 1/64, 1/32, 1/16, 1/8, 1/4, 1/2 and 1 run in that order, each solve started from the last state that qualified, beginning at §1's positive control and using its policy, all in one batch job on the H200, falling back to titan, at the mesh and solver route §1 recorded, with the device stated in the record. (2) For TCV and ITER, which refuse at the stored coefficients, the record states the terminal reason and residual from two starting routes: the stored flux map under the default policy, and the same start under the positive control's policy. (3) Each case is given one of two verdicts within those stated sets. Reached: for MAST-U the last solve of that sequence, at the full recorded displacement, qualifies, and the MAST-U solve at the stored coefficients counts as reached by §1's positive control; for TCV and ITER either route qualifies. Not reached: otherwise, with where each solve stopped. Negative control: the direct MAST-U solve at the full displacement under the default policy, started from the stored flux map, reproduces the refusal §1 recorded.

§3 — The solves qualify

Waits on §2, which says which cases are owed a repair.

For every case §2 marks as reached, the forward solve is repaired until the solves a reconstruction asks for beside the stored state qualify directly, without being led there. A case §2 marks as not reached is not forced: its record stands, and it stays open against this plan.

Done when. (1) On every case §2 marks as reached, each solve §1 showed refusing at the base revision, at its recorded coefficients and started from the stored flux map under the default policy, qualifies below the unchanged 1e-10 threshold, measured in one batch job on the H200, falling back to titan. (2) Nothing already converging is lost: the forward gate that passes at the base revision passes at the head with no added failure, both arms run in fresh processes on the same device. (3) Negative control: the same job run at the base revision reproduces the §1 refusals. The record carries a line-contour panel per repaired case of the qualified displaced state on the stored imas-efit state, on shared levels, with both null sets and the wall.

§4 — The public solve runs under a batch

Waits on the inverse baseline's row-exchange section, which has landed and whose case, record and solver route it reads; the inverse baseline's cost section waits on it.

The inverse baseline could not measure what a reconstruction costs at batch widths above one. Its attempt ran a route inventory on a MAST carrier (shot 22086, slice 40) on a CPU node and on a P100. The Newton-Krylov route of the public solve refused the batched call with a traced-array conversion on the host; the Picard and Anderson routes ran batched but ended unconverged at a residual of 0.032, batched and unbatched alike; and the unbatched Newton-Krylov solve did not converge either (4.8e-5 on the P100). No route both converged and ran under a batch, so no cost was reported. The lead ruled on 2026-11-18 that batching be made a section here and the cost section wait on it. The receipts are /home/ITER/mcintos/.cache/nova-inverse-equilibrium-baseline/route-inventory-cpu.json and /home/ITER/mcintos/.cache/nova-inverse-equilibrium-baseline/route-inventory-titan.json (titan job 1324349).

A batched entry to the forward solve already exists and carries the accelerated routes over a leading batch axis, so the capability is not new. What the receipts show is one route breaking inside that entry and the others not converging on that carrier. This section therefore adds no second batched surface and no new public entry point: it repairs that route under the existing batched entry, and widens that entry to take the request and return, per state, the receipt fields of the unbatched public solve.

The case this section is measured on is a different one, chosen because its solve is known to qualify alone: the generating state of the nova-written ITER rows, solved at the reference mesh on a device in the inverse baseline's row-exchange section and recorded in docs/evidence/fragments/inverse-equilibrium-baseline/efit-on-nova-rows.html.

Done when. (1) Positive control first: the generating state of the nova-written ITER rows qualifies below the unchanged 1e-10 threshold when solved alone by the public solve's default route, which is the route the inverse class calls and the one the receipts show refusing a batched call; the record names that route. The public forward solve on that route then runs under a batch of 16 and of 64 copies of that same state in one traced program on the H200, and that one call takes the unbatched solve's request and returns per-state converged flags and residuals as arrays of the batch width beside the unbatched receipt's fields for each state, with no host conversion inside the traced solve, with every copy qualifying below the threshold. The same batch with each copy displaced by an independent 1 % change in its profile amplitudes is run as well, and the record reports how many of those qualify; that count is reported, not gated. (2) Each batched state agrees with the same state solved alone with the flux difference at every mesh node within 1e-9 of the axis-to-boundary flux span, and the warm wall per state at width 16 is no greater than the warm wall of one unbatched solve, both measured in one job with compile excluded and the persistent compilation cache contract printed. (3) Negative control: at the base revision the same batched call does not return a per-state converged flag from the device, and the record states how it fails. Nothing already converging is lost: the forward gate that passes at base passes at head with no added failure.
