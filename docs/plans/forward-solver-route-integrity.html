Why this plan exists

The millisecond-converged-solve plan reached 0.88 with its accounting levers landed, and what remains on it is not accounting: the forward solver itself regressed when the mesh arrays became traced (dd7d8286, 2026-09-16), the compiled solve program is two orders of magnitude larger than a converged forward solve should be, and the one change that would shrink it, a single traced evaluator, moved certificate terminal states when it was tried as a frozen-topology interim. These are the difficult remainder of the millisecond target and they were sitting as followups on a plan that reads as nearly done. This plan carries them as sections with their own effort, depth, risk and attempt count so the sprint graph can see them. Evidence records of the parent plan are the inputs; the record of this plan is docs/evidence/archive/forward-solver-route-integrity-landed.html.

§1 — The Newton-Krylov accelerator route terminates at residual 1.29 and the moment-map ladder no longer orders

Two forward-solve regressions dated to the mesh-array tracing commit dd7d8286, both reproducing on CPU. First, profile.solve(seed, route=newton_krylov, newton_steps=8, warmup=40) terminates at a fixed-point residual of 1.2947 on the test machine while the picard route converges below 1e-6, so the accelerated route lost the equilibrium the shared map holds. Second, the finite-difference ladder in test_the_moment_map_is_differentiable_against_finite_differences expects the coarsest step's relative error above 1e-2 and measures 4.46e-4, so either the step scale no longer follows the traced mesh or the analytic Jacobian changed. A local-lane node repaired the two failures that surrounded these (the frozen-partition hook arity and a traced-program cache leak, merged at c0c28f30) and reproduced these two; a codex node is on them now.

Method. Instrument the newton_krylov route's telemetry per step on the test machine (full shapes, never an array converted to a scalar), compare its map arguments against the picard route's at the same state, and find which traced argument or frozen-partition read the Newton-Krylov path consumes differently since the mesh arrays became traced; the commit touched fixed_point.py, forward.py, forward_operator.py and reduced_newton.py. For the ladder, measure the three steps against the analytic Jacobian and decide from the measurement whether the step scale or the Jacobian moved. Never widen a tolerance.

Done when. tests/test_equilibrium_forward_solve.py is green in split all_debug jobs on CPU (the whole file exceeds the 59-minute limit), the H200 lane result is recorded when the reservation has headroom, and the evidence record carries a residual-against-step figure for both routes before and after.

§2 — The solve executable is 900 MB: unroll depth budget and scan the trips

§3 — Carry every solve evaluation through one traced operator state machine

The frozen-topology interim reduced the 300- and 1000-cell optimised solves from 654,832 and 662,331 instructions to 203,078 and 204,531 and cut the cold 300-cell compile from 370 s to 60 s, but it could not land: matched outer-jitted H200 comparisons changed all four required certificate terminal states, the single-null 500 row moving by 2.2e-3 with a non-finite terminal residual. Freezing the topology is not a semantics-preserving substitute for reusing the evaluator. The section implements one lax state machine whose sole operator body serves residual, merit, acceptance, recovery, reconciliation and Jacobian-vector requests while each request retains the exact live read semantics; the boundary proof is that three nested-JIT calls optimise to three inlined bodies.

Done when.
