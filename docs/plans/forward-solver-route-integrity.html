Why this plan exists

The millisecond-converged-solve plan reached 0.88 with its accounting levers landed, and what remains on it is not accounting: the forward solver itself regressed when the mesh arrays became traced (dd7d8286, 2026-09-16), the compiled solve program is two orders of magnitude larger than a converged forward solve should be, and the one change that would shrink it, a single traced evaluator, moved certificate terminal states when it was tried as a frozen-topology interim. These are the difficult remainder of the millisecond target and they were sitting as followups on a plan that reads as nearly done. This plan carries them as sections with their own effort, depth, risk and attempt count so the sprint graph can see them. Evidence records of the parent plan are the inputs; the record of this plan is docs/evidence/archive/forward-solver-route-integrity-landed.html.

§1 — The Newton-Krylov accelerator route terminates at residual 1.29 and the moment-map ladder no longer orders

Two forward-solve regressions dated to the mesh-array tracing commit dd7d8286, both reproducing on CPU. First, profile.solve(seed, route=newton_krylov, newton_steps=8, warmup=40) terminates at a fixed-point residual of 1.2947 on the test machine while the picard route converges below 1e-6, so the accelerated route lost the equilibrium the shared map holds. Second, the finite-difference ladder in test_the_moment_map_is_differentiable_against_finite_differences expects the coarsest step's relative error above 1e-2 and measures 4.46e-4, so either the step scale no longer follows the traced mesh or the analytic Jacobian changed. A local-lane node repaired the two failures that surrounded these (the frozen-partition hook arity and a traced-program cache leak, merged at c0c28f30) and reproduced these two; a codex node is on them now.

Method. Instrument the newton_krylov route's telemetry per step on the test machine (full shapes, never an array converted to a scalar), compare its map arguments against the picard route's at the same state, and find which traced argument or frozen-partition read the Newton-Krylov path consumes differently since the mesh arrays became traced; the commit touched fixed_point.py, forward.py, forward_operator.py and reduced_newton.py. For the ladder, measure the three steps against the analytic Jacobian and decide from the measurement whether the step scale or the Jacobian moved. Never widen a tolerance.

Done when. tests/test_equilibrium_forward_solve.py is green in split all_debug jobs on CPU (the whole file exceeds the 59-minute limit), the H200 lane result is recorded when the reservation has headroom, and the evidence record carries a residual-against-step figure for both routes before and after.

§2 — The solve executable is 900 MB: unroll depth budget and scan the trips

Measured 2026-09-14: the persistent compilation cache holds 1907 entries totalling 7.6 GB, the largest solve executable is 903 MB on disk and two certificate solve programs are 419 and 392 MB; retrieving three entries took 84.5 s; the 1000-cell exact-clip program's HLO exceeds the 2 GiB protobuf limit and cannot be serialised. A converged forward solve should compile to megabytes. The program is unrolled where it should loop: Newton steps and trips as Python loops rather than scans, fixed-capacity candidate tables evaluated in full at every stage, the read inlined per trip, the polygon fan on every cell. This bounds the 1 ms target directly because launch latency scales with kernel count.

Done when. An executable-size gate sits beside the memory gate (solve executable under 50 MB at 1000 cells, HLO op count reported); trips and Newton steps run as lax.scan or while_loop with fixed telemetry slots; the read is evaluated once per trip; a JAX profiler trace of one 1000-cell whole-cell solve on the H200 tables kernel count, launch latency share and compute share; terminal states on the committed 300-cell rows are bit-identical.

§3 — Carry every solve evaluation through one traced operator state machine

The frozen-topology interim reduced the 300- and 1000-cell optimised solves from 654,832 and 662,331 instructions to 203,078 and 204,531 and cut the cold 300-cell compile from 370 s to 60 s, but it could not land: matched outer-jitted H200 comparisons changed all four required certificate terminal states, the single-null 500 row moving by 2.2e-3 with a non-finite terminal residual. Freezing the topology is not a semantics-preserving substitute for reusing the evaluator. The section implements one lax state machine whose sole operator body serves residual, merit, acceptance, recovery, reconciliation and Jacobian-vector requests while each request retains the exact live read semantics; the boundary proof is that three nested-JIT calls optimise to three inlined bodies.

Done when. The four certificate terminal states are bit-identical to the committed rows under the state machine, the instruction count is at or below the interim's, and the compile time is banked beside the census. This is the plan's critical-risk section: it changes the semantics surface of every solve, and its gate is the exact certificate, never a tolerance.

§4 — The pre-warm pin covers none of the lane's programs

Measured 2026-09-18: the pre-warm covers 3292 keys the lane never requests and none of the 1285 keys it does, so the lane's 1341 hits all came from that target's own earlier run on the same directory; a lane that has never run there compiles everything it needs. Add the lane target's program set as pre-warm rows, make the guard's served_entries count program-key cache entries rather than a recursive file count that includes the XLA autotune subtree, and make the guard marker line-anchored.

Done when. A lane run against a directory holding only the pin's keys reports hits for the lane's own programs with zero compile seconds, served_entries equals the count of program-key entries on disk, and an anchored grep finds the marker on a passing run.

The codex run r-20260919T090428129698 holds nova/equilibrium/forward.py and forward_operator.py while blocked; its worktree carries route telemetry tests, a frozen-domain label tracker, the live-map Newton repair and a staged residual-against-step renderer under docs/figures/millisecond-converged-solve/newton-krylov-route/render.py that has not yet produced its figure.

The program size this section owns now blocks another plan's evidence, measured 2026-09-19 on the centroid-constrained positive control. Two all_debug jobs aborted inside LLVM compiling jit_scan, the first at 64G and the second at 180G, both with allocateMappedMemory failed and a core dump at exit 134, the second after a slow-compile alarm and 38 minutes. Tripling the allocation changed nothing, so the constraint is the compiled module rather than the job's memory request. Two things follow for this section. The gate for section 2 should include a CPU arm, since an executable that cannot be compiled on a 180G node is a failure a device-only budget would not catch. And the scheduler signal is not trustworthy here: sacct reported COMPLETED 0:0 for both jobs and for every sub-step while the payload aborted, so the payload log is the only evidence of what happened. The centroid plan's positive control waits on this section rather than on its own node.

Lead ruling 2026-09-20, reordering this plan. Section 2 goes first, ahead of the Newton-Krylov repair and the pre-warm pin, and on the strongest lane. The reason is measured on the compile-abort plan: one compiled solve costs about seventeen thousand memory mappings to load because it is 400 to 900 MB of executable, a process is capped at 65,530, and the certificate needs four loads, so every heavy CPU measurement in the sprint now aborts in compilation. The pre-warm pin is moot until this section shrinks the programs; pre-warming 450 MB programs is what fills a 7.6 GB cache.

The ruling is also a design constraint, stronger than the section's wording of scanning the trips: these processes never loop; they are designed as efficient maps. Newton steps, trips, the per-trip read and the polygon fan over cells are expressed as vectorised maps and scans with fixed telemetry slots, never as Python loops that inline a copy of the body per iteration. A converged forward solve compiles to megabytes.
