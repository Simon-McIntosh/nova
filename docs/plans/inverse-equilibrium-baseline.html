Why this plan exists

Nova's north star is unchanged: nova is the exact forward operator, estimation lives across a typed seam in imas-ambix, and a public forward solve that accepts a measurement array is a test failure. The lead ruled on 2026-11-13 that an inverse class is nevertheless worth carrying in nova as a development instrument, for three uses:

  • Comparison with EFIT. imas-efit has no forward mode: every solve fits p′ and FF′ to the magnetics. A like-for-like comparison therefore needs nova to answer the same question from the same inputs, so that a disagreement can be split into a fit difference and a forward difference.
  • A baseline for new approaches. A new estimator, in imas-ambix or elsewhere, is judged against the plain least-squares answer on the same cases, never against a description of it.
  • A debugging instrument for the forward solve. A fit that closes on data while its own forward re-solve does not reproduce it locates a forward defect that profile freedom was hiding.

The tree already holds several partial inverses, none of which runs through the forward solve's request and receipt: three magnetics-driven reconstructions on reduced models (harmonic, moment and profile; the assembled chain failed 10 of 12 EFIT parity metrics with no converged fraction on MAST, see spine-efit-parity), the pulse-design inverse that solves coil currents for shape targets, and the shape-steering inverse of the playable solve. This plan delivers one inverse class with one contract, and decides what happens to the three reconstructions.

The boundary this plan keeps. The forward solve's public request gains no measurement field. The inverse class is plain weighted least squares with a declared regulariser; priors, noise models, filtering and uncertainty propagation beyond the least-squares covariance remain imas-ambix work. The class reads convention-clean inputs and carries no facility-specific convention module.

Its record is docs/evidence/archive/inverse-equilibrium-baseline-landed.html.

§1 — Known-answer recovery

The inverse class is first judged where the answer is known. A converged forward state with prescribed p′, FF′ and conductor currents supplies synthetic flux-loop, field-probe and plasma-current rows through nova's own synthetic-diagnostic responses; the class is handed those rows, the conductor currents and the wall, and must return the state that produced them. Three states are used: one analytic Solov'ev certificate row, one MAST state and one ITER state, each with a fitted basis that contains the generating profiles.

Done when. (1) With noise-free rows, on all three states, the recovered flux map agrees with the generating state within 1e-6 of the axis-to-boundary flux span in the sup norm over the plasma, the whitened data residual is at or below 1e-8, and a forward solve of the recovered coefficients with no data reproduces the recovered flux map within the forward solve's own tolerance. (2) The fit receipt records, per case, the iteration count, the singular values of the linearised response and every coefficient the data did not determine; the class is callable only outside the forward solve's public request, and the existing test that a forward solve accepts no measurement array still passes. (3) Negative control: the same fit with one flux-loop row's geometry displaced by 5 cm fails clause (1) on the flux map and reports that row as the largest whitened residual.

§2 — The same inputs as EFIT

The decisions fitted-unknowns and vertical-freedom were locked on 2026-11-14: the class fits the profile coefficients and the conductor currents, the currents weighted by their measurement uncertainty, and the vertical position is whatever the magnetics determine, with its residual reported. The bands below are read against a fit of that configuration.

The comparison the lead asked for: the inverse class and imas-efit answer the same question from the same inputs. On ITER that holds for the magnetics rows only: imas-efit's ITER reconstruction also carries a synthesised on-axis pressure point and a q0 prior that the class does not, so the ITER row shares the magnetics and not the constraint set. The case set is read from imas-efit's own committed cases through IMAS, at the data dictionary version each was written in: one slice of imas-efit's own magnetics-only reconstruction of MAST-U 45272 (its stored regression baseline, with monomial p′ and FF′, written at data dictionary 4.1.0, which carries a closed boundary outline on every slice), one TCV slice and one ITER scenario slice, none with an iron core. The comparator on every case is a state imas-efit itself produced; the CCFE references for the same pulse are another code's output, carry no boundary outline and a different flux sign, and are not used. imas-efit carries no MAST case, and the lead chose its MAST-U case on 2026-11-14 so that a stored imas-efit equilibrium exists for every case. For each case the class fits the same number of profile coefficients imas-efit fitted, with the conductor currents treated as the locked decision fitted-unknowns directs, and the vertical position held as the locked decision vertical-freedom directs.

Done when. (1) On every case the class converges and its reconstructed state is compared with imas-efit's stored equilibrium in physical units: magnetic axis within 0.20 m, plasma current within 1.5 %, boundary and axis flux within 5 % of the axis-to-boundary flux span, the magnitude of q95 within 2.0 with the sign each state stores reported beside it, and the mean distance between the two closed boundaries reported in millimetres; the whitened residual per sensor is tabulated beside imas-efit's own for the same rows. imas-efit's fit carries a rigid vertical shift and this fit does not, so the table also reports, per case, the vertical offset between the two current centroids, and the axis and boundary measures both as measured and with that offset removed; the bands are judged on the measured values. The ITER row is reported against the same measures under the label same magnetics, different constraints and is not judged against the bands; the record states the size of its gap, and no prior is added to the class to close it. (2) Each disagreement is split into a fit part and a forward part by one further run per case: imas-efit's fitted p′ and FF′ are solved forward by nova with no data, and the table reports nova-forward against imas-efit and nova-inverse against nova-forward separately. (3) Negative control, constructed to fire under either option of fitted-unknowns: the fit rerun with every magnetics row, the measured plasma current, and the measured conductor currents with their uncertainties all scaled by 1.10 leaves the 1.5 % plasma-current band on every case. The evidence record carries, per case, line-contour flux panels of the nova state beside the imas-efit state on shared levels, with both null sets and the wall, under the repository plotting rules.

§3 — One scoreboard for every estimator

Waits on §2, whose case set and configured fit it scores.

The baseline is only useful if a new approach can be put beside it without re-deriving the comparison. The §2 case set and bands become a scoreboard that accepts any reconstructed state supplied as an IMAS equilibrium, whichever code produced it, and scores it with the same comparator and the same reference-free checks (axis inside the wall, axis inside its own boundary, boundary area at least half its bounding box).

Done when. (1) One published table holds a row per case and a column group per estimator for imas-efit and the nova inverse class, generated from stored states by one command whose receipt names each state's digest. (2) A third estimator's states, supplied as IMAS equilibria, add a column group with no change to the scoring code; this is demonstrated with a deliberately perturbed copy of the nova states, which the table must rank worse than the unperturbed column on every case. (3) The reference-free checks run and are reported for every column, including when the reference comparison passes.

§6 — White sensor noise: is the reported covariance honest?

Reuses the three known states and the fit of §1, which has landed. It needs no EFIT state.

§1 recovers a known state from noise-free rows, so nothing yet tests the uncertainty the fit reports. Here each §1 state is fitted many times, each time from rows carrying independent Gaussian noise, and the scatter of the recovered answers is compared with the covariance the fit receipt states. A fit whose covariance is right can be trusted when it says a coefficient is poorly determined; one whose covariance is wrong cannot, however good its best estimate.

The noise on each sensor is independent of every other sensor and of every other realisation, with a standard deviation of 1% of the root-mean-square signal of that sensor's row family, and the fit is given the same standard deviations as its weights. The row families are the ones the §1 fit already reads: flux loops, field probes and the plasma current. Conductor currents remain supplied data, exactly as in §1, and carry no noise, so the unknowns are the same profile amplitudes §1 fits.

Done when. (1) For each of the three §1 states, over 256 noise realisations, the variance of the recovered coefficients along every principal direction of the receipt covariance, divided by the variance the receipt states, lies inside the chi-square interval for 255 degrees of freedom whose joint coverage over every direction tested on the three states is 99% (about 0.72 to 1.32 for six directions; the node computes the interval for the number it tests and reports it), and the mean reduced chi-square of the whitened residuals is between 0.9 and 1.1. (2) The mean of the recovered coefficients lies within three standard errors of the generating coefficients on every state, and the root-mean-square flux-map error is reported at 0.5, 1 and 2 times the stated noise, growing in proportion to the noise within 20%. (3) Negative control: the same study with the noise drawn at twice the standard deviation the fit is told fails clause (1), with a variance ratio near four. Evidence is one H200 job that runs every realisation of every state, with a table of the variance ratios and one figure per state overlaying the scatter of recovered coefficients on the receipt's covariance ellipse.

§7 — Drifting sensors: 1/f noise over a pulse, beside EFIT

Waits on §6, which shows the white-noise behaviour this section is read against, on §3, whose scoreboard holds the comparator, on §8, which delivers the imas-efit run on rows written by nova, and on two decisions that are now locked: drift-noise-model (a parametric sweep) and efit-on-synthetic-rows (a nova node runs imas-efit).

Integrated magnetic sensors drift: their noise is correlated in time, with more power at low frequency (a 1/f spectrum). On one time slice such noise is only an offset on each sensor and cannot be told from white noise of the same size. Its effect appears over a sequence of slices, where the reconstructed axis, boundary and safety factor wander slowly instead of scattering, and averaging over slices no longer removes the error. That is the long-pulse problem, so the case is ITER.

One stationary ITER state is held fixed for a sequence of slices. Each sensor carries noise whose power falls as frequency to the power minus the spectral index above a corner frequency and is flat below it, drawn independently per sensor; the reference sequence has spectral index 1 (1/f), and the spectral index and the corner frequency are both swept, and a second sequence carries white noise of the same root-mean-square size. The nova fit and imas-efit both reconstruct both sequences from the same rows, written as IMAS magnetics. imas-efit is run through the path §8 delivers, magnetics-only with its pressure and q0 priors disabled, so both codes carry one constraint set; the configuration read back from each output confirms it. If the priors cannot be disabled, every imas-efit column carries the §2 label same magnetics, different constraints and the two codes' drift measures are not read as a like-for-like comparison.

Done when. (1) Over at least 200 slices, for each code and each noise sequence, the table reports the root-mean-square error and the slice-to-slice correlation (lag one) of the magnetic axis position, the boundary flux and q95, and the error of the mean over 50 consecutive slices beside the single-slice error. (2) The control holds: on the white sequence the lag-one correlation of every reported quantity is within 0.15 of zero for both codes, and on the 1/f sequence it exceeds 0.5; a generator or pipeline that fails this is repaired before any comparison is read. (3) With the noise size swept upward from the §6 level, the record states for each code the size at which the root-mean-square error against the held generating state first exceeds 0.05 m on the axis position and 0.2 on q95, and whether the nova receipt's per-slice covariance understates the error of the 50-slice mean, with the ratio. (4) At the reference noise size, the spectral index is swept over at least three values from 0.5 to 2 and the corner frequency over at least three values spanning two decades, and the table reports for each code the lag-one correlation and the error of the 50-slice mean at every point, with the swept ranges stated. Figures: per code, the axis position against slice index for both sequences on one panel, and one overlaid contour panel of the two codes' states at the slice of largest disagreement.

§8 — imas-efit on rows written by nova

Reuses the ITER machine and the fit of §1, which has landed. §7 compares the nova fit with imas-efit on synthetic rows that only nova can generate, and the decision efit-on-synthetic-rows gives the run to a nova node. No nova node has yet written magnetics for imas-efit to read, and imas-efit's stored ITER configuration adds a synthesised pressure point and a q0 prior that a magnetics-only comparison must not carry. This section delivers that run on its own, on noise-free rows where the answer is known, so that §7 measures drift and not wiring.

The generating state is a forward solve on the §1 ITER machine whose p′ and FF′ are members of the basis imas-efit resolves for this run, and the nova fit is given the same functions, so both codes' fit functions contain the generating profiles and a disagreement is wiring, not basis mismatch. Its synthetic magnetics rows, with the conductor currents and the machine description imas-efit needs, are written as IMAS data at one stated data dictionary version. imas-efit is run on them from the nova side with its pressure and q0 priors disabled, and its output is read back through IMAS.

Done when. (1) imas-efit converges on the noise-free rows, and the record states its code revision and, per flux function, the basis, the live coefficient count and the edge constraint it resolved, read from its output or its run log, with the priors shown disabled. (2) Its reconstruction is compared with the generating state in physical units: magnetic axis position, plasma current, boundary and axis flux as a fraction of the axis-to-boundary span, and q95, tabulated beside the nova fit of the same rows. For both codes the plasma current agrees with the generating state within 1.5 %, the magnetic axis position within 0.02 m, the boundary and axis flux within 2 % of the axis-to-boundary span after each state's stored flux sign is read, and the magnitude of q95 within 0.1 with the sign each state stores reported beside it; these bands sit below the thresholds §7 reads as drift. (3) Negative control: with every magnetics row, the measured plasma current and the conductor currents all scaled by 1.10, the plasma current imas-efit reconstructs leaves the 1.5 % band. The evidence record carries one overlaid line-contour panel of the imas-efit state on the generating state, on shared levels, with both null sets and the wall.

§ Decisions

Where does the 1/f noise model in §7 come from?

§7 needs a noise size and the two frequencies bounding the 1/f range for each sensor family. No such figures are recorded in nova. A swept model claims nothing about the real sensors and finds the size at which each code fails; a specified or measured model ties the result to hardware but needs a source the plan does not hold.

Lead's ruling of 2026-11-15, given through the decision census: a specified or measured spectrum applies only where real data exists, and ITER is synthetic, so the study sweeps spectral index and corner frequency. The lead's words: "this is only possible for real data, iter is synthetic".

Who runs imas-efit on nova's synthetic noisy rows in §7?

§2 reads equilibria imas-efit already stored. §7 needs imas-efit run on new inputs that nova writes, which no section of this plan does yet. Running it from nova needs imas-efit's entry point to accept an ITER magnetics-only case built by nova; handing the rows to the imas-efit session keeps each code with its owner but adds a cross-session dependency.

Lead's ruling of 2026-11-15, given through the decision census: a nova node builds and runs imas-efit on the synthetic noisy rows and nova owns the EFIT configuration, matching the resolved fit configuration that imas-efit's equilibrium-fit-provenance plan records.

What does the class fit on the EFIT comparison cases?

Lead 2026-11-14: fit the profile coefficients and the conductor currents, each current weighted by its measurement uncertainty, so the fit carries the same unknown set as imas-efit and a disagreement is not confounded by a different one.

Does nova carry an inverse class at all, given the north star?

Lead 2026-11-13: nova is not an inverse code and the strategy stands, but an inverse class is useful for development, for comparison with EFIT and as a baseline when developing new approaches. The forward solve's public request gains no measurement field.

Once the scoreboard exists, do the harmonic, moment and profile reconstructions stay?

How is the vertical position of an elongated plasma held during a fit?

Lead 2026-11-14: the current centroid is determined by the magnetics and its residual is reported; no rigid shift freedom is added, so a vertical drift shows as a result and cannot absorb a forward-solve defect.
