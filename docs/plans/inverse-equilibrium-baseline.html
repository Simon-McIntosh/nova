Why this plan exists

Nova's north star is unchanged: nova is the exact forward operator, estimation lives across a typed seam in imas-ambix, and a public forward solve that accepts a measurement array is a test failure. The lead ruled on 2026-11-13 that an inverse class is nevertheless worth carrying in nova as a development instrument, for three uses:

  • Comparison with EFIT. imas-efit has no forward mode: every solve fits p′ and FF′ to the magnetics. A like-for-like comparison therefore needs nova to answer the same question from the same inputs, so that a disagreement can be split into a fit difference and a forward difference.
  • A baseline for new approaches. A new estimator, in imas-ambix or elsewhere, is judged against the plain least-squares answer on the same cases, never against a description of it.
  • A debugging instrument for the forward solve. A fit that closes on data while its own forward re-solve does not reproduce it locates a forward defect that profile freedom was hiding.

The tree already holds several partial inverses, none of which runs through the forward solve's request and receipt: three magnetics-driven reconstructions on reduced models (harmonic, moment and profile; the assembled chain failed 10 of 12 EFIT parity metrics with no converged fraction on MAST, see spine-efit-parity), the pulse-design inverse that solves coil currents for shape targets, and the shape-steering inverse of the playable solve. This plan delivers one inverse class with one contract, and decides what happens to the three reconstructions.

The boundary this plan keeps. The forward solve's public request gains no measurement field. The inverse class is plain weighted least squares with a declared regulariser; priors, noise models, filtering and uncertainty propagation beyond the least-squares covariance remain imas-ambix work. The class reads convention-clean inputs and carries no facility-specific convention module.

Its record is docs/evidence/archive/inverse-equilibrium-baseline-landed.html.

§1 — Known-answer recovery

The inverse class is first judged where the answer is known. A converged forward state with prescribed p′, FF′ and conductor currents supplies synthetic flux-loop, field-probe and plasma-current rows through nova's own synthetic-diagnostic responses; the class is handed those rows, the conductor currents and the wall, and must return the state that produced them. Three states are used: one analytic Solov'ev certificate row, one MAST state and one ITER state, each with a fitted basis that contains the generating profiles.

Done when. (1) With noise-free rows, on all three states, the recovered flux map agrees with the generating state within 1e-6 of the axis-to-boundary flux span in the sup norm over the plasma, the whitened data residual is at or below 1e-8, and a forward solve of the recovered coefficients with no data reproduces the recovered flux map within the forward solve's own tolerance. (2) The fit receipt records, per case, the iteration count, the singular values of the linearised response and every coefficient the data did not determine; the class is callable only outside the forward solve's public request, and the existing test that a forward solve accepts no measurement array still passes. (3) Negative control: the same fit with one flux-loop row's geometry displaced by 5 cm fails clause (1) on the flux map and reports that row as the largest whitened residual.

§2 — The same inputs as EFIT

Deferred until the decisions fitted-unknowns and vertical-freedom are locked: they fix what is fitted, and the bands below are only meaningful against a fit of the same configuration.

The comparison the lead asked for: the inverse class and imas-efit answer the same question from the same inputs. The case set is read from imas-efit's own committed cases through IMAS, at the data dictionary version each was written in: one MAST slice, one TCV slice and one ITER scenario slice, none with an iron core. For each case the class fits the same number of profile coefficients imas-efit fitted, with the conductor currents treated as the locked decision fitted-unknowns directs, and the vertical position held as the locked decision vertical-freedom directs.

Done when. (1) On every case the class converges and its reconstructed state is compared with imas-efit's stored equilibrium in physical units: magnetic axis within 0.20 m, plasma current within 1.5 %, boundary and axis flux within 5 % of the axis-to-boundary flux span, q95 within 2.0, and the mean distance between the two closed boundaries reported in millimetres; the whitened residual per sensor is tabulated beside imas-efit's own for the same rows. (2) Each disagreement is split into a fit part and a forward part by one further run per case: imas-efit's fitted p′ and FF′ are solved forward by nova with no data, and the table reports nova-forward against imas-efit and nova-inverse against nova-forward separately. (3) Negative control, constructed to fire under either option of fitted-unknowns: the fit rerun with every magnetics row and the measured plasma current scaled by 1.10 leaves the 1.5 % plasma-current band on every case. The evidence record carries, per case, line-contour flux panels of the nova state beside the imas-efit state on shared levels, with both null sets and the wall, under the repository plotting rules.

§3 — One scoreboard for every estimator

The baseline is only useful if a new approach can be put beside it without re-deriving the comparison. The §2 case set and bands become a scoreboard that accepts any reconstructed state supplied as an IMAS equilibrium, whichever code produced it, and scores it with the same comparator and the same reference-free checks (axis inside the wall, axis inside its own boundary, boundary area at least half its bounding box).

Done when. (1) One published table holds a row per case and a column group per estimator for imas-efit and the nova inverse class, generated from stored states by one command whose receipt names each state's digest. (2) A third estimator's states, supplied as IMAS equilibria, add a column group with no change to the scoring code; this is demonstrated with a deliberately perturbed copy of the nova states, which the table must rank worse than the unperturbed column on every case. (3) The reference-free checks run and are reported for every column, including when the reference comparison passes.

§4 — Cost on the H200

A baseline that cannot be run over a pulse is of little use for development. The cost of one reconstruction is measured where the forward solve's cost is decided, on the H200.

Done when. (1) The record reports, for the §2 MAST case at batch widths 1, 16 and 64, the warm wall per slice, the forward solves per reconstruction and the cold compile wall, measured in one H200 job with the persistent compilation cache contract printed. (2) The warm wall per slice at width 16 is at or below ten times the warm forward solve's wall per slice at the same shape and batch width, both measured in that job with compile excluded. A larger figure fails this clause: the record then names the step responsible with its share of the wall, and the section stays open. Negative control: the same measurement with the reconstruction's convergence exit disabled and its iteration cap doubled exceeds the ceiling. (3) imas-efit's recorded per-slice wall for the same case is quoted beside it with its hardware.

§5 — The reduced-model reconstructions

Deferred until the decision reduced-reconstructions is locked on the §3 table. If the lead rules that the inverse class supersedes them, the harmonic, moment and profile reconstructions and their parity chain leave the tree and every consumer moves onto the class or is deleted with them; if they stay, each is entered on the §3 scoreboard as its own column so its standing is measured rather than assumed.

Done when. The decision is locked and either (a) no import of the three reconstructions remains under nova, tests, scripts or benchmarks and the fast test lane adds no failure against its base, or (b) the §3 table carries one column group per retained reconstruction.
