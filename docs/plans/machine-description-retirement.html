§1 — Nova is a physics solver; producing data is not its job

Nova grew a description-packaging layer because something had to carry the MAST geometry and nothing else did. That layer is now three separable things, and all three are better served elsewhere: a bespoke registry schema with its own digest scheme, a content-addressed artifact cache with an OCI reference helper that nothing publishes through, and a machine-specific builder that loads one machine's shot into IDSs. The map-driven producer in imas-ambix replaces all three generically, so this plan removes them rather than maintaining a second implementation.

The geometry is not what is being retired. The conductor and sensor description — including the restored P4-lower loop positions that made all 44 described loop positions unique and lifted the solve-input join from 39 to 43 of 46 reconstruction loops — is real, validated physics and migrates intact into the MAST map. What goes is the wrapper around it.

§2 — What changed since authoring, and what still has to go

Re-authored 2026-08-26: the 2026-08-13 text described a repository that no longer exists. Between 2026-08-20 and 2026-08-23 the active DIII-D onboarding (S10) rebuilt and extended the very layer this plan retires: nova/imas/mast_artifact.py was renamed and generalized machine-generic as nova/imas/machine_artifact.py (commit 0dfda59a, rename similarity R094); the OCI helper gained a real publisher — nova/scripts/diiid_machine_artifact.py (513 LOC: oras login / push --image-spec v1.1 / pull, a ghcr.io reference validator, and tests/test_diiid_artifact_publication.py) with a concrete published tag recorded in the S10 plan and the owner's oras push still outstanding; and the layer gained an owner-directed capability, the DDv4 publication floor (latest_publication_dd_version() / publication_dd_version(), commit 1df19c16, implementing the ddv4-latest-native decision of 2026-08-20). The old §2 argument that "nothing publishes through the helper" is therefore false today.

What remains true, and still motivates this plan for MAST: physical_digest answers "is this the same machine?" as a single global question, which a machine whose geometry changes across and within campaigns cannot satisfy — every description move has needed a coordinated cutover touching the packaged registry, digest pin files, a published tag and a downstream pinned constant. The producer's replacement asserts determinism, partition consistency and visible change instead. The retirement scope must now distinguish the MAST-specific bespoke surfaces (retire) from the machine-generic publication capability the owner directed into existence (re-home in the producer, never drop — in particular the DDv4 floor).

§4 — Sequencing and the consumer coupling

This plan runs LAST — behind S10, S15 and S16. DIII-D publishes through the layer today with the owner push outstanding (S10, deadline 2026-10-18), and the catalog's validated forward route is digest-pinned through the machine description (782e9e08, consumed by the S15/S16 chain). The external dependency (imas-ambix:machine-map-transform-engine) is satisfied for STARTING the equivalence demonstration — the producer exists with machine_maps/mast.json and diii-d.json — but not for starting any deletion: the dependency currently runs backwards from this plan's assumption, with ambix importing and asserting on nova.imas.machine_artifact rather than superseding it, and the ambix nova dependency is an editable path pin tracking nova HEAD, so a deletion here breaks ambix the same day unless the consumer moves in the same beat.

On the open removal-style decision: circumstance has largely foreclosed "clean deletion in one beat" — a live publication path and an owner-directed capability cannot be deleted in one beat without either a deprecation window or a scope cut that retires only the MAST-specific surfaces while the producer absorbs the generic capability. The decision should be re-put to the owner against this corrected inventory.

Done-when: every surface in the §3 inventory removed or re-homed per its disposition, with the geometry verified equivalent through the producer beforehand — the same 44 unique loop positions and the same 43-of-46 join, demonstrated numerically, not asserted; the DDv4 publication floor re-homed in the producer with its refusal test carried over; the calibration package decoupled from the registry; the ambix geometry source and identity tests migrated in coordination; and the full suite green at its accepted failure set with no new failure.
