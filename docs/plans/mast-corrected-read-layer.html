§1 — Objective

Make corrected reads a property of the architecture, not a habit of the caller. The diagnostic-correction machinery is landed and proven: the LinkML schema, the MAST instance (128 corrections over 76 probe channels), and the application engine in nova/calibrate/corrections.py all shipped, and the acquisition-scale cutover was proven float-equal on 3,395 reads before the legacy table was deleted. But the goal the machinery exists for — transforms always robustly applied, without changing on-disk data — fails today for three independent reasons, none of them performance (the engine costs ~0.9 ms/shot after a one-time ~117 ms document load):

  1. Only one correction kind is wired. The MAST read path draws kinds=(acquisition_scale,) alone (nova/imas/mast_block_scale.py:762). The five promoted gains, the pair states, and the exclusions in the same document change nothing on any read — and test_the_read_path_divides_by_no_promoted_gain pins the gains out, contradicting the schema's own definition of promoted ("measured, corroborated, and applied by the read path").
  2. Application is opt-out. The three correcting functions each take a block_scale keyword that silently disables correction when handed a bare table.
  3. Nine-plus direct zarr doors bypass the layer. Worst case, nova/imas/mast_flux_loop_adjudication.py calls the corrected reader and then re-opens the same group raw four times (lines 807, 919, 1051, 1120). Today those channels carry no correction so the numbers agree — promote one flux-loop gain and the four sites silently serve raw data.

This plan is routing and enforcement, not new machinery — and it is the data-side prerequisite of mast-catalog-gpu-solve, whose ingest stage must stream corrected solve inputs.

§2 — Design: one door, full chain, explicit raw

  • Single door: read_shot_waveforms (nova/imas/mast_vacuum_cohort.py:911) is already the funnel for time base, drives, plasma current, probe channels, provenance and window masking, and already returns scale_corrections beside the data. Every other zarr.open_group site on the sensor groups is deleted and re-routed through it.
  • Full promoted chain: widen the chain from kinds=(acquisition_scale,) to every promoted kind in ApplicationStage order (the order is a schema property mirrored by APPLICATION_ORDER with an agreement test). The five gains enter the arithmetic per the locked promoted-gains-applied decision in diagnostic-correction-schema; the vacuum-floor bench re-runs to quantify the shift before the pinning test flips.
  • Disposition semantics preserved: refused and unmeasured channels come back untouched — never divided by 1.0 — and the MEASURED / BRACKETED / REFUSED / UNMEASURED disposition (plus CorrectionChain.extrapolated) states whether a correction happened. Exclusions and indeterminate channels keep their refuse-unless-resolved contract.
  • Raw stays explicit: the read-as-published path survives as one named object (the pattern mast_acquisition_sweep.py already uses), so calibration tooling that must see the archive raw says so in its own name — no silent None-default kwarg.
  • Performant on the hot path: index the document by (channel, kind) once at load. Today's chain build is a linear scan over all 128 corrections per channel (~9,700 record visits per shot); a full-archive sweep of 17,000 shots costs ~16 s of pure chain building that the index collapses to near-constant per channel. On-disk data is never rewritten; correction is a pure function of (document version, channel, pulse, time).
