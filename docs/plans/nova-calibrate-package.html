§1 — What exists, and why it must stop being scripts

The vacuum-floor and misfit programmes produced a complete diagnostic-calibration ladder that is demonstrably machine-portable physics — nothing in a through-origin gain fit, a free current inversion, or a filament localization scan is MAST-specific — yet it lives as one-shot scripts under ~/.cache/nova-mast/ and as mast_-prefixed modules inside nova.imas. Every future machine (and every future MAST session) re-derives the machinery or copies it. Edlington (2001) makes the case sharper: MAST's own commissioning calibrated its Rogowski system from designed vacuum shots with a matrix solve — the approach is standard practice; what is missing is a durable, tested implementation.

§2 — Architecture

  1. Machine-agnostic kernels. nova/calibrate/ holds numerics only: every function takes arrays and channel metadata (positions, axes, response columns), never a store path or shot number. The existing signatures are already close — the couplings recompute needed only probe poses, a response matrix and drive waveforms.
  2. Per-machine adapters stay in nova.imas. Store readers, cohort selection, channel naming and drive maps remain machine code (mast_vacuum_cohort and friends), now thinned to adapters that feed the kernels. The MAST modules are the first adapter, not the pattern.
  3. Corrections flow through the schema. All fitted quantities — gains, offsets, drift rates, scale steps, pair states, exclusions — are emitted and consumed as diagnostic-correction-schema documents, replacing in-code constants like PROMOTED_CHANNEL_SCALES. Read-path application order is fixed and tested: offset, drift, scale step, gain.
  4. Naming discipline. Modules and functions named by mechanism (gain.through_origin_fit, inversion.identifiability), never by campaign, machine, or investigation.

§3 — Test strategy

  1. Unit lane is synthetic and store-free. Every kernel is tested against manufactured truth: a known filament field through the analytic loop formulas (already validated against the polygon kernel), synthetic drive waveforms with injected gain errors, scale steps at exact rungs (1/2, 1/√2, √2, 2), drift ramps, and pair-failure state sequences. Recovery to stated tolerance is the assertion. uv run pytest tests/calibrate/ runs with no data mounts.
  2. Regression pins from the banked record. The MAST results this machinery already produced become fixture-pinned regression tests on small extracted arrays committed with the tests (couplings for a handful of channels, the obr17 gain, one identifiability spectrum) — the numbers in the research records must keep reproducing.
  3. Store-backed integration tests are opt-in behind the existing data-availability flags, mirroring the norma-corpus pattern; they never gate the default suite.
