§1 — Finding: the directory does not hold nova's JAX code

The hygiene audit (2026-08-08) established that the bulk of nova's JAX-traced physics compute is not in nova/jax/. Roughly 6,750 lines across ~14 modules in nova/biot/ thread an xp array-namespace parameter and run under both numpy and JAX; further traced compute lives in nova/equilibrium/profile.py, nova/transport/current_diffusion.py, nova/biot/tiledassembly.py and nova/circuit/propagate.py. nova/jax/ holds thirteen modules that happen to be JAX-only. The directory name therefore promises a completeness it does not deliver.

That gap is not cosmetic — it actively attracts misfiled code. Two pure-numpy modules had drifted in and were moved out during the hygiene sweep: wall_mask.py (375 lines of numpy raster geometry, now nova/equilibrium/wall_mask.py) and equilibrium_labels.py (constants, now nova/equilibrium/labels.py). A directory named after a library collects whatever sits near that library's stack, regardless of what it does.

nova/jax/ is also the package's only technology-organised directory. Every other one — biot, equilibrium, transport, geometry, frame, circuit, linalg — is filed by what the code does. Filing by what it imports splits four domain concepts across a seam, so a reader looking for "the operator" or "the field-null code" finds half of it:

The consumer census settles the direction. Eleven of thirteen modules are imported from a domain package, and none of the thirteen is consumed by nova/jax/ as a coherent unit. Only two — config.py (the jax_enable_x64 owner) and tree_util.py (pytree registration) — are genuine library support with no domain at all.

§2 — Target shape

Each module moves to the package that consumes it, and the traced implementation is stored in the same file as its numpy or numba peer rather than in a parallel module. Where a concept already has both halves — the operator, the field nulls, null selection, the polynomial basis — the move is a merge into one file, not a relocation of two.

The traced path becomes the default. nova is aimed at GPU compute and at derivative-based coil fitting, and JAX is what supplies both; the host implementations stay as the checking reference and the legacy route, reached explicitly rather than by default.

Correction to the plan's own premise. An earlier draft described this as inverting today's arrangement, "where the numpy implementation is the one a caller reaches first and the traced one is the alternative selected at nova/biot/operate.py:84". Both halves are wrong, and the error matters because it inflates how much of this plan is new work. Line 84 is inside the host operator's turn update. The real selection is at :97-100:

try:  # jitted operator is the primary path; numpy is the fallback
    from nova.jax.operate import BiotOperator as Operator
except ImportError:  # jax extra absent
    Operator = NumpyOperator

It executes once at import and binds a module global that Operate.load_operators constructs through at :184, so all eight biot solvers silently receive the traced operator whenever import jax succeeds. For the operator, traced-default is therefore a ratification of live behaviour, not an inversion — which is also why the single-precision default in §6 has gone unnoticed: it has been the shipped default all along.

Keeping both implementations in one file is also what makes the pair testable as a pair. This sweep has already found three divergences that existed precisely because the two halves sat in different files: the Force index that was read from the caller on one side and silently from the dataset on the other; the degenerate-fit guard present in one biquadratic copy and absent from the other; and the wall_flux zero-polarity answer, which is NaN on the traced side and (0, 0, 0) on the serial one. Co-location does not prevent divergence by itself, but it puts the two implementations and their parity test in front of the same reader.

§3 — The naming, settled

Two modules cannot both be nova/geometry/select.py, so the technology seam has to surface somewhere. With both implementations in one file the seam moves inside the module, and the question becomes what to call the two entry points.

Both entry points carry an explicit token: traced_ and host_. Neither implementation takes the bare name. Where an import-time selection alias already exists — today only nova/biot/operate.py — the bare name is reserved for that alias, bound to the traced implementation when JAX is present and to the host one when it is not. So the bare name never denotes an implementation; it denotes "whichever was selected", which is exactly what it already means at :97-100.

This satisfies both locked decisions without contradiction. A caller who does nothing still reaches the traced path (default-path = traced-default), while every implementation is named for the mechanism that distinguishes it, so no reader has to know which half a bare name resolves to.

Why host, given both halves are compiled

The host peers are not "the uncompiled ones", and they are not one library. nova/geometry/select.py:105 is @njit(cache=True) — numba, not JAX. nova/biot/operate.py:25 is a plain dataclass with no jit at all. nova/linalg/basis.py is scipy. That heterogeneity is precisely why a library token cannot serve: _numpy is false for the numba peers, _numba is false for the operator, and _jax names the very seam this plan deletes. The property all three share is where and how they execute — eagerly, on the CPU, under Python control flow — and host names it. The vocabulary is already in the tree: greens.py:57 prints "the section twin runs 1.2 to 1.6 times the host" and flux_surface_connectivity.py:220 opens "Host adapter: run …".

The token is not perfect and the boundary should be stated rather than discovered: a jax.jit function on a CPU-only machine also runs on the host. traced names its side precisely — traced into an XLA graph, hence device-portable, differentiable, and free of data-dependent branching. host names the complement by where it is pinned. Note too that njit degrades to a pass-through when numba is absent (nova/__init__.py:50-68), so a "host" route may be interpreted Python.

Dependency-named symbols are retired repo-wide

The same rule that forbids jax_select as a filename forbids NumpyOperator as a class name — it names a dependency, not a mechanism, and it is false the moment the implementation stops being numpy. Every such name goes:

Measurement method and gate rationale

The plan as first written assumed all thirteen modules want the same treatment. They do not, and the tree already contains three distinct arrangements — only one of which is a problem.

Arrangement 2 is the one to imitate, and it is worth being precise about what justifies it, because it also corrects a common assumption about why the traced route exists. Measured in benchmarks/greens_elliptic_route.py and recorded at nova/biot/greens.py:44-77: the traced filament twin runs 1.9 to 3.9 times the host over 64 to 65536 targets, and the section twin 1.2 to 1.6 times. The traced route is slower on CPU, because the differentiable Bulirsch descent costs 6 to 50 times the Cephes ellipkm1/ellipe pair per element. Tracing buys GPU portability and autodiff; on host per-element work it pays for them. "Traced by default" is a statement about the target hardware, not a claim of universal speed.

Gate. Each of the eleven pairs is measured before it is merged, on the model of greens_elliptic_route.py: cost across the argument regime the call sites actually reach, accuracy against a reference neither route can be, and an explicit statement of every semantic difference. Each pair then lands in exactly one outcome, recorded with its numbers:

  • Collapse — the arithmetic is identical, so one xp-threaded body replaces both and the pair stops existing. No naming decision applies.
  • Keep both — a measured cost or semantic difference justifies the duplication, as with greens. Merge into one file under the §3 names, with the justification written into the module docstring the way greens.py:44-77 does it.
  • Delete one — the peer is unused, unreachable, or strictly worse. Remove it; no merge needed.

A pair may not be merged on the assumption that both halves are wanted. The measurement is the deliverable that licenses the merge.

§ Decisions

Should the traced and serial implementations of a concept live in one file or stay as paired modules?

Owner decision 2026-08-08: both implementations stored in a single file. The split across files is what let three divergences accumulate unnoticed in this sweep alone — the Force index lookup, the degenerate-fit guard, and the wall_flux zero-polarity return. One file puts the pair and its parity test in front of the same reader.

Which implementation should a caller reach by default?

Owner decision 2026-08-08: the traced path is the default. nova is aimed at GPU compute and derivative-based coil fitting, and JAX supplies both. The numpy and numba implementations remain as the checking reference and the legacy route, reached explicitly. This inverts today's arrangement, where the traced operator is the alternative selected at nova/biot/operate.py:84.

What names distinguish the two implementations inside one module, given the repository forbids version-flavoured names and the default is now the traced one?

Owner decision 2026-08-09: both implementations carry an explicit mechanism token, traced_ and host_. Neither takes the bare name. Where an import-time selection alias already exists (today only nova/biot/operate.py:97-100) the bare name is reserved for that alias, bound to the traced implementation when JAX is present and the host one when it is not -- so a bare name never denotes an implementation, only 'whichever was selected'. This satisfies default-path=traced-default (a caller who does nothing still reaches the traced path) while naming every implementation for its mechanism. host_ is chosen over a library token because the host peers are not one library: numba at geometry/select.py:105, bare numpy at biot/operate.py:25, scipy at linalg/basis.py -- so _numpy, _numba and _jax are each false somewhere, and _jax names the very seam this plan deletes. The token names where and how the code executes: eagerly, on the CPU, under Python control flow. Boundary to state explicitly: a jax.jit function on a CPU-only machine also runs on the host; 'traced' names its side precisely, 'host' names the complement by where it is pinned. The existing traced_ family in nova/biot is kept and its host peers gain host_ as they are touched, so one convention holds package-wide. Dependency-named symbols are retired repo-wide by the same rule: NumpyOperator becomes HostOperator, and the *_jax suffixes in connectivity_boundary, flux_surface_connectivity and transport/current_diffusion become traced_ prefixes.

May a pair be merged before its two halves have been measured against each other?

Owner decision 2026-08-09: measure before merge. The tree holds three arrangements, not one: the xp-threaded single body across ~14 biot elliptic modules (no duplication, no divergence possible); the traced_ twins in greens and zeta whose duplication is justified by benchmark and semantics at greens.py:44-77; and the eleven nova/jax pairs, which have never been measured and in which three divergences accumulated plus at least one unreachable member (jax/select.py:50 bisect_2d assigns into a jnp.zeros array, which JAX rejects). Merging first would freeze eleven unjustified duplications into the domain packages and make them permanent. Each pair is measured on the model of benchmarks/greens_elliptic_route.py -- cost over the argument regime the call sites reach, accuracy against a reference neither route can be, and every semantic difference stated -- and lands in exactly one verdict: collapse to one xp-threaded body, keep both with the justification written into the module docstring, or delete the dead half. A pair that collapses needs no naming decision and no merge. Note the measurement can invert the usual assumption: greens measures the traced filament twin at 1.9-3.9x the host and the section twin at 1.2-1.6x, because the differentiable Bulirsch descent costs 6-50x the Cephes pair per element. Tracing buys GPU portability and autodiff, not universal speed.

The traced operator never calls enable_x64(), so the default path evaluates in single precision. Keep, fix, or pin?

Owner decision 2026-08-09: single precision is retained deliberately for the traced path -- the target is high-throughput GPU solve, where the fp64 rate penalty is severe, and that is what the traced route exists to serve. But it must stop being accidental. Measured on main 2026-08-09: inner jnp dtype float32, evaluate float32, coilset.plasmagrid.psi float32, max rel diff vs the host 5.667e-08, while the live numpy view stays float64. Three obligations follow. (1) Pin it: precision is currently import-order dependent -- with enable_x64() called earlier in the process the same operator is float64 end to end -- and this merge changes import order by construction, so a dtype assertion plus a captured reference array must prove the merge did not move it. (2) The existing tests cannot see it: every cross-implementation assertion leaves rtol at numpy's default 1e-5, three to four decades looser than the 5.7e-08 gap, so a green suite is NOT evidence precision was preserved; only test_force_index_gain_agrees_across_implementations:200 acknowledges the divergence and it accommodates rather than pins it. (3) Amend the stated policy: nova/jax/config.py declares fp64 'mandatory rather than a preference' for exactly this class of quantity, so the deliberate exception is recorded there with its throughput justification and accuracy bound. A policy contradicted by the default path is worse than no policy. Related mechanism to make deliberate in the same pass: Operate.check_source:342 rebinds self.array[attr] to whatever dtype evaluate returned while __getattr__:292 writes in place into the pre-allocated float64 array, so the shaped and unshaped views can sit at different dtypes.

The host and traced halves of the select pair return different shapes and answer degenerate cases differently. Converge or preserve?

Owner decision 2026-08-09: converge on the traced convention. The asymmetry is forced rather than arbitrary -- JAX cannot branch on a traced value to raise a Python exception, so a traced kernel must fold the classification into its return and signal degeneracy with a sentinel -- but the codebase has already written down which convention is correct, in the HOST's own docstring at nova/geometry/select.py:117-122: '(0, 0, 0) is a well-formed coordinate and flux, so a caller cannot tell it from a real result; the traced convention is the safer one, and moving to it would change what Limiter.update_wall publishes at zero plasma current.' So: wall_flux returns the 4-array with NaN at zero polarity on both sides; null_type returns NaN where the host raised ValueError('Plane surface'); null_coordinate adopts the traced Hessian-determinant floor of 1e-30 on both; subnull takes one signature, decided by the measurement. This is a deliberate behaviour change with a known blast radius -- one live consumer at nova/biot/limiter.py:56 unpacking three values, with the traced call commented out one line above -- so it lands as its own commit with its own zero-plasma-current test, and is not resolved silently by whoever converts the module. Until it converges the import-time fallback is itself a hazard: in a JAX-free process a bare name would bind to a host peer of different arity, so either converge first or let the traced name be absent without JAX, but never fall back silently across a shape change.
