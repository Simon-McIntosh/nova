§1 — Finding: the variants are not a backend problem

An audit (2026-08-08) of the suspected "traceable variant" proliferation across nova/biot, nova/jax and the spine packages found that the biot numerics are already single-source: 34 signature sites across ~14 modules (~6,750 lines) thread an xp array-namespace parameter, and the hard blocker was already solved properly — nova/biot/completeelliptic.py implements the Bulirsch cel descent with a fixed trip count precisely so one implementation runs under both numpy and JAX (its docstring states the contract: no convergence test, no data-dependent branch). No TraceableFoo/FooJax class pairs exist; the token traceable appears in two files repo-wide.

What reads as proliferation is five distinct hygiene defects. A global backend = numpy|jax setting would fix almost none of them — ~3,300 lines of genuinely JAX-only code (lax.scan Picard sweeps, static-shape gathers) cannot run under numpy, and the largest live pair (nova/geometry/select.py numba vs nova/jax/select.py) is a three-backend axis a two-value flag cannot describe. The decision below locks the response: hygiene sweep, no switch.

✓ landed 2026-08-08

§2 — Work items

All five items landed in ten commits (28035f70…0f553ebb). 5 dead modules deleted with per-file zero-importer proof; 19 jax_enable_x64 sites collapsed onto nova/jax/config.py; the two numpy modules rehomed so nova/jax/ holds only jax-referencing code (16 modules → 14); Bernstein, _dilate4 and the biquadratic fit single-homed. The parity work found three real defects, each returning a wrong answer rather than an error: a silently-absent Force index, an empty profile ladder that raised on one arm, and a missing degenerate-fit guard that let ±inf into vmapped gradients. Two listed items were refused on evidence — nova/jax/fieldnull.py is not a copy (its hex-stencil construction moved to nova/geometry/hexstencil.py instead), and the four greens hosts were KEPT: measured, the traced twins cost 1.9–3.9× and return a small negative flux where the host returns the divergence inf. No suite regressed; ruff 34 against a 36 baseline. Full record: §2 landed.

§ Decisions

Should nova gain a numpy|jax backend selection setting (pyproject and/or environment variable), or is the cleanup alone the right response?

User selection 2026-08-08 on the audit evidence: no backend switch. The numerics are already single-source through the xp namespace parameter; the genuinely JAX-only code cannot run under numpy; and the largest live pair is a numba-vs-JAX axis a two-value flag cannot describe. Callers keep choosing routes explicitly (the tiledassembly backend= parameter and the operate.py fallback stand as-is). Revisit only if a concrete consumer needs process-wide route selection.

Adopt the NaN wall_flux convention, or keep the serial sentinel deliberately

The sweep documented rather than aligned the one convention split it found. The serial wall_flux returns (0, 0, 0) at zero polarity, the traced one all-NaN. NaN is the safer answer — (0, 0, 0) is a well-formed coordinate and flux a caller cannot distinguish from a real result — but adopting it changes what Limiter.update_wall publishes at zero plasma current, so it needs validating rather than doing in passing. Two callers.
