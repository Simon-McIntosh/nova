§1 — What the code already requires

The optional-JAX story is fiction, and a worker lost twenty-five minutes proving it. Twenty-one modules under nova/ import JAX at module scope, and sixteen of them are nova/equilibrium/ — including forward.py (the public ForwardProfile), profile.py (ReconstructProfile), topology.py, fixed_point.py and connectivity_boundary.py. The physics spine cannot be imported at all without JAX. Only one guarded import exists in the whole package (nova/jax/config.py), so there is no fallback path to speak of.

But the extra that would declare it pins the wrong thing. The jax extra is jax[cuda12]>=0.5 on linux, so "declare JAX" and "pull ~2.5 GB of CUDA wheels" are currently the same request. That is why the plain runtime ended up duplicated inside the test extra instead: test pins its own jax>=0.5, which is the only reason uv run --extra test works at all. Two pins for one dependency, and neither named honestly.

§2 — Three extras, each naming one thing

testnova[jax] transitively — no second pinthe test lane

test must keep resolving JAX, or this change re-breaks what it is fixing. Deleting the pin outright would make uv run --extra test stop supplying JAX — the exact failure that motivated the work. The dependency is therefore moved, not removed: test depends on nova[jax], which drops the duplicate pin while leaving every existing --extra test invocation working unchanged.

JAX stays out of [project.dependencies]: a bare import nova and the frame, biot and IMAS surfaces do not need it, and forcing it on every install would trade one dishonest declaration for another.

Done-when: uv run --extra test resolves JAX with no CUDA wheels on a CPU host and the equilibrium suite passes; --extra gpu is what selects the CUDA build; no extra pins JAX twice; the installed jaxlib variant is reported for both compositions.

§ Followups

Declare the GPU extra where the H200 lane installs from

The gpu extra now exists but nothing yet selects it: the H200 lane and any CUDA-enabled worker environment still install through whatever composition they used before, so a device run can silently land on the CPU jaxlib — which is exactly what made three of this sprint's speedup figures CPU-only. Point the GPU install path at --extra gpu and record the resolved jaxlib variant, so a device claim is verifiable from the environment rather than assumed. Owned by the catalog plan because that is where the device lane is defined.
