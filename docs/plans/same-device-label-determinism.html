§1 — The measurement, and why it outranks everything else on this lane

Every reproducibility argument made about this solve so far has compared two things: a compiled route against an eager one, a batched route against a per-slice one, one platform against another. This plan exists because a comparison of one route against itself failed. Two back-to-back invocations of the same driver, in one SLURM allocation, on one NVIDIA H200 NVL, at float64, on byte-identical inputs and the exact same seed, returned different registered-bound verdicts.

The cleanest single instance. conservation.divergence_b failed both batch widths in the first repetition and passed both in the second. Nothing about the input, the seed, the device, the driver or the source changed between them.

This is not the batch-size dependence already characterised, and it is worse. Batch-size dependence is a property that can be measured once and stated: three bounds change status between widths 1 and 4, and every one of the 69 receipt rows carries pass_status_depends_on_batch_size so a reader cannot mistake silence for independence. Run-to-run variation on one device has no such shape. It means a verdict is a sample rather than a value, and no number of passing runs establishes that the next one passes.

It survived the repair that was expected to explain it. A fixed binary summation tree and a cell-centred radial-volume reconstruction made moments.volume and moments.major_radius bitwise equal between the scalar observation entry and a jitted vmap of it, on all six held-out cases. That repair improved the pass counts — 65 to 67 and 66 to 68 bounds at the two widths — and did not remove the run-to-run movement. So the cause is not the reduction association in Nova's own moment code, which is the hypothesis this plan starts by having already excluded.

Why it blocks the labelled catalog specifically. The throughput product is a store of boundaries, moments and conservation diagnostics across 1,341,435 slices, and its value rests on a consumer being able to trust a published label. A route that returns a different verdict on a rerun cannot certify anything: the acceptance check that a throughput rung invokes would pass or fail by luck of the run. Terminal flux agreement at 3.58e-12 does not help here, because the disagreement is downstream of the state.

The movement is one or two units in the last place, and that is a lead rather than a reassurance. Read from the receipt's own remaining-failure entries, the flipping observable moves by a maximum absolute difference of 1.3877787807814457e-16 at width 1 and 2.7755575615628914e-16 at width 4 — one and two units in the last place of a binary64 number near unity. It nonetheless carries a maximum relative difference of 2.5 and 4.5 and a maximum bound ratio of 2.967 and 5.341, because both observables whose verdicts move, conservation.divergence_b and conservation.divergence_j, are divergence residuals that are identically zero in exact arithmetic. Their computed value is roundoff, so a bound on them is a bound on roundoff, and a last-bit change crosses it.

That makes two candidate faults, not one, and they must not be merged. A genuinely nondeterministic operation is one fault, and §3 owns it. A criterion that scores a quantity whose exact value is zero against a threshold at the same scale as its own rounding error is a different fault, and it is the plan's own standing rule turned on this lane: a criterion must be passable by something, and one that is passable only when the last bit falls the right way is not. The two faults imply opposite repairs — deterministic kernels at a measured throughput cost, or an absolute floor on a residual that has no meaningful relative scale — so an arm that fixes one while reporting the other's symptom would close nothing. Every node here reports each flipping observable's absolute value beside its bound, so which fault is in play is visible rather than inferred.

§4 — Method requirements binding on every node here

Retain every repetition; never collapse them into a best or latest run. This plan exists because a worker kept a repetition it could have discarded. A receipt that reports only the most recent run of a nondeterministic process is not evidence, and a summary that averages verdicts hides the very property under study.

Name the production diff between compared trees and decline attribution when more than one mechanism sits in it. Inherited from the predecessor lane, where a re-measurement was read as evidence for one mechanism while an unrelated operator-order commit was the true mover.

Report a pass count only with its repetition count beside it. The direct analogue of the lesson that an admission count means nothing without achieved traversal: on this lane, "67 of 69" is meaningless without "in which of how many runs".

Never derive an acceptance criterion from an achieved value of the quantity it scores, and a criterion must be passable by something.

§ Decisions

If a deterministic control is found, does it apply to the whole production forward path or only to the acceptance-measurement driver? Applying it everywhere makes every published label reproducible and pays its throughput cost on all 1,341,435 slices; applying it only to the measurement makes the acceptance check trustworthy while leaving the production route free to vary, which certifies a route different from the one that produced the store. Answer it only after the cost is measured, never before.

§2 IS CHEAP AND IT SPLITS THE PROBLEM IN HALF. Nobody has yet compared the terminal flux array bitwise across two runs of the same case in one allocation, because no existing receipt retains the raw terminal arrays across repetitions. If the state repeats and only the labels move, the search is confined to the observation path. If the state itself varies, then every single-run label argument on this lane becomes provisional and that is a much larger finding, so it is worth an hour to know which world we are in.

THE CLEANEST TARGET TO INSTRUMENT is conservation.divergence_b. It failed both batch widths in one repetition and passed both in the next, so it flips on the coarsest possible signal and needs no subtle statistics to detect. Use it as the canary while building the repetition harness, then widen to all 69.

DO NOT DECIDE THE CONTROL SCOPE BEFORE THE COST IS MEASURED. The open decision asks whether a deterministic control applies production-wide or only to the measurement driver, and the honest answer depends entirely on the per-slice throughput cost across 1,341,435 slices. A measurement-only control certifies a route that is not the one which produced the store, which is close to certifying nothing - but a production-wide control that halves throughput is a real trade and belongs to the owner, not to this plan.
