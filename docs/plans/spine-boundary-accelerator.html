§1 — Objective

Nova owns all physics solves; this plan makes the differentiable boundary push its pinned, accelerated core. The smooth LCFS discovery developed in ambix — identify the o-point, push a contour outward until it binds at the first x-point or the wall, one code path with no limited/diverted branch, continuous through the marginal transition by construction — already lives in nova code-identically (nova/jax/connectivity_boundary.py + stencil_nulls.py + flux_surface_connectivity.py; audit: boundary-push-port-audit). What did not port is what makes it trustworthy and fast: the behaviour tests that pin x-vs-wall termination and switch continuity, the exact-tangent Newton–Krylov that converts 6× more slices than production Picard, the safeguarded Anderson mixer, the profile-damping guard, and the topology-read cost removals that the batched corpus engine was stalled on. This plan lands all of it in nova and retires the ambix accelerator plan (supersedes imas-ambix:batched-newton-accelerator).

§2 — Work items

  1. Pin the behaviour. Re-bank the unported assertion classes against synthetic truth (nova has no host contour reader; the ambix synthetic gate reproduced interpolated wall tangency to 1e-15): x-point-termination and wall-termination of the push; limited↔diverted continuity through the marginal transition (max_rel_step < 0.05, classify-first steps >3× larger); the Lipschitz smooth-weight bound (1e-4·span ψ ripple moves core weight <0.8 max / <0.01 mean); no-flip-on-topology-switch for emitted x-slot labels; and first-ever coverage of Topology.boundary / x_mask / psi_lcfs (nova/jax/topology.py) — the x-vs-wall selector is currently asserted by no test in the repo.
  2. Promote the accelerators into the package. The exact-tangent Jacobian-free Newton–Krylov (jax.linearize tangents + fixed-shape batched GMRES) moves from the ambix probe script into nova as the batched inner solver driving forward_operator.residual / ReconstructProfile; the safeguarded Anderson mixer (Walker–Ni type-II, ridge-regularised, step-capped, Picard fallback) ports as the fallback option; a current-centroid pin guards NK's basin (the smooth map has multiple fixed points). Add the profile-damping parameter to the LSQ path (undamped coefficient jumps can escape to the outboard-corner attractor — the guard ambix needed and nova lacks) and fix ProfileResult.axis returning the static seed instead of the solved axis. Lock the two carried decisions (below) on the re-measured budget ladder.
  3. Remove the read wall. The topology read is ~99.7% of every map evaluation. Three removals, each with a read-equivalence check: warm-started binding search (bracket around the previous sweep's level; cold sweep only on first evaluation or bracket miss), dilate-by-doubling flood fill (~log₂(nr+nz) steps to the same fixed point), and a coarser iteration-resolution read with the calibrated τ=10⁻³ full-resolution read at emit only.
  4. Hex-native stationary points. Generalise stencil_nulls.ring_sign_changes from its hardcoded 8-ring raster roll to a stencil-array parameter, consuming the angle-sorted 6-neighbour rings nova's hex plasma mesh already writes (nova/biot/plasmagrid.py (n,7) stencil; nova/jax/null.py already categorizes on it). The sign-change count is ring-length-independent; check the conditioning of the exactly-determined 6-coefficient sub-null fit on the 7-point cluster before switching any default. The raster path stays.
  5. Coupled profile state. Lift the rich profile coefficients into the Newton state (smooth softplus non-negativity, ridge+prior rows inside the Jacobian) so under-constrained higher-order fits stop thrashing between sweeps — the mechanism the profile-state decision selects.

Done-when: behaviour pins green including the marginal-transition and x-vs-wall gates; NK/Anderson/Picard re-measured on the fast read with both decisions locked; read-equivalence checks recorded for all three removals with the measured speedup; hex stencil path tested with conditioning recorded; full suite green. Throughput laddering on H200 hardware belongs to mast-catalog-gpu-solve, not here.

§ Decisions

Which convergence accelerator is adopted as the batched inner solver? Carried from the superseded ambix plan. Evidence so far: exact-tangent NK converts 62% of cold slices at a 40-evaluation budget vs 19% smooth-Picard and 10% production-Picard, with every operation a Green's-GEMM column or tiny dense solve; Anderson ties Picard exactly on both maps in both studies. Lock after the §2 item-2 re-measurement on the fast read.

How do the rich-profile coefficients enter the Newton iteration — lifted into a coupled KKT state (nonneg + prior rows inside the Jacobian), or held as an inner implicit fit with damping only?
