Comparison adapter refuses an invalid-axis read

Measured landing fragment

The adapter publishes a decision only for a read that licensed an axis

The axis-ranking merge (4763425e9) taught the fixed-shape read to rank valid in-vessel polarity extrema and to refuse when none qualifies, returning valid=false and a NaN axis. The field-swap comparison adapter scripts/prototypes/efit_field_swap/crosscheck.py did not consult that verdict: read_state took reading.boundary and reading.axis and published "diverted" if boundary_class else "limited" regardless. A NaN axis therefore still produced a plasma label.

The repair inspects the read before it publishes. Where reading.valid is false or the axis is not finite, the lattice appends a refusal note, sets a refusal flag, and publishes no outcome for that resolution; if no resolution licenses an axis the adapter returns the label refused invalid axis with a NaN axis, a NaN boundary and a NaN boundary flux, and the note names the refusal. The refusal sits at the same seam the coverage certificate already uses, so the two refusals - incomplete census coverage and an unlicensed axis - stay distinct labels.

Exercising the refusal without the TCV data

A synthetic field carries a single interior stationary point that is a minimum, presented through the adapter's own spline field over a rectangle. Under the declared positive-polarity convention the axis is expected at a flux maximum, so the census types the extremum as the wrong kind, the read admits no axis and returns valid=false. The loop's boundary winding is +1 and the admitted index sum is +1, so the coverage certificate closes and the adapter reaches the read - the exact state the defect decided from. Under the present adapter that state returns limited; under the repair it returns refused invalid axis. This is the negative control: with the refusal guard removed the new test fails on assert 'limited' == 'refused invalid axis', exit 1.

The near-fold persistence gate gains a test

The fixed-shape read refuses an extremum whose signed persistence to its nearest saddle is not resolved in the booked field: persistent = ~any(saddle) | (persistence > level_enclosure + level_enclosure[nearest]), and eligible = extrema & persistent. Nothing in the suite exercised it. The added test builds the double well under a large constant background. The background is a physical flux offset: it moves no stationary root and changes no signed persistence, but it grows the fitted coefficients and therefore the binary64 enclosure of the fitted level. At a 10^15 background the selected extremum's persistence lies inside that enclosure, the pair is one number in binary64, and the read publishes no axis; the same field with no background is accepted. Deleting the persistent comparison - eligible = extrema - restores valid=true and the test fails, exit 1.
