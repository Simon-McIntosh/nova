Research input

Batched factor executable size

On the 289-cell limited carrier, passing the state, carrier arrays and predecessor LU as traced operands reduces the largest two-correction batch executable to 1.362 MB. The width-128 synchronized wall is 0.279 ms per distinct state, with 128/128 reaching a scaled residual at or below 10−12. The diverted carrier is measured for program size and compile; its separate convergence defect remains open.

Method and provenance

The prototype scripts/prototypes/batched_factor/measure.py imports the fixed-shape moment map without changing product code. It uses the cached 289-cell limited and 282-cell diverted certificate carriers, binary64 before array construction, and a cache-disabled H200 process for each carrier. The residual is evaluated from the scaled moment map. A vmapped JVP of identity directions forms every dense Jacobian column inside one jitted factor program; jax.scipy.linalg.lu_factor and lu_solve build and apply the device factor. The factor, state, scale and carrier arrays are runtime arguments to the two-correction chord program. A separate program builds fresh factors over state groups of four within one compiled scan to bound the temporary Jacobian memory.

The fresh closure-constant reproduction and the runtime and HLO jobs write complete logs and JSON receipts under /home/ITER/mcintos/.config/reckon/crew/runs/r-20261015T143916649094-batched-factor-size. Each log begins with revision, tree, command, imported nova and measurement-module paths. All walls are synchronized medians of five calls, or three for the factor build. MB uses decimal bytes. The width-128 wall is a batch throughput measure, not a single-state latency.
