§1 — Verdict

Nothing of the boundary-push kernel was lost in the port. The three modules implementing the differentiable read — connectivity_boundary.py (965 lines: monotone valid→invalid level sweep, softmin binding, retracted-gate sigmoid core weight), flux_surface_connectivity.py (254: fixed-iteration flood fill), stencil_nulls.py (291: ring sign-change classification + biquadratic sub-null refinement) — are code-identical between imas_ambix/latent/ and nova/jax/; every differing line is a docstring rewrite or import-path change. wall_mask.py ported complete and gained one public symbol. Neither side has diverged in physics since the port.

What did not port is everything around the kernel:

  • The behaviour pins. 43 ambix test functions have no nova counterpart, clustered on the load-bearing behaviours: x-point-vs-wall termination of the push (6 ambix tests, 0 nova), limited↔diverted continuity through the marginal transition (3 vs 0 — incl. test_continuous_through_marginal_transition, which asserts max_rel_step < 0.05 across a genuine topology switch and that a classify-first read steps >3× larger), the Lipschitz smooth-weight bound, and the no-flip-on-topology-switch label test. Independent of the port, nova's Topology.boundary (nova/jax/topology.py:82) — the actual x-point-versus-wall selector with its mode-index lax.cond — is asserted by no test in the repo.
  • Both accelerators. The exact-tangent Jacobian-free Newton–Krylov (jax.linearize tangents + fixed-shape batched GMRES) exists only inside an ambix probe script (scripts/tau_map_accelerator_probe.py:358) and was never a package symbol on either side. Anderson mixing has zero occurrences anywhere in nova (three implementations in ambix; the library-grade one is _AndersonMixer, gs_solve.py:2011 — Walker–Ni type-II, depth 6, ridge-regularised, three safeguards costing no extra map evaluation). Nova's only Newton–Krylov is scipy.optimize.newton_krylov on the eager path — finite-difference, not jittable.
  • The profile-damping guard. Ambix's solve_equilibrium_lsq carries a second mixing parameter (gs_solve.py:2497-2508) added because an undamped jump to the LSQ optimum can move the boundary read far enough in one sweep to escape into the outboard-corner attractor. Nova's ReconstructProfile LSQ jumps to its optimum every sweep undamped — that failure mode is unguarded — and its solve loop is fixed-count relaxed Picard under lax.scan (8 iterations, single relaxation 0.6, no convergence test consulted). One latent defect found: ProfileResult.axis returns the static seed, not the solved axis (profile.py:498).
  • The host reference reader. latent/topology.py (919 lines, contourpy/ndimage) stayed in ambix; several unported tests use it as the reference, so nova re-banks against synthetic truth instead (the ambix synthetic gate reproduced interpolated wall tangency to 1e-15).

§2 — The accelerator evidence chain (three ambix plans)

The measured trail that the nova work inherits, in causal order:

  1. greens-filament-solver (shipped): the ≥3× CPU throughput gate closed as an honest negative with the cause localised — the hard-threshold host topology read makes the free-boundary map non-differentiable; NK erratic on it, Anderson ~1.3× on well-posed slices only.
  2. differentiable-solve-accelerator (shipped): the smooth connectivity read fixed convergence (10 of 14 limit-cycling slices turned monotone; synthetic wall tangency to 1e-15) but not CPU throughput (the smooth read costs 2.63× the hard read's wall; net 0.5–0.95×). NK on the smooth map hit 2e-12 residuals but could converge to the wrong basin without a current-centroid pin.
  3. batched-newton-accelerator (active at 0.17, now superseded into nova): on 48 cold-seed slices at a shared 40-evaluation budget, exact-tangent NK converts 62% (median final residual 3.4e-5, 30× under tolerance) vs 19% for smooth-map Picard and 10% for production relaxed Picard; Anderson ties Picard exactly on both maps — the acceleration is entirely the exact tangent. Every NK operation is a Green's-GEMM column or a tiny fixed-shape dense solve, so the scheme vmaps unchanged. The remaining wall is the read itself: at B=512 the topology read is ~99.7% of every map evaluation, with a ≥5× removal path (warm-started binding search, dilate-by-doubling log-depth flood, coarser iteration-resolution read with the calibrated τ=10⁻³ full-resolution read at emit). τ locked at a single 1e-3 operating point (continuation bought one slice). §3–§7 of that plan are verified unbuilt on both sides.

§3 — The hex stencil runs the other way

The 6-point hexagonal stationary-point variant does not need building: nova already has it, and it is the original. nova/geometry/hexstencil.py builds the axial hex neighbourhood as a 6-point ring with the centre cell prepended, so the row is 7 columns wide (nova/jax/fieldnull.py reads it); nova/biot/plasmagrid.py:113 Delaunay-tessellates the hex filament centroids, keeps exactly-6-neighbour vertices, angle-sorts them into closed rings, and writes an (n,7) stencil; nova/jax/null.py:87 already categorizes on it ("1d hexagonal grid"). Ambix's stencil_nulls.py — whose docstring says it mirrors nova.jax.select — is the rectangular-raster specialisation of that machinery. The work is one generalisation: ring_sign_changes hardcodes an 8-ring of jnp.roll shifts on a (nz,nr) raster; parameterising it on a stencil array makes it a strict superset (the sign-change count is ring-length-independent; the 6-coefficient biquadratic fit over a 7-point cluster is exactly determined — conditioning to be checked, vs over-determined on the 3×3 raster block).

§4 — Acceleration substrate already in nova

nova/equilibrium/forward_operator.py exposes a differentiable, vmap-able residual built to be root-found; its only current caller is a dev script (nova/biot/boundary.py, optimistix Newton, runs at import with hard-coded arguments). The differentiable substrate the NK accelerator needs exists in the package and is unused — the port is a promotion, not an invention.
