Overview

The coupled plant — the sectioned coil winding, the reduced passive system, and the plasma flux drive at every coil section and passive mode — is returned through one public call and one result type. nova.circuit.coupled_plant.coupled_plant(machine, source) returns a CoupledPlant and nothing else is exported from the module. The call composes the machine binding, the sectioned conductor set, the passive reduction and the prescribed plasma; it does not re-derive any of them.

The plant is cached through the serialisers nova.circuit.passive ships, extended to the coupled plant, with the location resolved through nova.database.filepath.FilePath. The cache key is a digest over the machine, the frequencies and the reduction settings, so a plant is reused only when it was built from the same inputs.

What this is for. A switched converter model has to see the plant as a state-space multiport: which coil sections exist, how they couple, how the passive modes screen them and what the plasma drives into them. This call is that interface; it is a composition, so the physics it returns is exactly the physics the underlying nodes already measured.

One call and one result type

CoupledPlant carries, per the brief: coil_names; the section-level coil_inductance and coil_resistance; the reduced passive system as mode_tau and mode_coil_coupling (every retained mode against every coil); the plasma flux drive as section_plasma_flux and mode_plasma_flux against plasma_times at the frequencies the plant was reduced for; reduction_error against frequency; and provenance naming the machine label, the plasma source label and the nova revision.

CoupledPlant.terminal_impedance(frequency_hz) returns the (n_freq, n_coil, n_coil) terminal impedance with the retained passive modes shorted. It is the same function the reduction search minimises against, so the returned error is the error of the returned object rather than a separate estimate.

The plasma source is accepted through a minimal interface: an object exposing plasma_times, coil_current_times, coil_currents and a prescribed_currents() -> list[PrescribedCurrent]. Nothing in the module names a concrete source type, so the IMAS-backed source and a reduced test source are interchangeable.

Cold and cached, reduced and full

The call returns the same plant cold and from its cache, and the comparison is by value on every array field, including mode_tau — an earlier form compared only shapes and would have passed a perturbed cache.

The reduced plant's terminal impedance matches the full model's to under 1% for every coil from 0.1 Hz to 5 kHz, and the returned reduction_error is under 1% over the same band.

The retained count grows with the sectioning, and that is the cost of the guarantee. On the eight-coil case above the search retains all 64 modes: at 48 of 64 the worst relative error is 191%, and the ratio only falls below 1% once the set is complete. The error is a maximum over coil pairs and frequencies including near-cancelling off-diagonal entries, so it is a strict criterion; a weaker pairing criterion would retain far fewer modes. The retained count and the error it achieves are both on the result, so a consumer can trade them rather than take a default.

The point-flux kernel now has one owner

The vessel-evolution driver's passive_flux_at_points derived a per-ampere point coupling of its own. It now calls nova.circuit.linkage.sensor_grid_couplings, the finite-area kernel the rest of the circuit tier uses, and takes the grid column the point index selects. The two agree, and the section 3 receipt's VS3 peaks are unchanged to the reported precision: 8.40230532 → 8.40042344 Wb (relative −2.24e-4) and 10.0803061 → 10.09798884 Wb (relative +1.75e-3). A test pins the equality, so a second point kernel cannot reappear unnoticed.

The driver's assembly — coupled section flux and coil voltage from the section linkage, the passive currents and the prescribed plasma — previously had no test. It is now exercised on a reduced case through evolve.psis_and_voltages and evolve.integrate.

Controls

The gate is tests/test_coupled_plant.py and tests/test_iter_vessel_evolution.py together: ten tests, all passing, against the committed revision.

The negative control perturbs one cached array — mode_tau, scaled by 1.5 where the plant is written — in a scratch copy of the module outside the repository. The cold-and-cached comparison then fails on mode_tau, whose two values differ by exactly that factor, and the log ends EXIT=1; the head arm on the same scratch tree passes with EXIT=0. Each arm prints the module file it imported, so the arm is known to have loaded the mutated module and not the worktree's. The first attempt at this control passed on both arms: pytest prepends the invocation directory to sys.path, so a run started inside the worktree imported the unmutated package even with the shadow on PYTHONPATH. The arms now run from a neutral directory holding a copy of the test, which is what makes PYTHONPATH alone select the package.

The positive controls are the analytic ones the earlier nodes established: the single-ring L/R decay and the exact zero-order-hold propagation, both still green in the same gate.

Caveats

The tolerance search now doubles the retained count on each trial rather than growing it one mode at a time. The one-at-a-time form is O(n_modes) trials and does not finish on a wall set of a thousand circuits; the doubling form reaches the same decision in a logarithmic number of trials. The mode counts at which the search lands can differ from the linear form between successive doublings, so a caller who pinned a retained count to a number between powers of two should pass that count explicitly.

The reduced-vs-full guarantee is measured on the reduced test sectioning and on the eight-coil sectioning above, not yet on the full ITER sectioned set: assembling the real plant calls the geometry rebuild, which did not finish inside this node's budget. The real-set number is owed and is the natural next step, together with a figure from it.
