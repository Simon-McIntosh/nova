The default lane was carrying a heavy solve

The default lane is path-free pytest, configured in pyproject.toml as -m 'not slow' with timeout = 300. A collection-only run of the two files under that filter reported 1 collected, 3 deselected: the single test of tests/test_forward_receipt_raster.py was collected because it carried no marker, while all three tests of tests/test_forward_compile_identity.py were deselected as slow. So the raster solve ran in the fast lane, where it cannot finish, and the compile-identity file was already correctly excluded.

What dominates each file

Receipt raster. One test; it is the dominating test by construction. The negative-control run shows its cost is the native XLA compile of the request-seam solve program, not the Newton iterations or the fixture: the failure lands in jax/_src/compiler.py:350 in backend.compile_and_load, and the wall does not stop at the timeout because the handler cannot pre-empt native code.

Compile identity. Three tests, each marked slow. On the H200 the first, test_certificate_rows_share_one_solve_program_per_mesh, passes; the second, test_traced_exterior_preserves...terminal_state, fails at base (full traceback recorded in the lane log). All three share the same cost driver as the raster file: the compile of the certificate solve program.

Change

The raster test gains @pytest.mark.slow with a comment naming the mechanism. No assertion was deleted and no tolerance was loosened. After the change the default-lane collection of the file reports no tests collected (1 deselected).
