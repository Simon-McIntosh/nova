§1 — Result

A transport forward solve is the same class of problem as the prescribed-profile free-boundary equilibrium: given geometry, an initial profile state, boundary and actuator waveforms, and a declared source and transport-model selection, the solver advances the 1D flux-surface state deterministically and reports conservation receipts. No measurement regression belongs inside it. Fidelity is an explicit model selection recorded in provenance — never a silent approximation. The producer of corrections and uncertainty remains Ambix; the deterministic evolution operator belongs to Nova, alongside ForwardProfile.

Nova already owns one rung of this ladder: the poloidal-flux (current) diffusion solve ported from the Ambix torch prototype (nova/transport/current_diffusion.py, landed 9e9c73e3), formulated after the TORAX finite-volume ψ equation and verified three ways — analytic Bessel eigenmode decay, byte-level parity with the frozen torch prototype, and relative RMS < 1% against a real TORAX run on shared circular geometry with Sauter conductivity. That verification pins the formulation (time coefficient, current normalisation, θ-scheme) but not the closures: the rung has no conductivity physics, no bootstrap current, no sources, and evolves one of the four coupled channels a torax-class solver carries.

§2 — What the native rung has and lacks

The ported solve is a vertex-centred finite-volume θ-scheme (backward Euler default) with a jitted Thomas tridiagonal kernel — O(n), jit/vmap/grad-safe — the axis-regularity condition at ρ̂=0 and the measured plasma current as an edge-gradient condition at ρ̂=1. Geometry is frozen per interval by design. Conductivity is a three-parameter bounded empirical family fitted across shots; despite the "Sauter/Spitzer-informed" phrasing in its docstring, no Sauter, Spitzer or neoclassical conductivity is implemented anywhere in the ambix or nova trees — the family merely brackets the Spitzer temperature scaling while staying finite at the separatrix. The solver accepts any conductivity callable, which is how the TORAX cross-check injects Sauter values.

§3 — TORAX assessment

TORAX (github.com/google-deepmind/torax, Apache-2.0, Citrin et al.) is at v1.4.3 with active daily development and is verified against RAPTOR. It solves the four coupled 1D PDEs on normalised toroidal flux with the Φ̇_b moving-grid terms, and it exposes exactly the embedding surface an outer free-boundary loop needs:

  • Step-wise library API. make_step_fn returns a jitted SimulationStepFn; jitted_fixed_time_step accepts runtime_params_overrides and geo_overrides. The documentation's worked example is an iteration loop with an external equilibrium code, requiring the geometry provider to hold both the previous and new geometry so the Φ̇_b term is correct.
  • Functional immutable state. Core state objects are frozen registered pytrees; the stepper itself is a pytree. An ensemble is a vmap over state, not a serialisation problem.
  • Differentiability is tested end-to-end — value-and-grad of fusion gain with respect to an I_p waveform through a 200-step jitted loop, checked against central differences. The Newton-solver gradient path was fixed in v1.4.3.
  • Return channel built in. Post-processing computes pprime and FFprime explicitly as the hand-back to an equilibrium code, and the IMAS writer accepts an external boundary.

Four caveats shape the integration:

  1. Dependency pin. TORAX ≥ 1.3.0 hard-pins imas-python==2.1.0 and bounds h5py<3.15; the ambix environment carries imas-python 2.2.0 (required by imas-ink ≥ 2.2) and h5py 3.16, so the installed TORAX is stuck at 1.1.1 — which predates the geometry-override API, Redl bootstrap, the IMAS DDv4 geometry path and the Newton gradient fix. Resolving this pin (uv override-dependencies, relaxing imas-ink, or an upstream loosening) gates everything else.
  2. COCOS is undeclared upstream (issue #528, open since 2024). Geometry construction force-normalises signs — ψ increasing outward, positive I_p, absolute values applied to Φ, F and the |∇ψ| averages — and the IMAS writers hard-code sign flips. The boundary therefore needs explicit round-trip sign tests against Nova's pinned COCOS 17 provenance, not documentation trust.
  3. Geometry construction is NumPy/SciPy. The resulting geometry object is a pytree and passes into jit, but gradients cannot flow back through its construction. Picard/fixed-point equilibrium coupling is unaffected; an end-to-end differentiable loop would need a jnp port of one ~250-line builder.
  4. Import side effects. TORAX sets jax_enable_x64 and appends an XLA fast-compile preset at import — benign for Nova, which owns x64 configuration already, but worth pinning in a shared-process test.

§4 — Geometry contract

All non-circular TORAX geometry funnels through one adapter type whose fields are 1D profiles versus ρ̂ plus four scalars. Nova's traced FSA assembly already produces the majority from a solved flux map; the gap is a bounded list of additional surface averages, all computable by the same contour-free coarea kernel:

Two handoff routes exist: construct the adapter object directly (explicit, sign-controlled, no experimental layer), or emit an in-memory IMAS equilibrium IDS and reuse TORAX's own reader (DDv4, marked experimental, requires the custom run loop we would use anyway). Either way the IMAS equilibrium representation remains the interchange format for egress.

§5 — Embed, do not reimplement

Reimplementing even the current-diffusion equation plus Sauter conductivity to TORAX's verification standard consumed one plan already; the remaining three channels, the neoclassical closures, the source catalogue and the stepper machinery are person-years of verified physics available under Apache-2.0, maintained daily, with the coupling API designed for precisely this use. The native rung stays: it is the fully differentiable, dependency-free floor of the ladder, already validated against TORAX itself, and the right vehicle for learned-closure work where the empirical conductivity family is the point rather than a deficiency. Integration effort, in order: resolve the dependency pin; extend the FSA record with the missing averages and build the geometry adapter; write COCOS round-trip sign tests; lift consumers off whole-run calls onto the step API. State conversion is cheap (frozen pytrees), and differentiability through geometry construction is deferred until a gradient across the equilibrium loop is load-bearing.

§6a — Window coupling and innovation flow

Equilibrium and transport advance at different native rates, so the coupled solve needs a multi-rate coupling scheme. The candidates, assessed against splitting error, GPU shape and the assimilation envelope:

Three facts settle the selection. First, staggered co-simulation with interpolated geometry is the first iteration of waveform relaxation, so one windowed contract with an iteration cap covers both schemes as measurable points on one axis — and TORAX's time-dependent geometry provider already implements the transport side of the exchange natively. Second, the assimilation layer learns from model–measurement innovation, and an unconverged seam confounds that signal with numerical splitting error; converging the window to a declared, receipted tolerance is what keeps the innovation attributable to physics rather than to the solver. The residual coupling behaviour is not discarded — iterations, contraction rate, exit residual and damping travel as typed receipts the consumer classifies beside the innovation, and slow contraction is itself a physics signal. Third, a converged fixed point differentiates by the implicit-function adjoint without unrolling the iteration, so the converged window is the differentiable case, not the opaque one — learned closures inside the propagator train through it exactly, provided the geometry adapter is authored in jnp from the traced FSA record rather than through TORAX's host-side builder.

The resulting authority split: Nova owns the deterministic window fixed point and must surrender its convergence behaviour as receipts; the consumer owns window scheduling, the ensemble update at window boundaries, and learned corrections — which enter the loop only as typed inputs (member closure parameters; declared model-error source terms through the seam's new-physics registry), never as invisible patches. The single-sweep equilibrium and transport waveform primitives stay public pure functions, so a declared composition that wants corrections between relaxation sweeps remains architecturally possible without weakening the default. One subtlety the waveform type must carry explicitly: profiles interpolate in time on the normalised radial coordinate while the coordinate map itself evolves, so the waveform includes Φ_b(t) and the axis and boundary references — the per-slice coordinate guarantee of the flux-function seam, extended to time.

§6 — Current consumers and recorded drift

Real TORAX is already a declared ambix dependency, exercised two ways: a parameter-space ensemble smoother running up to 128 whole simulations per shot, and a sequential filter running one nominal trajectory per shot — both on analytic circular geometry rather than the reconstruction, with heat and particle evolution disabled, a resistivity multiplier folded into an effective Z_eff, and a broad exception handler that silently degrades to zero-filled profiles. The step-wise API removes the need for all four compromises. Separately, the torch donor of the ported solver still sits in the ambix tree with two unported functions (per-column amplitude scales and the β_p coefficient sensitivity), and the evolved-profile projection is not yet wired into the label-solve soft-prior hook it was built for. These are consumer-side obligations recorded in the ambix integration plan, not Nova work.
