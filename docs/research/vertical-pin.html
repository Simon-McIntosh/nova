Vertical pin on the converged forward solve

This note records the design and measured behaviour of an optional vertical-position pin on nova's converged forward solve, and states plainly which of its done-when items closed and which did not.

Why a pin

A current centroid is free to translate in height when the equilibrium is elongated: the elongation-driven vertical force c Z (Z − Zfree) loses stiffness with elongation, so the residual is nearly flat in Z near the free root and a converged solve can land the centre anywhere along that flat direction. The free root is not controlled by anything the operator commanded. A converged forward solve of an elongated state therefore needs a compensating unknown to hold the height at a commanded target.

Design

The pin is built on the generic chord-Newton fixed-point solver, which owns no physics. Three additions sit in nova/equilibrium/solve.py:

  • VerticalPin(target, pin_scale, initial) — a registered dataclass whose fields are all runtime leaves, so nothing about a particular target, scale or seed is captured in the traced program.
  • pin_residual(residual_fn, observation, pin) — returns the base map augmented by one row (observation(extended, operands) − target) / pin_scale, where extended is the base state with the compensating unknown appended. The base map reads the unknown off the extended state's last element and adds its declared field through the runtime operands.
  • pin_state and pinned_fixed_point — extend the state by the seed and drive the augmented map.

Because the unknown is part of the state and the field it drives enters the map as an operand, the compiled program is the same pinned or unpinned and for any target value. The test counts one lowered-and-compiled program and calls it at two targets.

Why the unknown rides in the extended state

An alternative is to introduce the unknown as a genuine extra component: append it to the state, and let the base residual_fn read it off the last element. That is what the landed design does, and it is what makes the program's structure constant. Putting the unknown in the operands instead would make the map's dependence on it invisible to factor, which builds the Jacobian by vmapped forward-mode differentiation over the state's directions; the pin column would then be missing from the LU factor and the correction would not know it could move the unknown.

Carrier and gate

The gate (tests/equilibrium/test_solve_vertical_pin.py) is an analytic elongated carrier on the current centroid with elongation kappa = 1.8. Its radial row is (R − R_centroid) + c Z²; its vertical row is c Z (Z − Zfree) unpinned, reduced by beta u when the pin's unknown u is present. The seed is [1.2, 0.62], deliberately off both targets so the pin's first correction carries real work.

Not done

  • Production wiring. The pin is not yet carried through the forward-solve seam. ForwardSolveRequest has no pin field, no production route builds a ConstraintPair whose unknown is the pin, and nothing maps a machine description to a declared vertical-field coil set or a uniform radial field. This is the largest remaining item: done-when (1) asks the converged solve to accept the pin, and only the generic solve does so far.
  • The 550-cell lobe run (done-when 3). The cold solve that stalls at 1.54987e-3 on a collapsing line search has not been re-run with the pin. Whether the stall clears is unmeasured.
  • Suite arms. Both suite arms were cut short by the background-run ceiling before their summary lines, so no delta against the orientation base is available. A complete run at a merged head is owed.

Follow-ons

  1. Carry the pin through ForwardSolveRequest, SolveRoute and ConstraintPair, so a request names a target height and the unknown's declared source, and the solve reports the pin residual beside the base residual.
  2. Resolve a machine's vertical-field coil set (or uniform radial field) from its static description, so the pin needs no hand-declared source.
  3. Re-run the 550-cell lobe carrier with the pin against the stalled cold solve and report both residual histories.
  4. Run the suite arms to completion at a merged head and record the delta against the orientation base.
